## 1. CSS contrast-color() — 背景に合わせてテキスト色を自動選択する

**出典**: [CSS contrast-color() for Readable Text — modern-css.com](https://modern-css.com/readable-text-without-manual-contrast-checks/)

### ① 目的・問題意識

デザインシステムやユーザー生成コンテンツでは、背景色が動的に変わることが多い。  
その都度 `color: white` / `color: black` を手動で設定するのは非現実的で、ミスの温床になる。  
`contrast-color()` はブラウザが自動でWCAG AA準拠のコントラストを持つ色（黒か白）を返すCSS関数。

### ② 具体的なコード・技術詳細

**基本構文:**
```css
/* 背景が紫のとき → white を返す */
color: contrast-color(purple);

/* 背景が黄のとき → black を返す */
color: contrast-color(yellow);
```

**カスタムプロパティとの組み合わせ（推奨パターン）:**
```css
.card {
  --bg: var(--brand-color, rebeccapurple);
  background-color: var(--bg);
  color: contrast-color(var(--bg));
}
```

**ダークモード対応（light-dark() との組み合わせ）:**
```css
:root { --bg: #eee; }
@media (prefers-color-scheme: dark) {
  :root { --bg: #222; }
}
body {
  background-color: var(--bg);
  color: contrast-color(var(--bg));
}
```

**color-mix() との組み合わせ（ホバー時に背景が明るくなり、テキストも自動調整）:**
```css
.card {
  --bg: oklch(0.6 0.15 250);
  background: var(--bg);
  color: contrast-color(var(--bg));

  &:hover {
    --bg: color-mix(in oklch, oklch(0.6 0.15 250) 40%, white);
  }
}
```

**ブラウザサポート:**
- Chrome 147+（2026年4月）
- Firefox 146+
- Safari 26.0+
- → **Baseline Newly Available**（2026年4月時点で全主要ブラウザ対応）

### ③ なぜ効果的か

- JavaScript不要・プリプロセッサ不要・ルックアップテーブル不要
- WCAG AA基準のコントラスト比 4.5:1 をブラウザが自動計算
- `--bg` を1変数管理するだけでテキスト色も追随する
- Interop 2026 の対象機能として全ブラウザが協調実装した

**制限事項:**  
中間トーン（例: `#2277d3` のようなロイヤルブルー）では黒テキストが返るが、小文字には読みにくい場合がある。WCAG 2アルゴリズムは中間トーン付近で最適でないため、明暗のはっきりした背景色での使用を推奨。

## 2. CSS Gap Decorations — グリッド/フレックスのギャップに装飾線を引く

**出典**:
- [CSS Gap Decorations: row-rule and column-rule for Grid and Flex — modern-css.com](https://modern-css.com/grid-dividers-without-borders-or-pseudo-elements/)
- [Gap decorations: Now available in Chromium — developer.chrome.com](https://developer.chrome.com/blog/gap-decorations-stable)
- [A new way to style gaps in CSS — developer.chrome.com](https://developer.chrome.com/blog/gap-decorations)

### ① 目的・問題意識

グリッドやフレックスのアイテム間に区切り線を引くには、従来は `nth-child` セレクタや `border` / 疑似要素を駆使するハックが必要だった。  
CSS Gap Decorations はコンテナ自身がギャップ内に装飾線を描画できる新機能で、DOM構造を変えずに実現できる。

### ② 具体的なコード・技術詳細

**旧来の方法（ハック）:**
```css
/* nth-child でギャップ端のボーダーを除去する必要があった */
.grid > * {
  border-inline-end: 1px solid #ddd;
  border-block-end: 1px solid #ddd;
}
.grid > :nth-child(3n) {
  border-inline-end: 0;
}
.grid > :nth-last-child(-n + 3) {
  border-block-end: 0;
}
```

**新しい方法（Gap Decorations）:**
```css
.grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 24px;
  column-rule: 1px solid var(--border);
  row-rule: 1px solid var(--border);
}
```

**rule-break — 交差点での挙動制御:**
```css
.grid {
  display: grid;
  gap: 24px;
  column-rule: 2px solid oklch(18% 0.01 60);
  row-rule: 1px solid oklch(72% 0.16 70);
  rule-break: intersection; /* 交差点で線を続ける */
}
```

`rule-break` の値:
- `normal` (デフォルト): T字交差では止まり、十字交差では続く
- `intersection`: 常に交差点を通過する
- `none`: 各ラインが独立する

**rule-inset — 端をどれだけ内側に縮めるか:**
```css
.grid {
  display: grid;
  gap: 16px;
  column-rule: 1px solid currentColor;
  rule-inset: 8px; /* 両端から8px縮める */
}
```

**アニメーション — ホバー時に装飾線を表示:**
```css
.grid {
  display: grid;
  gap: 24px;
  column-rule-width: 0px;
  column-rule-style: solid;
  column-rule-color: royalblue;
  transition: column-rule-width 300ms;

  &:hover {
    column-rule-width: 2px;
  }
}
```

**フレックスレイアウトでの使用:**
```css
.bill {
  display: flex;
  column-rule-width: 1px, 3px;
  column-rule-style: solid, double;
  column-rule-color: oklch(18% 0.01 60);
  row-rule: 1px solid oklch(72% 0.16 70);
  rule-break: intersection;
}
```

**ブラウザサポート:**
- Chrome / Edge 149+（2026年6月2日 Stable）
- Safari / Firefox: 未対応（プログレッシブエンハンスメントとして使用推奨）

**W3C仕様:**  
CSS Gaps Module Level 1 Working Draft が **2026年6月24日**（本号と同日）に公開された。  
→ https://www.w3.org/TR/2026/WD-css-gaps-1-20260624/

### ③ なぜ効果的か

- DOM変更なしにコンテナ側で装飾を管理できる（関心の分離）
- アニメーション可能（rule-width、color、inset）
- 非対応ブラウザではギャップが通常どおり表示されるだけ（プログレッシブエンハンスメント）
- `column-rule` はマルチカラムレイアウトで既存の概念を拡張したものなので直感的

## 3. Approximating contrast-color() — 旧ブラウザへのフォールバック実装

**出典**: [Approximating contrast-color() With Other CSS Features — CSS-Tricks](https://css-tricks.com/approximating-contrast-color-with-other-css-features/)

### ① 目的・問題意識

`contrast-color()` が Baseline になる前（またはポリフィルが必要な環境）において、同様の挙動をネイティブCSSで近似する方法。  
OKLCHカラー空間の相対カラー構文と `round()` 関数を組み合わせて実現する。

### ② 具体的なコード・技術詳細

**コア技術: OKLCH の相対カラー構文 + round()**

```css
/* OKLCHの L（明度）を反転させて黒/白のどちらかを返す */
color: oklch(from var(--bg) round(1.21 - l) 0 0);
```

**なぜ `1.21` という係数か:**
- OKLCH明度の閾値は約0.65〜0.72の範囲（平均0.69）
- `1.21 - 0.72 = 0.49` → `round()` で 0 (黒) になる
- `1.21 - 0.71 = 0.50` → `round()` で 1 (白) になる
- 0.5以上なら白(1)、0.5未満なら黒(0)として機能する

**完全なフォールバックパターン:**
```css
.card {
  --bg: var(--brand-color, rebeccapurple);
  background-color: var(--bg);

  /* フォールバック: oklch近似 */
  color: oklch(from var(--bg) round(1.21 - l) 0 0);

  /* contrast-color() サポート時は上書き */
  @supports (color: contrast-color(red)) {
    color: contrast-color(var(--bg));
  }
}
```

**CSS Custom Functions を使ったバージョン（Chrome 130+ / Firefox 130+）:**
```css
@function --white-black(--color) {
  result: oklch(from var(--color) round(1.21 - l) 0 0);
}

.card {
  --bg: oklch(0.45 0.2 250);
  background: var(--bg);
  color: --white-black(var(--bg));
}
```

**黒/白以外に拡張する例:**
```css
/* 白の代わりに薄いベージュ、黒の代わりにダークネイビーを使う */
.card {
  --fg-light: oklch(0.96 0.01 80);   /* ほぼ白 */
  --fg-dark: oklch(0.12 0.03 250);   /* ダークネイビー */

  color: oklch(from var(--bg)
    clamp(0, round(1.21 - l), 1)   /* 0 or 1 */
    /* ... color-mix などでblend */ 0 0);
}
```

### ③ なぜ効果的か

- `contrast-color()` 非対応環境でも1行で近似できる
- OKLCH空間は人間の知覚に線形対応しているため、単純な明度閾値でも精度が高い
- `@supports` と組み合わせることで段階的な移行が可能

## 4. Creating Memorable Web Experiences: A Modern CSS Toolkit

**出典**: [Creating Memorable Web Experiences: A Modern CSS Toolkit — CSS-Tricks (Mariana Beldi)](https://css-tricks.com/creating-memorable-web-experiences-a-modern-css-toolkit/)

### ① 目的・問題意識

ライブラリ依存（GSAPなど）なしに、ネイティブCSSで「記憶に残る」ウェブ体験を作る方法。  
CSS の 3D、clip-path、カスタムプロパティ、スクロール駆動アニメーション、View Transitions、@property が揃った今、外部ライブラリ不要でできることが増えている。  
「動かせるから動かす」ではなく、「動きでメッセージを伝える」という設計思想が前提。

### ② 具体的なコード・技術詳細

**テキストスプリットアニメーション（GSAPのSplitText相当をCSSで実現）:**

各文字を `<span>` で包み、カスタムプロパティをインデックス乗数として使う。

```html
<p class="split-text">
  <span style="--i: 0">H</span>
  <span style="--i: 1">e</span>
  <span style="--i: 2">l</span>
  <span style="--i: 3">l</span>
  <span style="--i: 4">o</span>
</p>
```

```css
.split-text span {
  display: inline-block;
  animation: slide-in 0.4s both;
  /* --i をディレイの乗数として使用 */
  animation-delay: calc(var(--i) * 50ms);
}

@keyframes slide-in {
  from {
    opacity: 0;
    translate: 0 1em;
  }
  to {
    opacity: 1;
    translate: 0 0;
  }
}
```

**スクロール駆動アニメーション（IntersectionObserver 不要）:**

```css
@keyframes fade-in {
  from { opacity: 0; translate: 0 40px; }
  to   { opacity: 1; translate: 0 0; }
}

.reveal {
  animation: fade-in linear both;
  animation-timeline: view();
  animation-range: entry 0% entry 30%;
}
```

**@property でアニメーション可能なカスタムプロパティ（グラデーション遷移など）:**

```css
@property --gradient-angle {
  syntax: "<angle>";
  inherits: false;
  initial-value: 0deg;
}

.hero {
  background: linear-gradient(var(--gradient-angle), #667eea, #764ba2);
  animation: rotate-gradient 4s linear infinite;
}

@keyframes rotate-gradient {
  to { --gradient-angle: 360deg; }
}
```

**View Transitions API（ページ間のスムーズな遷移）:**

```css
/* 要素に一意の名前を付ける */
.card {
  view-transition-name: card-hero;
}

/* デフォルトのクロスフェードをカスタマイズ */
::view-transition-old(card-hero) {
  animation: slide-out 300ms ease-in;
}
::view-transition-new(card-hero) {
  animation: slide-in 300ms ease-out;
}
```

**auto-height へのアニメーション（従来は JS が必要だった）:**

```css
details {
  overflow: hidden;
}

details[open] summary ~ * {
  animation: expand 300ms ease-out;
}

@keyframes expand {
  from { height: 0; }
  to   { height: auto; } /* CSS now supports animating to auto! */
}
```

### ③ なぜ効果的か

- アニメーションをCSSのみで実装することで、処理がメインスレッドからGPUへオフロードされる
- スクロール駆動アニメーションは `IntersectionObserver` を完全に置き換え可能
- `@property` によりカスタムプロパティのアニメーションが型付きで可能になった
- `animation-timeline: view()` は遅延読み込みのためのJSコードを排除する

## 5. Do Graphs and Charts Need to Be Accessible?

**出典**: [Do graphs and charts need to be accessible? — tempertemper (Martin Underhill)](https://www.tempertemper.net/blog/do-graphs-and-charts-need-to-be-accessible)

### ① 目的・問題意識

グラフや図表はPNGやSVGとして表示されることが多く、視覚に依存したコンテンツになりがち。  
「図表はアクセシブルにしなければならないか？」という問いに対する実践的な回答と実装指針。  
答えは「画像自体は必ずしも公開しなくていいが、**伝える情報は必ずアクセシブルにしなければならない**」。

### ② 具体的なコード・技術詳細

**アプローチ1: SVG に ARIA ロールを付けてテーブルセマンティクスを与える**

```html
<figure>
  <svg role="table" aria-label="月別売上データ">
    <g role="row">
      <text role="columnheader">月</text>
      <text role="columnheader">売上</text>
    </g>
    <g role="row">
      <text role="cell">1月</text>
      <text role="cell">¥120,000</text>
    </g>
    <!-- ... -->
  </svg>
</figure>
```

**アプローチ2（推奨）: SVGを装飾として隠し、HTMLテーブルをアクセシブルな実体とする**

```html
<figure>
  <!-- SVGはプレゼンテーション用（支援技術には隠す） -->
  <svg role="presentation" aria-hidden="true" focusable="false">
    <!-- チャートの描画 -->
  </svg>

  <!-- 視覚的に隠されているが支援技術には公開されるテーブル -->
  <figcaption>
    <table class="visually-hidden">
      <caption>月別売上データ</caption>
      <thead>
        <tr>
          <th scope="col">月</th>
          <th scope="col">売上</th>
        </tr>
      </thead>
      <tbody>
        <tr>
          <th scope="row">1月</th>
          <td>¥120,000</td>
        </tr>
        <!-- ... -->
      </tbody>
    </table>
  </figcaption>
</figure>
```

**視覚的に隠す CSS（display: none は支援技術にも隠れるため NG）:**

```css
.visually-hidden {
  clip: rect(0 0 0 0);
  clip-path: inset(50%);
  height: 1px;
  overflow: hidden;
  position: absolute;
  white-space: nowrap;
  width: 1px;
}
```

**アプローチ3: `<img>` + alt テキスト（シンプルなグラフ向け）**

```html
<img
  src="sales-chart.png"
  alt="2026年1〜6月の月次売上。1月:120万円、2月:145万円、3月:132万円、4月:168万円、5月:155万円、6月:180万円。全体的に右肩上がりの傾向。"
/>
```

### ③ なぜ効果的か

- データの可視化（SVG）と構造化データ（HTMLテーブル）を分離することで、それぞれのアクセシビリティを最大化できる
- `role="presentation"` + `aria-hidden="true"` を SVG に付けることで、スクリーンリーダーが複雑なSVGマークアップを読み上げるのを防ぐ
- HTMLテーブルは元から行/列のセマンティクスを持つため、スクリーンリーダーとの相性が最善

## 6. CSS Gaps Module Level 1 — W3C Working Draft 公開

**出典**: [CSS Gaps Module Level 1 — W3C Working Draft (2026-06-24)](https://www.w3.org/TR/2026/WD-css-gaps-1-20260624/)

### ① 目的・問題意識

CSS マルチカラムレイアウトで定義されていた `column-rule` を、グリッド・フレックス・その他コンテナレイアウトに拡張し、行方向の `row-rule` も追加する仕様を正式化。  
Gap Decorations 機能の仕様的基盤となるドキュメントが Chrome 149 Stable リリース（2026年6月2日）と同日に Working Draft として公開された。

### ② 具体的なコード・技術詳細

仕様で定義される主要プロパティ群:

| プロパティ | 説明 |
|---|---|
| `column-rule` | 列ギャップ内の装飾線（shorthand: width / style / color） |
| `row-rule` | 行ギャップ内の装飾線（column-rule の行方向版） |
| `rule-break` | 交差点での線の描画挙動（`normal` / `intersection` / `none`） |
| `rule-inset` | 装飾線を両端から縮める量 |
| `rule-inset-cap` | コンテナ端（交差しない側）のみのインセット |
| `column-rule-visibility-items` | 装飾線を隣接アイテム間のみに表示 |
| `row-rule-visibility-items` | 同上（行方向） |

**完全なサンプル（グリッドカードUI）:**

```css
.cards-grid {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(200px, 1fr));
  gap: 32px;

  /* 縦線: 実線 1px */
  column-rule: 1px solid hsl(220 10% 85%);

  /* 横線: 破線 1px */
  row-rule: 1px dashed hsl(220 10% 85%);

  /* 交差点では線を描画し続ける */
  rule-break: intersection;

  /* コンテナ端から8pxで止まる */
  rule-inset-cap: 8px;
}
```

### ③ なぜ効果的か

- W3C の正式ドキュメントとして仕様化されたことで、他のブラウザベンダー（Firefox, Safari）の実装推進が加速する
- `column-rule` はマルチカラムレイアウトで長年の実績があるため、APIの一貫性が高い
- アニメーション対応（width、color、inset）により動的UIにも対応
