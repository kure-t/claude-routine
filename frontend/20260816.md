## 1. テキストデザインを引き立てる5つのCSSプロパティ

**記事タイトル**: 5 CSS Properties You Should Know for Better Text Designs
**URL**: [https://master.dev/blog/typographic-css-tricks/](https://master.dev/blog/typographic-css-tricks/)

### ① 目的・問題意識

Web上のテキストデザインは `font-size` や `color` など基本的なプロパティだけで組まれがちだが、それだけでは「見出しをグラデーションで彩る」「複数行にまたがるハイライトの端をきれいに揃える」「縦書き中に数字だけ横向きにする」といった、印刷物レベルの繊細なタイポグラフィ表現ができない。本記事は、あまり知られていないが強力な5つのCSSプロパティ（`background-clip`, `vertical-align`, `box-decoration-break`, `letter-spacing`, `text-combine-upright`）を使い、JavaScriptや画像に頼らず表現力の高いテキストデザインを実現する方法を解説している。

### ② 具体的な技術詳細とコード例

#### 1. `background-clip: text` — 背景（グラデーション/画像）をテキストでマスクする

見出しに単色ではなくグラデーションや画像を「流し込む」ためのテクニック。背景を要素のテキストの形にクリップし、文字の塗り色自体は透明にすることで実現する。

```css
h1.gradient-text {
  background: linear-gradient(90deg, #f7971e, #ffd200, #ff6b6b, #c471ed, #12c2e9);
  background-size: 300% 100%;
  background-clip: text;
  -webkit-background-clip: text; /* Safari など旧実装向け */
  color: transparent;
  -webkit-text-fill-color: transparent;
}
```

クロスブラウザ対応としては、接頭辞なしの `background-clip: text` が Chrome 120+ / Firefox 49+ / Safari 14+ / Edge 120+ でサポートされているため、`-webkit-background-clip: text` と併記しておくのが安全。画像を背景に使えば、写真の中に文字がくり抜かれたような効果も作れる。

```css
h1.image-mask-text {
  background: url('photo.jpg') fixed;
  background-size: cover;
  background-clip: text;
  -webkit-background-clip: text;
  color: transparent;
  -webkit-text-fill-color: transparent;
}
```

#### 2. `vertical-align` — インライン要素・テキストの垂直位置合わせ

アイコンフォントやインライン画像とテキストのベースラインがずれる問題を、`line-height` をいじらずに解消するためのプロパティ。`baseline`（デフォルト）、`middle`、`text-top`、`sub`、`super` など複数のキーワードに加え、`%` や `px` での微調整も可能。

```css
.icon-inline {
  display: inline-block;
  vertical-align: middle; /* テキストの中央にアイコンを揃える */
}

sup {
  vertical-align: super;
  font-size: 0.75em;
}
```

#### 3. `box-decoration-break` — 複数行にまたがる装飾を「フラグメントごと」に揃える

蛍光ペンでハイライトしたような `background` や `padding`、`border-radius` を持つインライン要素が改行で複数行に分かれたとき、デフォルト（`slice`）では最初と最後の行以外の装飾が欠けてしまう。`box-decoration-break: clone` を指定すると、各行（各フラグメント）ごとに同じ装飾が複製され、行が変わっても均一な見た目を保てる。

```css
.highlight {
  background-color: yellow;
  border-radius: 20px;
  padding: 0.45rem 0.6rem;
  box-decoration-break: clone;
  -webkit-box-decoration-break: clone; /* Safari 等は接頭辞が必要 */
}
```

```html
<p>
  この文章の一部分だけ
  <span class="highlight">複数行にまたがるくらい長くハイライトした場合でも、
  各行の端が丸くきれいに揃う</span>
  という効果を確認できます。
</p>
```

用途としては、マーカーでなぞったような強調表現や、コードスニペット内の複数行選択ハイライトなどに向く。

#### 4. `letter-spacing` — 文字間隔によるトーン調整

見出しやラベル、ボタンのテキストにわずかな `letter-spacing` を加えるだけで、フォントを変えずに「上品さ」「視認性」をコントロールできる。特に全て大文字（`text-transform: uppercase`）のラベルでは、字間を詰めすぎると窮屈に見えるため正の値を付けるのが定石。

```css
.eyebrow-label {
  text-transform: uppercase;
  font-size: 0.75rem;
  font-weight: 600;
  letter-spacing: 0.12em; /* フォントサイズに対する相対値で指定するのが安全 */
}

.tight-heading {
  font-size: 3rem;
  letter-spacing: -0.02em; /* 大きな見出しはわずかに詰めると締まって見える */
}
```

#### 5. `text-combine-upright` — 縦書き中の数字・欧文を横向きに組む（縦中横）

`writing-mode: vertical-rl` で縦書きにしたテキストの中で、日付や品番などの数字だけを横向きのまま1文字分の幅に収めて表示する日本語組版の技法「縦中横（tate-chū-yoko）」を、画像や特殊フォントなしにCSSだけで再現する。

```css
.num {
  text-combine-upright: all;
  writing-mode: vertical-rl;
}
```

```html
<p class="vertical-text">
  令和<span class="num">8</span>年<span class="num">4</span>月<span class="num">29</span>日
</p>
```

`text-combine-upright` は `none | all | digits <integer>?` を受け付ける。`all` はマークアップで囲んだ範囲すべてを1文字幅に収めて横向き表示し、`digits` は連続する半角数字（既定2桁、最大4桁）を自動でまとめる値だが、`digits` はブラウザサポートが乏しいため、実務では `all` を明示的にマークアップして使うのが現実的。

### ③ なぜそれが効果的か

| プロパティ | 効果の理由 |
|---|---|
| `background-clip: text` | JavaScriptや画像埋め込みなしに、グラデーション/画像テキストをレスポンシブかつテキストとして選択可能な状態で実装できる |
| `vertical-align` | インライン要素の位置合わせに `line-height` の力技を使わずに済み、レイアウト崩れのリスクを減らす |
| `box-decoration-break: clone` | 改行位置に依存せず装飾が破綻しないため、可変長テキストでも安定した見た目を保証できる |
| `letter-spacing` | フォントファイルを追加せずにタイポグラフィのトーンを調整でき、パフォーマンスコストがほぼゼロ |
| `text-combine-upright` | 縦書きレイアウトでも数字の可読性を保ちつつ、伝統的な日本語組版のルールに忠実な表現ができる |

## 2. `:has()` によるスクロールロック付きダイアログ

**記事タイトル**: Scroll-Locked Dialogs
**URL**: [https://frontendmasters.com/blog/scroll-locked-dialogs/](https://frontendmasters.com/blog/scroll-locked-dialogs/)

### ① 目的・問題意識

ネイティブの `<dialog>` 要素を `showModal()` で開いたとき、背景ページがスクロールできてしまう問題が長年 CSS だけでは解決しづらかった。従来は JavaScript で `body` に `overflow: hidden` のクラスを付け外しする実装が一般的だったが、この記事は `:has()` セレクタが全ブラウザで使えるようになったことを踏まえ、**JavaScriptなしでスクロールロックを宣言的に実現する方法**を検証している。

### ② 具体的な技術詳細とコード例

素朴な発想として、`body` が `dialog` を「持っている」ときに `overflow: hidden` を当てればよいと考えがちだが、`<dialog>` はモーダルが閉じている間もDOM上に存在し続けるため、単純な実装だとスクロールが常にロックされてしまう。

```css
/* ❌ 素朴な実装 — dialog が非表示でも DOM に存在する限りスクロールがロックされ続ける */
body:has(.lock-scroll) {
  overflow: hidden;
}
```

正しくは、`showModal()` 呼び出し時にブラウザが自動的に付与する `open` 属性、かつ `:modal` 疑似クラス（モーダルとして開いている状態のみにマッチ）を組み合わせて条件を絞り込む。

```css
/* ✅ dialog が「モーダルとして開いている」ときだけスクロールをロックする */
html:has(dialog[open]:modal) {
  overflow: hidden;
}
```

```html
<dialog id="confirm-dialog">
  <p>本当に削除しますか？</p>
  <button value="cancel">キャンセル</button>
  <button value="confirm">削除する</button>
</dialog>

<script>
  const dialog = document.getElementById('confirm-dialog');
  document.getElementById('open-btn').addEventListener('click', () => {
    dialog.showModal(); // open 属性が付与され :modal にマッチするようになる
  });
</script>
```

なお、対象範囲を `body` ではなく `html` にしているのは、`body` に `overflow: hidden` を当てるだけではモバイルSafariなどでタッチスクロールがすり抜けるケースがあるため、より確実にスクロールを止める実装として `html` 要素を対象にする手法が紹介されている。

### ③ なぜそれが効果的か

- **JavaScript不要**: `open` 属性と `:modal` 疑似クラスはブラウザが自動で管理するため、`body` にクラスを付け外しするJSが一切不要になる
- **宣言的で状態同期のバグが起きない**: 「モーダルが開いている」というDOMの実際の状態とCSSのロック条件が一致しているため、JS側の付け忘れ・消し忘れによるスクロールロックの不整合が起きない
- **`:modal` による厳密な絞り込み**: `open` 属性だけで判定すると `<details>` の `open` など無関係な要素にも誤反応しうるが、`:modal` を併用することで「本当にモーダル表示されているダイアログ」だけを対象にできる

## 3. AIボット過多と戦う — ブログ運営者のリアルな防衛策

**記事タイトル**: My Blog's Biggest Fans Are AI Bots. So I Fought Back.
**URL**: [https://ranthebuilder.cloud/blog/my-blogs-biggest-fans-are-ai-bots-so-i-fought-back/](https://ranthebuilder.cloud/blog/my-blogs-biggest-fans-are-ai-bots-so-i-fought-back/)

### ① 目的・問題意識

2026年時点でAIクローラー（GPTBot、ClaudeBot、PerplexityBotなど）を含む自動化トラフィックがWeb全体のHTTPリクエストの過半数を占めるまでに増加しており、個人ブログ運営者にとってもインフラコストとアクセス解析の信頼性を脅かす問題になっている。筆者は自身のブログで「セッションの91%がリファラーなしで到着し、毎日同じ時間帯にまるでシフトが終わるかのようにトラフィックが消える」という不自然なパターンを観測し、`robots.txt` だけでは正体を偽装する（人間のようなUser-Agentで実ブラウザを操作する）ボットを止められないという課題に直面した。

### ② 具体的な技術詳細

#### `robots.txt` の限界

`robots.txt` はあくまで「お願いベース」の紳士協定であり、強制力を持つ防御手段ではない。すべてのルールはボットが自ら名乗るUser-Agent文字列に依存しており、筆者が本当に止めたいボット（正体を偽装するボット）はそもそも正直に名乗らないため、`robots.txt` の更新だけでは根本解決にならない。

#### AWS WAFのAIトラフィック課金機能（x402プロトコル）による対策

筆者が検証した対策の一つが、AWS WAFの「AIトラフィックのマネタイズ」機能。保護対象ページへのリクエストに対し、HTTPステータス **402 Payment Required** を返し、オープンな **x402プロトコル**上でUSDC建ての機械可読な価格を提示する。AIエージェント側がその価格を支払うとWAFがエッジで支払いを検証し、1往復のリクエストでページが配信される、という仕組み。

```
Client (AI agent) → GET /protected-article
                  ← 402 Payment Required
                     (x402: price in USDC, payment endpoint)

Client → Pay via x402 (USDC)
       → GET /protected-article (with payment proof)
       ← 200 OK (article content served)
```

ただし、この方式が機能するのは「正直に名乗り、プロトコルに従って支払うボット」に対してのみであり、正体を偽って人間のふりをするボットには効果がないという限界も筆者は明記している。

### ③ なぜそれが効果的か

- **`robots.txt` を「信頼できる正直なボット」向けの一次防衛線として維持**しつつ、それだけに頼らない多層防御の発想に切り替えられる
- **x402（HTTP 402）はプロトコルレベルでの経済的インセンティブ**を提供するため、コンテンツを完全にブロックするのではなく「対価を払えばアクセスできる」形で収益化とアクセス制御を両立できる
- 一方で、**すべてのボットを解決する銀の弾丸ではない**と明言している点が実務上重要で、「正直者に効くレイヤー」と「悪意ある偽装ボットに効くレイヤー（WAFのレート制限・フィンガープリンティング等）」を分けて考える必要性を示している

## 4. Pure CSS Pipe + Bubbles & Animation API（デモ）

**URL**: [https://codepen.io/sheepsheep/pen/ExJbejq](https://codepen.io/sheepsheep/pen/ExJbejq)

### ① 目的・問題意識

「画像やSVGを使わず、CSSのグラデーション・シャドウの重ね合わせだけで立体的な配管（パイプ）を表現できるか」「そこから泡（バブル）が湧き出るアニメーションを、CSSアニメーションではなくWeb Animations API（Animation API）で制御できるか」という、遊び心のあるビジュアル表現の技術検証を目的としたコードデモ。

### ② 具体的な技術詳細（デモの内容）

- **パイプの造形**: `--main-color` / `--main-light` / `--main-dark` といったCSSカスタムプロパティで基調色・ハイライト・シャドウの3色を定義し、`--pipe-base-height` / `--pipe-base-width` / `--pipe-edge-width` などの寸法変数でパイプの本体・継ぎ目（エッジ）の太さや高さを調整できるようになっている。金属パイプの光沢は複数の `linear-gradient` を重ねて表現。
- **バブルの造形**: `--bubble-color` / `--bubble-light` / `--bubble-dark` という別系統のカスタムプロパティで泡の配色を分離管理し、パイプ本体の配色とは独立してカスタマイズ可能にしている。
- **アニメーション制御**: CSSの `@keyframes` だけでなく、JavaScriptの **Web Animations API**（`element.animate()`）を併用し、泡が生成されるタイミング・軌道・消滅をより細かくプログラム的に制御している点が特徴。CSSだけのループアニメーションに比べ、ランダム性のある発生間隔や個体差のある軌道を実装しやすい。

### ③ なぜそれが効果的か

- **CSSカスタムプロパティによる「デザイントークン化」**: パイプとバブルで配色変数を分離しているため、色を差し替えるだけで別デザインのパイプ（例: 錆びた鉄パイプ、カラフルなおもちゃのパイプ)に一瞬で作り替えられる
- **Web Animations APIとCSSのハイブリッド構成**: 静的な質感（グラデーション・シャドウ）はCSSに任せ、時間軸で変化する動きだけJSのAnimation APIに委ねることで、パフォーマンス（ブラウザのコンポジタに乗るCSSアニメーション）と柔軟性（JSでの動的制御）を両立している
- 実務に直結するというより、**CSSカスタムプロパティ設計とAnimation APIの組み合わせパターンの実例**として、UIの装飾的アニメーション実装の参考になる
