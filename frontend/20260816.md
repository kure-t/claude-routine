## 1. TanStack Table v9 正式リリース

**リンク:** https://tanstack.com/blog/announcing-tanstack-table-v9

### ① 目的・問題意識

TanStack Table v8 では全フィーチャーがバンドルに含まれており、小規模なテーブルでも未使用のソート・フィルタリング・グルーピング機能が必ずバンドルされていた。また、大量行を扱う際のメモリ消費が大きく、状態管理がグローバルな `getState()` に集中していたため、細粒度の再レンダリング制御が困難だった。

### ② 具体的な技術詳細とコード

**主な Breaking Changes:**

| V8 | V9 |
|---|---|
| `useReactTable()` | `useTable()` |
| `getCoreRowModel()` | `tableFeatures()` + `_rowModels` |
| `table.getState()` | `table.store.state` または `table.atoms.<slice>.get()` |
| `enablePinning` | `enableColumnPinning` + `enableRowPinning` |
| `columnSizingInfo` (state key) | `columnResizing` |
| `sortingFn` / `sortingFns` | `sortFn` / `sortFns` |

**V8 → V9 完全移行例:**

```javascript
// === V8 (旧) ===
import { useReactTable, getCoreRowModel, getSortedRowModel } from '@tanstack/react-table'

const columnHelper = createColumnHelper<Person>()

const table = useReactTable({
  columns,
  data,
  getCoreRowModel: getCoreRowModel(),
  getSortedRowModel: getSortedRowModel(),
  enablePinning: true,
  onColumnSizingInfoChange: setInfo,
})

const state = table.getState()
const cells = row._getAllCellsByColumnId()
```

```javascript
// === V9 (新) ===
import {
  useTable,
  tableFeatures,
  rowSortingFeature,
  columnPinningFeature,
  columnSizingFeature,
  columnResizingFeature,
  createColumnHelper,
  createSortedRowModel,
  sortFns,
} from '@tanstack/react-table'

// 使用するフィーチャーのみを宣言（未使用はバンドルから除外される）
const _features = tableFeatures({
  rowSortingFeature,
  columnPinningFeature,
  columnSizingFeature,
  columnResizingFeature,
})

const columnHelper = createColumnHelper<typeof _features, Person>()

const table = useTable({
  _features,
  _rowModels: {
    sortedRowModel: createSortedRowModel(sortFns),
  },
  columns,
  data,
  enableColumnPinning: true,
  enableRowPinning: true,
  onColumnResizingChange: setResizing,
})

// 状態アクセスの3パターン
const fullState = table.store.state          // スナップショット（購読なし）
const sortingAtom = table.atoms.sorting.get() // スライス単位のリアクティブ購読
const cells = row.getAllCellsByColumnId()     // アンダースコアなし public API
```

**段階的移行用エスケープハッチ:**

```javascript
// V8 API を V9 エンジン上で使える（V10 で削除予定）
import { useLegacyTable } from '@tanstack/react-table/legacy'
```

**TanStack Store の状態アクセスパターン:**

| メソッド | ユースケース |
|---|---|
| `table.store.state` | 全状態スナップショット（購読なし） |
| `table.atoms.<slice>.get()` | スライス単位のリアクティブ購読 |
| `table.state` | フレームワーク固有セレクタ |

### ③ なぜ効果的か

- **バンドルサイズ削減:** `tableFeatures()` で宣言したフィーチャーのみがバンドルされる。ソートのみのテーブルは約5kBから始まり、未使用のフィルタリング・グルーピングは除外される
- **メモリ効率:** 大規模テーブルで最大90%のメモリ削減。内部アーキテクチャのリファクタにより、テーブルオブジェクト間でより多くの処理を共有
- **型安全性:** `TFeatures` を型パラメータの先頭に置くことで、コンパイル時により強い型チェックが可能
- **細粒度リアクティビティ:** atom ベースの状態により、リアクティブな更新とスナップショット読み取りを明確に分離できる
- **不変性保証:** `data` と `columns` が `readonly` に変わり、状態管理をバイパスする偶発的なミューテーションを防ぐ

## 2. Next.js 16.3 リリース

**リンク:** https://nextjs.org/blog/next-16-3

### ① 目的・問題意識

長時間の開発セッションでは Next.js の dev サーバーが数十GBものメモリを消費し、クラッシュや "FATAL ERROR" が頻発していた。また、ビルド時間の短縮と、サーバー駆動アプリへのSPA的な即時ナビゲーション体験の実現が求められていた。

### ② 具体的な技術詳細とコード

**Turbopack の Persistent Build Cache（デフォルト有効化）:**

```typescript
// next.config.ts
// v16.3 ではデフォルトで有効。無効化が必要な場合のみ設定
const nextConfig = {
  experimental: {
    turbopackMemoryEviction: false, // デフォルト: 'full'
  },
}
export default nextConfig
```

**メモリ効率の改善（開発サーバー）:**

Turbopack がコンパイラの「コールドな」状態をファイルシステムキャッシュに書き出すことで、RAMへの保持が不要になった。

| アプリ | v16.2 | v16.3 |
|---|---|---|
| Vercel 社内ダッシュボード | 21.5 GB | 2 GB |
| nextjs.org | 4.6 GB | 0.84 GB |

**パフォーマンス指標:**

- ビルド速度: 未変更アーティファクトのキャッシュ読み取りにより、リピートビルドが大幅高速化
- SSR スループット: 負荷下で最大22%多くのリクエストを処理
- 型チェック: `next build` が TypeScript 7 を使用可能に

**Instant Navigations（実験的）:**

```typescript
// next.config.ts（実験的フラグ）
const nextConfig = {
  experimental: {
    cacheComponents: true,
    partialPrefetching: true,
  },
}
```

サーバー駆動ページをSPA的に動作させる機能。プリフェッチとコンポーネントキャッシュを組み合わせてナビゲーション時の待機時間をゼロに近づける。

**AI エージェント向けバージョン付きドキュメント:**

コーディングエージェントがバージョン一致したドキュメントをセットアップなしで読めるよう、バージョン付きドキュメントAPIを提供。

**Turbopack の新機能:**

- Development memory eviction（デフォルト有効）
- next build 向け永続ファイルキャッシュ（デフォルト有効）
- 実験的な Rust 製 React Compiler
- `import.meta.glob` サポート

### ③ なぜ効果的か

- **開発体験の劇的改善:** 長時間セッションでのメモリ消費を最大90%削減し、"FATAL ERROR" によるクラッシュを実質的に排除
- **ビルド時間短縮:** ファイルシステムキャッシュにより、再ビルド時に変更のないアーティファクトの処理をスキップ
- **Instant Navigations:** サーバーモデルの恩恵を保ちながらSPA的なUXを実現し、ユーザーの体感速度を向上
- **エージェント対応:** AI コーディングツールがバージョン固定のドキュメントにアクセスできることで、ハルシネーションが減りコード生成の精度が向上

## 3. Flue v2 — React ライクなフックを持つ AI エージェントフレームワーク

**リンク:** https://flueframework.com/blog/flue-2/  
**記事:** [React for Agents: Astro Creator Brings Hooks to his Meta-Harness, Flue](https://www.latent.space/p/flue-2)

### ① 目的・問題意識

Astro の作者 Fred Schott が開発したエージェントフレームワーク。エージェント開発においてコンポーザビリティが課題であり、既存フレームワークでは「エージェントが実行ターンをまたいで能力を動的に変化させる」ことが難しかった。React のコンポーザビリティがエージェント開発に最適だと気づき、「React for agents」として設計された。

### ② 具体的な技術詳細とコード

**コアコンセプト:** エージェントを JavaScript 関数として表現し、「毎ターン（= モデル呼び出しの前）に再レンダリング」される。React の関数コンポーネントと同様の概念。

**`useModel` — 必須フック（LLMの宣言）:**

```typescript
'use agent';
import { useModel } from '@flue/runtime';

export function TriageAgent() {
  useModel('anthropic/claude-sonnet-4-6');
  return 'Investigate the reported issue and recommend the next action.';
}
```

**`usePersistentState` — 永続化された状態管理:**

React の `useState` と同じAPIだが、値は会話ストレージに永続化され、次のターンでも保持される。

```typescript
'use agent';
import { useModel, usePersistentState, useTool } from '@flue/runtime';

export function CaseAssistant() {
  useModel('anthropic/claude-haiku-4-5');

  const [phase, setPhase] = usePersistentState('phase', 'gathering');
  const [factsChecked, setFactsChecked] = usePersistentState('factsChecked', 0);

  useTool('checkFact', {
    description: 'Verify a claim against the knowledge base',
    parameters: z.object({ claim: z.string() }),
    execute: async ({ claim }) => {
      const result = await verifyFact(claim);
      setFactsChecked(prev => prev + 1);
      return result;
    },
  });

  if (phase === 'gathering') {
    return 'Gather information about the case.';
  }
  return `Review the ${factsChecked} verified facts and summarize.`;
}
```

**`useSkill` — 外部スキルの注入:**

```typescript
'use agent';
import { useModel, useSkill } from '@flue/runtime';
import { webSearchSkill } from '@flue/skills';

export function ResearchAgent() {
  useModel('anthropic/claude-sonnet-4-6');
  useSkill(webSearchSkill);
  return 'Research the given topic and provide a detailed report.';
}
```

**React コンポーネントとの統合:**

```tsx
import { useFlueAgent } from '@flue/react';
import { useState } from 'react';

function ChatUI() {
  const [input, setInput] = useState('');
  const { send, messages, isRunning } = useFlueAgent(TriageAgent);

  return (
    <div>
      {messages.map(m => <div key={m.id}>{m.content}</div>)}
      <input value={input} onChange={e => setInput(e.target.value)} />
      <button onClick={() => send(input)} disabled={isRunning}>送信</button>
    </div>
  );
}
```

### ③ なぜ効果的か

- **React との概念的一致:** フックベースのAPIにより、React 開発者が直感的にエージェント開発を行える
- **コンポーザビリティ:** スキル・ツール・モデルをフックとして組み合わせることで、エージェントの能力を柔軟に構成できる
- **動的な能力変化:** `usePersistentState` で状態を保持しながら、毎ターンの「再レンダリング」でエージェントの振る舞いを変化させられる
- **型安全性:** TypeScript + Zod による入力スキーマ定義でツールのインターフェースが明確

## 4. WebMCP — ブラウザのネイティブ MCP で React アプリを AI エージェント対応に

**リンク:** https://github.com/GoogleChromeLabs/use-webmcp-tool  
**関連:** https://github.com/agentcathq/webmcp-react

### ① 目的・問題意識

AI エージェントが Web アプリを操作する際、従来はDOMスクレイピングやスクリーンショット解析に頼っていた。これは脆弱で非効率。WebMCP は W3C 提案の新しいブラウザAPI（`document.modelContext`）で、ページが構造化されたツールを直接エージェントに公開できる。React コンポーネントのライフサイクルと連動した宣言的なツール登録が課題だった。

### ② 具体的な技術詳細とコード

**WebMCP のネイティブAPI（低レベル）:**

```javascript
// 手動でのライフサイクル管理が必要で冗長
const controller = new AbortController();

document.modelContext.registerTool({
  name: "add-todo",
  description: "Add items to todo list",
  inputSchema: {
    type: "object",
    properties: { text: { type: "string" } },
    required: ["text"],
  },
  async execute({ text }) {
    addTodoItem(text);
    return { content: [{ type: "text", text: `Added: ${text}` }] };
  },
}, { signal: controller.signal });

// アンマウント時に手動でアンレジスタ
controller.abort();
```

**`useWebMCP` フック（React による抽象化）:**

```javascript
import { useWebMCP } from "use-webmcp-tool";

function TodoTools({ addTodo }) {
  const { supported, registered, error } = useWebMCP({
    name: "add-todo",
    description: "Add a new item to the user's active todo list",
    inputSchema: {
      type: "object",
      properties: { text: { type: "string", description: "The todo item text" } },
      required: ["text"],
    },
    async execute({ text }) {
      addTodo(text);
      return `Added: ${text}`;
    },
    enabled: true, // 条件的な登録も可能
  });

  if (!supported) return null;
  return (
    <p>
      {registered ? "🤖 Agent tools ready" : "Registering..."}
      {error && `Error: ${error.message}`}
    </p>
  );
}
```

**Zod スキーマを使った型安全版（webmcp-react）:**

```javascript
import { useMcpTool } from "@mcp-b/react-webmcp";
import { z } from "zod";

function SearchTools({ onSearch }) {
  useMcpTool({
    name: "search",
    description: "Search the product catalog",
    input: z.object({
      query: z.string().describe("Search query"),
      limit: z.number().optional().default(10),
    }),
    handler: async ({ query, limit }) => ({
      content: [{ type: "text", text: JSON.stringify(await onSearch(query, limit)) }],
    }),
  });

  return null;
}
```

**戻り値の自動正規化（useWebMCP）:**

| execute の返り値 | 変換後 |
|---|---|
| 文字列 | `{ content: [{ type: "text", text }] }` |
| undefined / null | `{ content: [] }` |
| `{ content: [...] }` 形式 | そのまま pass-through |
| throw | `{ content: [...], isError: true }` |
| その他オブジェクト | JSON シリアライズされたテキストブロック |

### ③ なぜ効果的か

- **ライフサイクルとの同期:** コンポーネントのマウント時にツール登録、アンマウント時に自動解除。スクリーンに表示されているコンポーネントのツールのみがエージェントに公開される
- **グレースフルデグラデーション:** `document.modelContext` 非対応ブラウザでは `supported: false` を返し、UI に影響を与えない
- **現在のブラウザ対応:** Chrome 149+ で Origin Trial 中。WebMCP Bridge 拡張機能で Claude Code / Cursor などのデスクトップクライアントとも接続可能
- **React のコンポーネント哲学との一致:** 宣言的な登録パターンにより、DOM の制御と同じ感覚でエージェントツールを管理できる
