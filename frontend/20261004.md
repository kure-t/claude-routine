## 1. Why GitHub now ships more CSS, not less (GitHub Blog: Improving site performance by shipping more CSS)
https://github.blog/engineering/architecture-optimization/improving-site-performance-by-shipping-more-css/

### ① 目的・問題意識
- 2023年頃から特定ページのコンポーネント数が急増し、CSS-in-JS (styled-components) に起因する性能問題が顕在化した。
  - スタイルがクライアントで初期化されるため初期ロードが遅い
  - サーバーサイドレンダリング (SSR) 性能の低下
  - ページ上のコンポーネント数に比例してスタイル更新コストが増大
- Primer チームは、ネイティブ CSS 機能を使え、かつ CSS-in-JS 同様のコロケーションとカプセル化を維持できる手段として CSS Modules を採用。

### ② 技術詳細
- CSS Modules: `.module.css` ファイル内のクラス名をビルド時にユニーク名へ書き換え、ファイル単位でスコープ化するバンドラ規約。ランタイムの JS は不要。
- 移行手法: feature flag、visual regression テスト、段階的ロールアウト。
- 経緯: Primer コンポーネントは 2024年12月までに移行完了 → SSR 55% 高速化、コンポーネント初期化 25% 高速化。`sx` prop を数千箇所の GitHub UI から除去する作業は 2025年4月開始、codemod・VS Code プラグイン・のちに Copilot coding agent を活用し、2026年6月に 100% CSS Modules に到達 (計約3年)。
- 具体的なコード: **未取得** (記事本文を読めていない)。

### ③ なぜ効果的か
- CSS Modules は変換がビルド時に完結し、レンダー時に JS でスタイルを生成するランタイムコストがない。CSS 総量は増えても SSR 時間が 55% 短縮された。

## 3. CSS だけで要素の重なりを検出する (Ahmad Shadeed: Detect when elements overlap with CSS)
https://ishadeed.com/article/css-detect-overlap/

### ① 目的・問題意識
- 2つの要素が視覚的に重なったことを JS なし (ResizeObserver 等不要) で検知し、重なった側を隠す/薄くするなどのスタイル切替を行いたい。

### ② 技術詳細 (検索要約より、コードは未取得)
1. Anchor Positioning の `anchor()` で、2要素の端の間に「測定用要素」を配置する (間隔が測定用要素の幅になる)。
2. 測定用要素の中に固定幅の疑似要素を入れ、`overflow-x: auto` にする。間隔が疑似要素の幅より狭くなるとスクロール可能 (オーバーフロー) になる。
3. `scroll-timeline` と `timeline-scope` でオーバーフローの有無を CSS 変数のトグルに変換する。
4. その変数を Style Container Query で読み、重なった要素を非表示/フェードさせる。
- 前提: Anchor Positioning と Scroll-driven Animations の両対応ブラウザ。プログレッシブエンハンスメントとして使うのが推奨。

### ③ なぜ効果的か
- レイアウト結果 (実際の余白) をブラウザ自身がスクロール可否として表現するため、サイズ計測を JS に頼らず宣言的に状態を取り出せる。

## 4. CSS だけでグリッド情報を抽出する (css-tip.com / master.dev: Extracting Grid Information Using CSS)
https://css-tip.com/grid-information/ , https://blog.master.dev/extracting-grid-information-using-css/

### ① 目的・問題意識
- レスポンシブな CSS Grid の行数・列数・各アイテムの座標を、JS なしで CSS から取得したい (座標に応じたスタイリング等)。

### ② 技術詳細 (検索要約より、コードは未取得)
- Scroll-driven Animations (`view-timeline`, `animation-range`, entry-crossing / exit-crossing) で、各要素の辺がスクロールコンテナに対してどこにあるかを追跡する。
- アニメーション進捗値を `round()` と `calc()` で整数のグリッド座標に変換する。

### ③ 効果
- ブラウザが計算済みのレイアウト位置を進捗値として利用でき、列数の変化 (レスポンシブ) にも自動追従する。

## 5. Custom Attributes polyfill (Keith Cirkel)
https://www.keithcirkel.co.uk/custom-attributes-polyfill/

### ① 目的・問題意識
- 「Custom Elements の属性版」。要素が持つ振る舞いを属性として表現し、HTML/SVG/MathML/他のカスタム要素を問わず任意の要素に適用したい。

### ② 技術詳細 (検索要約より、コードは未取得)
- `Attr` をサブクラス化し、ハイフン付きの名前で登録する。一致する属性は接続済み要素上でそのクラスのインスタンスへインプレースにアップグレードされる。
- ライフサイクルコールバック: `constructor()` (アップグレード/生成時)、`attributeChangedCallback()` (値の追加・変更・削除)、`connectedCallback()` (接続時)、`disconnectedCallback()` (切断時)。

### ③ 効果
- `data-*` + 手書きの querySelector 初期化ではなく、Custom Elements と同じライフサイクルモデルで属性駆動の振る舞いを宣言的に再利用できる。
