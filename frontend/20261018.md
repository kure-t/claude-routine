## 1. Next.js 16.4：Cache Components がデフォルトに

**リンク:** https://nextjs.org/blog/next-16-4

### ① 目的・問題意識

Next.js 16.x で実験的に提供されてきた Cache Components（サーバーコンポーネントのキャッシュ層）を、すべての新規プロジェクトで推奨デフォルトとして採用。従来は手動で設定が必要だったが、`create-next-app` でスキャフォールドしたプロジェクトが最初からキャッシュ最適化済みの構成で生成される。Next.js 17 では全プロジェクトにデフォルト適用予定。

### ② 技術詳細

#### Cache Components デフォルト化

```js
// next.config.js（create-next-app で生成されるデフォルト設定）
module.exports = {
  experimental: {
    cacheComponents: true,
  },
}
```

既存アプリの移行には `cacheComponents` と `partialPrefetching` の両フラグを有効化する必要がある。

#### `ensureStatic`（ルートの静的性保証）

ルートセグメントで「このルートは必ず静的である」と宣言できる新しい config 項目。`'navigation'`・`'prefetch'`・`'shell'` の3段階で設定でき、動的コンテンツが混入するとビルドが失敗する。

```ts
// app/about/page.tsx
export const ensureStatic = 'navigation'  // 完全な静的ナビゲーションを保証

export default function AboutPage() {
  return <h1>About</h1>
}
```

設定値の意味：
- `'navigation'`：ユーザーがナビゲートした際のフルページが静的
- `'prefetch'`：プリフェッチコンテンツが静的
- `'shell'`：ページシェル（レイアウト）が静的

#### `navigation()` / `prefetch()`（キャッシュ制御）

`next/cache` から提供される新関数。コンポーネント内で `await navigation()` を呼ぶと、そのコンポーネントのキャッシュコンテンツを実際のナビゲーション時まで遅延させる。`Cache Components` が必須。

```tsx
import { navigation, prefetch } from 'next/cache'

async function MyComponent() {
  // ナビゲーション発生まで遅延ロード
  await navigation()
  const data = await fetchData()
  return <div>{data}</div>
}
```

#### `next upgrade --agent`（エージェント支援アップグレード）

AI コーディングエージェントにバージョンアップ作業を委ねるための実験的コマンド。バージョン固有のアップグレードガイダンスをエージェントに提供する。

```bash
npx next@canary upgrade --agent=latest
```

#### Turbopack の改善

- ディスクキャッシュサイズが **20〜25% 削減**
- プロダクションバンドルサイズが縮小
- 遅延サーバー HMR（Lazy Server HMR）導入

#### React 19.3 バンドル

Next.js 16.4 には React 19.3 が同梱。以下の機能が Stable に昇格：

- **`<ViewTransition>`** コンポーネント：ページ・コンポーネント間のアニメーションを宣言的に定義。`startTransition` / Suspense / `useDeferredValue` でラップされた更新に対してのみ発火。
- **Fragment Refs**：ラッパー要素なしに複数の兄弟要素グループに ref をアタッチ可能。
- **`browser()` API**：`use(browser())` でサーバーレンダリングからコンポーネントをオプトアウト。
- **Trusted Types サポート**：React DOM が Trusted Types の値を受け付けるように。

### ③ 効果

Cache Components のデフォルト化により、新規プロジェクトではゼロ設定でサーバーコンポーネントのキャッシュ最適化が有効になる。`ensureStatic` によってリグレッション防止が可能になり、誤って動的コンテンツが静的ルートに混入するバグをビルド時に検出できる。ビルドキャッシュ削減とバンドルサイズ縮小で開発体験・本番パフォーマンスの両面が向上。

## 2. TanStack Charts 1.0：TypeScript チャート文法ライブラリ

**リンク:** https://tanstack.com/blog/tanstack-charts-1-0

### ① 目的・問題意識

既存のチャートライブラリは「使い始めると後から乗り換えられない」問題があった。TanStack Charts は小さいラインチャートから始めて、必要に応じてバーやポイントを追加できる合成可能なアーキテクチャを採用。フレームワーク非依存エンジンの上に React・Vue・Solid・Angular アダプターを薄く被せる構成。

### ② 技術詳細

#### アーキテクチャ

```
┌────────────────────────────────────────────────────────────┐
│  @tanstack/charts（コアエンジン）                            │
│  - Marks（描画要素）: lineY, barY, pointY, ...             │
│  - Scales（スケール）: scaleLinear, scaleBand, ...         │
│  - Interactions: tooltip, brush, zoom, keyboard select     │
│  - Scene generation / reconciliation（D3 モジュール使用）   │
└────────────────────────────────────────────────────────────┘
           ↓ framework adapter（ライフサイクルのみ）
┌──────────┐  ┌─────────┐  ┌──────────┐  ┌───────────┐
│  React   │  │  Vue    │  │  Solid   │  │  Angular  │
│  /react  │  │  /vue   │  │  /solid  │  │  /angular │
└──────────┘  └─────────┘  └──────────┘  └───────────┘
```

エンジン自体はフレームワーク非依存。Marks がデータを視覚化要素にマッピングし、Scales がデータ値を画面座標に変換する。チャートセマンティクスはすべてコア層に存在し、アダプターはライフサイクルバインディングと ref/callback 公開のみ担当。

#### インストール

```bash
npm install @tanstack/charts
```

#### React での基本的な使い方（ラインチャート）

```tsx
import { defineChart, lineY } from '@tanstack/charts'
import { Chart } from '@tanstack/charts/react'

const data = [
  { month: 'Jan', value: 100 },
  { month: 'Feb', value: 150 },
  { month: 'Mar', value: 120 },
  { month: 'Apr', value: 200 },
]

const chart = defineChart({
  marks: [
    lineY({
      x: 'month',
      y: 'value',
      stroke: '#6366f1',
    }),
  ],
  tooltip: true,
})

export function RevenueChart() {
  return <Chart chart={chart} data={data} />
}
```

#### バーチャートの例

```tsx
import { defineChart, barY } from '@tanstack/charts'
import { Chart } from '@tanstack/charts/react'
import { scaleBand, scaleLinear } from '@tanstack/charts/scales'

const chart = defineChart({
  marks: [
    barY({
      x: 'month',
      y: 'value',
      fill: '#6366f1',
    }),
  ],
  scales: {
    x: scaleBand().padding(0.2),
    y: scaleLinear().domain([0, 250]),
  },
})
```

#### バンドルサイズ

- 基本的な React ラインチャート：**32.1 kB gzip**（公式値）
- 高度なツリーシェイキングにより、使用する Mark のみがバンドルに含まれる

#### Stable API 保証（1.0）

```
documented public APIs / extension protocols /
framework support / renderer behavior
```

React Native アダプターは引き続き実験的（Experimental）。

### ③ 効果

Mark の合成により、例えば `lineY` に `pointY` を重ねてポイント付きラインチャートを作るなど、ゼロコストで複合チャートを構築できる。エンジンが D3 の数学モジュールのみを使用し、それ以外をゼロ依存にしたことでバンドルサイズを最小化。フレームワーク非依存アーキテクチャにより、React から他フレームワークへの移行コストも低い。

## 3. React コンポーネントツリーのビジュアル記法

**リンク:** https://julesblom.com/writing/react-visual-notation

### ① 目的・問題意識

React のコードはコンポーネントが何をレンダーするかは示すが、アプリ全体の中でどこに位置するかは示さない。React DevTools は親ツリー（Parent Tree）またはオーナーツリー（Owner Tree）を表示できるが、図として描く標準的な記法がない。この記法を提案することで、アーキテクチャドキュメントや解説記事での共通言語を作る。

### ② 技術詳細

#### 親ツリー vs オーナーツリー

```
親ツリー（Parent Tree）：
  - DOM 構造上の親子関係を表す
  - <App> が <Layout> を render し、<Layout> が <Header> を render

オーナーツリー（Owner Tree）：
  - どのコンポーネントがどの要素を「作成した」かを表す
  - JSX で書いた場所＝オーナー
  - children として受け取った要素はオーナーではない
```

#### 記法の主なマーカー

| マーカー | 意味 |
|---------|------|
| Context プロバイダー境界 | Context の提供範囲を示す |
| Suspense 境界 | 非同期ローディング境界 |
| `memo()` ラッパー | メモ化コンポーネントを示す |
| エラー境界 | Error Boundary の範囲 |
| RSC（React Server Component） | サーバーコンポーネントの識別 |

#### ツール：React Trees Playground

Jules Blom が [julesblom.com/react-trees](https://julesblom.com/react-trees) でインタラクティブなプレイグラウンドを公開。React コードを貼り付けると親ツリーとオーナーツリーの両方をリアルタイムで図示する。

内部的には **bippy**（@aidenybai 作）を使用。bippy は実行中の React アプリの Fiber ツリーを読み取るライブラリで、これを使うと DevTools なしで任意の React アプリのコンポーネント構造をプログラマティックに取得できる。

```bash
# bippy のインストール
npm install bippy
```

```ts
import { getFiberRoots, traverseFiber } from 'bippy'

// 実行中の React アプリの Fiber ルートを取得
const roots = getFiberRoots()

// Fiber ツリーを走査してコンポーネント情報を収集
traverseFiber(roots[0], (fiber) => {
  console.log(fiber.type?.displayName || fiber.type?.name)
})
```

### ③ 効果

統一されたビジュアル記法により、PR レビューや技術ドキュメント、チームディスカッションで「どのコンポーネントがどのコンテキストスコープに属するか」「RSC と Client Component の境界はどこか」を一目で確認できるようになる。Suspense・memo・Context を含む複雑なコンポーネント設計の意図をコードではなく図で伝えられる。

## 4. Coinbase が React Native から脱却してネイティブへ

**リンク:** https://ivanthinking.net/2026/10/14/coinbase-is-going-mobile-native-too/

### ① 目的・問題意識

Coinbase のコンシューマー取引アプリが React Native から Swift（iOS）・Kotlin（Android）のフルネイティブ実装へ移行。Shopify のネイティブ移行発表（1週間前）に続く動きで、AI コーディングツールの普及が「クロスプラットフォームよりもネイティブで2回書く」選択のコストを下げたことが背景にある。

### ② 技術詳細

- **発表者：** Adam Wolf（Coinbase シニアエンジニアリングマネージャー）
- **移行先：** iOS → Swift、Android → Kotlin
- **理由として挙げられた点：**
  - AI コーディングツールにより、プラットフォームごとの実装コストが低下
  - ネイティブコードによる起動時間短縮とクラッシュ削減
  - iOS・Android の新機能への Day-One アクセス
  - React Native の New Architecture 移行だけでは根本的な問題を解決できなかった（Shopify 同様）

### ③ 効果・業界への影響

React Native の将来性についての議論を喚起。ただし「React Native は多くの企業・チームにとって引き続き有力な選択肢」という見方も強く、React Foundation や Expo チームによる継続的な改善が進んでいる。Shopify・Coinbase のような大規模ネイティブアプリ特有の判断として捉えるべきとの意見も多い。

## 5. Redux Toolkit 2.13：TypeScript 7 サポートと RTK Query 修正

**リンク:** https://github.com/reduxjs/redux-toolkit/releases/tag/v2.13.0

### ① 目的・問題意識

Redux Toolkit がビルドツールを刷新し、TypeScript 7 対応と RTK Query の重大なバグ修正を提供。特に `useQueryState` / `useQuery` でセレクターが毎レンダリング新規生成されてしまうパフォーマンス問題と、`isSuccess` フラグが誤った状態になるバグを修正。

### ② 技術詳細

#### TypeScript 7 サポート

- TypeScript 7.0 / 7.1 でのすべての型エラーを修正
- CI の TypeScript テストマトリクスに TS 7.0 を追加
- **最小サポート TypeScript バージョン：5.6**（DefinitelyTyped のサポートウィンドウに合わせて引き上げ）
- TS 5.4+ 標準搭載の `NoInfer` ユーティリティを使用するよう内部を更新
- RTK Query のフックオプション型をエクスポート（`Parameters<>` でラップ不要に）

#### ビルドツール移行

```
変更前                    変更後
Yarn               →  PNPM
tsup               →  TSDown
ESLint             →  Oxlint
Prettier           →  Oxfmt
```

パッケージレイアウト・`exports` 定義・公開 API は 2.12 から変更なし。

#### `useQueryState` / `useQuery` のセレクター修正

**問題：** セレクターがレンダリングごとに新しいインライン関数として生成されており、`useSelector` が毎回サブスクリプションを再登録していた。またレンダリング中に Store を直接読み取るアンチパターンも存在した。

**修正：** セレクターをメモ化し、レンダリング中の Store 直接読み取りを廃止。

```tsx
// 修正前（疑似コード）：毎レンダリングで新しい selector が生成されていた
const result = useSelector((state) => selectFromCache(state, {endpointName, queryArgs}))

// 修正後：セレクターがメモ化され、安定した参照を返す
const memoizedSelector = useMemo(
  () => createSelector(...),
  [endpointName, queryArgs]
)
const result = useSelector(memoizedSelector)
```

**`isSuccess` の誤フリップ修正：** エラー後にリフェッチ中の場合、`isSuccess` が関係ないコンポーネントの再レンダリングで `false` → `true` に誤って遷移していた問題を解消。`isSuccess` は今後リフェッチ中は `false` を維持する。

#### その他の RTK Query 修正

```ts
// fetchBaseQuery: URL がスキームで始まる場合のみ絶対 URL として扱う
// 修正前: '//cdn.example.com/api' も絶対 URL として扱われていた
// 修正後: 'https://' or 'http://' で始まる URL のみ絶対 URL

// ポーリングの改善
const api = createApi({
  endpoints: (build) => ({
    getData: build.query({
      query: () => '/data',
      // pollingInterval が設定されている場合、
      // ポーリング発火時に現在のキャッシュ状態を読む（修正済み）
      // skipPollingIfUnfocused: フォーカス喪失後も尊重（修正済み）
    }),
  }),
})
```

#### `createEntityAdapter` の修正

```ts
// setAll: 重複 ID の最後のアイテムを保持（setMany と一致させた）
// sorted adapter の updateMany: 同一 ID への複数更新を適用前にマージ
adapter.updateMany(state, [
  { id: 1, changes: { name: 'First update' } },
  { id: 1, changes: { value: 42 } }, // 以前は最初の更新のみ適用されていた
])
```

#### Redux ドキュメントの統合

Redux Toolkit・React Redux・Reselect の各ドキュメントサイトが **redux.js.org** に統合。旧 URL からはリダイレクト。

### ③ 効果

TypeScript 7 対応により最新版 TS でのビルドエラーが解消。`useQuery` セレクターのメモ化で無用な再レンダリングが削減される。`isSuccess` の修正はリフェッチ後のフラッシュ（画面チラつき）の解消につながる。

## 6. Ink 8：React ターミナルレンダラーにスクロール可能なビューを追加

**リンク:** https://github.com/vadimdemedes/ink/releases/tag/v8.0.0

### ① 目的・問題意識

Ink は React で CLI・TUI アプリを構築するライブラリ（Claude Code・Gemini CLI などでも使用）。v8 で長年の要望だったスクロール可能なビューを `<Box>` コンポーネントに直接組み込み、サードパーティライブラリなしで実装可能にした。

### ② 技術詳細

#### スクロール可能なビューの実装

`<Box>` に新しい `contentOffsetX`・`contentOffsetY` プロップが追加された。`overflow="hidden"` と組み合わせて使用する。

```tsx
import { Box, Text, useBoxMetrics, useInput } from 'ink'
import { useState } from 'react'

const ITEMS = Array.from({ length: 100 }, (_, i) => `Item ${i + 1}`)

function ScrollableList() {
  const [offset, setOffset] = useState(0)
  const [ref, setRef] = useState<any>(null)
  const metrics = useBoxMetrics(ref)

  // 表示可能な最大行数から最大スクロール量を計算
  const maxOffset = Math.max(0, ITEMS.length - (metrics?.clientHeight ?? 0))

  useInput((input, key) => {
    if (key.downArrow) {
      setOffset((prev) => Math.min(prev + 1, maxOffset))
    }
    if (key.upArrow) {
      setOffset((prev) => Math.max(prev - 1, 0))
    }
  })

  return (
    <Box
      ref={setRef}
      height={10}
      overflow="hidden"
      contentOffsetY={offset}  // ← v8 の新プロップ
    >
      {ITEMS.map((item) => (
        <Box key={item}>
          <Text>{item}</Text>
        </Box>
      ))}
    </Box>
  )
}
```

#### `useBoxMetrics` の更新

`clientWidth` と `clientHeight` が追加。ボーダーを除いたコンテンツ領域のサイズを返す。スクロール量の上限計算に使用。

```tsx
const metrics = useBoxMetrics(ref)
// metrics.clientWidth  : ボーダーを除いた幅（列数）
// metrics.clientHeight : ボーダーを除いた高さ（行数）
```

#### インクリメンタルレンダリング

変更されていない行プレフィックスをスキップして、変更された部分のみターミナルに書き出す最適化。フリッカーの削減と出力量の削減を実現。

#### 破壊的変更（v8）

```
- React 19.3 以上が必須
- <Box> の minWidth / maxWidth は数値のみ受け付ける（文字列不可）
- stdin/stdout/stderr が汎用 Node.js ストリームとして型付け
- useInput が未認識のターミナル制御シーケンスを受け取らなくなった
- render() が任意の Node Stream を受け付けるように変更
```

### ③ 効果

スクロール可能なビューをゼロ依存で実装できるようになり、ファイルリストや大量のログ表示が容易になる。インクリメンタルレンダリングによりターミナルでの描画が滑らかになり、特に高頻度更新（スピナー、プログレスバー）での体験が向上する。

## 7. Shaders がオープンソース化：React 向け WebGPU エフェクトライブラリ

**リンク:** https://github.com/shader-effects-inc/shaders

### ① 目的・問題意識

WebGPU / WGSL の知識がなくても、React・Vue・Svelte・Solid・Framer で200種類以上のビジュアルエフェクトを宣言的なコンポーネントとして使えるようにする。エンジン・コンポーネント・フレームワークバインディングをすべて MIT ライセンスでオープンソース化。

### ② 技術詳細

#### インストール

```bash
npm install shaders
```

#### React での基本的な使い方

```jsx
import { Shader, LinearGradient, CursorTrail } from 'shaders/react'

export function Hero() {
  return (
    <Shader className="w-full h-64">
      <LinearGradient colorA="#0f172a" colorB="#7c3aed" />
      <CursorTrail />
    </Shader>
  )
}
```

`<Shader>` がキャンバスをレンダーし、その子要素が GPU 上でトップダウンにブレンドされるレイヤーとして評価される。

#### Vanilla JS での使い方

```js
import { createShader } from 'shaders/js'

await createShader(document.getElementById('my-shader'), {
  components: [
    { type: 'LinearGradient', props: { colorA: '#0f172a', colorB: '#7c3aed' } },
    { type: 'CursorTrail' },
  ],
})
```

#### カスタムシェーダーの定義

WGSL を直接書いてカスタムコンポーネントを作成できる。

```ts
import { defineShader, wgsl, transformColor, transformPosition } from 'shaders/std'

export const Halo = defineShader({
  name: 'Halo',
  props: {
    color: { default: '#ffd166', transform: transformColor },
    center: { default: { x: 0.5, y: 0.5 }, transform: transformPosition },
    radius: { default: 0.6 },
  },
  paint: wgsl`
    let d = length((uv - center) * vec2f(aspect, 1.0)) / radius;
    return vec4f(color.rgb, 1.0 - smoothstep(0.8, 1.0, d));
  `,
})
```

- `uv`：ピクセルの UV 座標（0.0〜1.0）
- `aspect`：アスペクト比（組み込み変数）
- `paint` は `vec4f`（RGBA）を返す WGSL テンプレートリテラル
- `transform*` ヘルパーで CSS カラー文字列や座標オブジェクトを GPU 値に変換

## 9. React Native Skia 3.0：Graphite GPU バックエンドへ移行

**リンク:** https://github.com/Shopify/react-native-skia

### ① 目的・問題意識

React Native Skia が Google の Skia グラフィクスライブラリの新世代 GPU バックエンド「Graphite」を採用。従来の Ganesh バックエンドから移行し、WebGPU を活用した高性能レンダリングを実現。

### ② 技術詳細

- **Graphite バックエンド：** Skia の次世代 GPU API。WebGPU をサポートし、iOS（Metal）・Android（Vulkan）のモダン GPU API に最適化されている
- **WebGPU レンダラー：** React Native Skia がブラウザ（WebGPU）でも動作するよう対応
- **発表：** William Candillon（@wcandillon）が "Hello Graphite" ストリームで発表

### ③ 効果

Graphite バックエンドにより、モバイルアプリのグラフィクスパフォーマンスが向上。ブラウザ・iOS・Android 間でのシェーダーコードの共有が容易になり、グラフィクス集約型アプリ開発の体験が向上する。
