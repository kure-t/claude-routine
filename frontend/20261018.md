## 1. GitHub が CSS-in-JS をやめ CSS Modules に移行(Improving site performance by shipping more CSS)

原典: [GitHub Blog](https://github.blog/engineering/architecture-optimization/improving-site-performance-by-shipping-more-css/)

### ① 目的・問題意識
github.com の UI 基盤 Primer が使っていた styled-components(CSS-in-JS)は、レンダリング時に JS でスタイルを生成するランタイムコストがあり、SSR 時間とコンポーネント初期化時間を押し上げていた。クライアント/サーバーのランタイム処理を不要にするため、CSS Modules へ約3年かけて移行した。

### ② 技術詳細
- スタイルをコンポーネントの JS と同じ場所の CSS ファイルに記述し、ビルド時にクラス名へハッシュを付与(`.button` → 一意の名前)してスコープ化。マッピングは JS にエクスポートされる(CSS Modules はバンドラの規約でありブラウザ標準ではない)。
- スタイルはまとめた stylesheet として HTML と一緒に配信される。
- 移行手法: フィーチャーフラグ、ビジュアルリグレッションのスナップショット比較(新旧実装を比較)、スタッフ→全ユーザーの段階的ロールアウト。
- Primer コンポーネントは 2024年12月までに移行完了。Primer React v38 で styled-components 依存を削除。
- 難所は `sx` prop の除去。codemod、VS Code プラグイン、Copilot coding agent を使い、sx を CSS Modules ファイルへ変換し、`styled-react` ラッパーの import を `primer/react` 直接 import に置換、プリプロ環境でテスト後デプロイ(二次情報では 2026年6月に 100% CSS Modules)。
- (具体的な before/after コードは本文未取得のため省略)

### ③ なぜ効果的か
実行時のスタイル生成が不要になり、CSS はブラウザがネイティブに処理できる。結果、SSR 時間 **55% 減**、ページ上コンポーネント初期化時間 **25% 減**(GitHub 報告値。別記事は特定ページで最大22%減とも報告)。CSS 量は増えても JS ランタイム処理が消える方が効く、というのが記事タイトルの主張。
懸念: Hacker News ではハッシュ化クラス名が広告ブロッカーやユーザーのカスタム CSS を難しくするとの指摘あり。

## 2. Anthropic による Claude Web アプリ高速化の深掘り

原典: Anthropic エンジニアリングブログ(一次ソース未取得。二次情報: [daily.dev](https://daily.dev/posts/how-anthropic-made-claude-3x-faster-9wrbqobnn))

### ① 目的・問題意識
claude.ai とデスクトップアプリの体感速度改善。主要4ジャーニー(アプリ起動、会話の開始/読み込み、メッセージ送信)が利用の95%を占めるとして計測対象にした。

### ② 技術詳細(二次情報)
- 2週間のスプリントで3,000件超の変更、13指標の幾何平均で約3.1倍高速化。
- 例: 新規ロード時の「入力可能になるまで」p75 が 3,085ms → 550ms。Claude Code デスクトップのセッション開始 837ms → 347ms。
- 施策: メッセージ入力欄を初期 HTML に含める、デスクトップ起動処理の削減、ホバー時の会話プリフェッチ、完成済みコンテンツブロックの再利用、成長するコードブロックのシンタックスハイライトを worker へ移動、テーブルの逐次表示。
- Claude でボトルネック発見・ベンチマーク作成・デプロイ監視を行い、人間が目標設定とレビューを担当。

### ③ なぜ効果的か
実ユーザーデータ(RUM)で計測し、体感に直結する初期表示と操作応答に集中したため。注意点として、キャッシュ無効化の不具合(他タブで削除したスレッドがサイドバーに残る)を指摘する批評もある。
