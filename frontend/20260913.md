## 1. Why StyleX is having a moment

**参照記事:** [The State of CSS-in-JS in 2026](https://blog.openreplay.com/state-css-in-js-2026/) / [StyleX Explained: Meta's Compile-Time CSS-in-JS](https://www.oflight.co.jp/en/columns/stylex-meta-atomic-css-in-js-2026) / [StyleX won CSS-in-JS because AI agents can read it](https://dev.to/adioof/stylex-won-css-in-js-because-ai-agents-can-read-it-473a)

### ① 目的・問題意識

従来の CSS-in-JS（styled-components、Emotion など）はランタイムでスタイルを JavaScript から CSS へ変換・注入していた。これにより：

- React Server Components（RSC）との相性が悪い（サーバーサイドでの JS 実行が前提）
- バンドルサイズが増大する（ランタイムライブラリが含まれる）
- スタイル注入がレンダリングをブロックする

StyleX はこれらの問題を**ビルド時コンパイル**で解決する。JavaScript でスタイルを記述しながら、最終成果物は完全に静的な CSS ファイルとなるため、ランタイムコストがゼロ。

### ② 具体的なコードと技術詳細

**インストール:**
```bash
npm install @stylexjs/stylex @stylexjs/babel-plugin
```

**Babel 設定（`.babelrc`）:**
```json
{
  "plugins": ["@stylexjs/babel-plugin"]
}
```

**基本的な使い方:**
```jsx
import * as stylex from '@stylexjs/stylex';

// スタイル定義（ビルド時にアトミック CSS クラスへ変換）
const styles = stylex.create({
  button: {
    backgroundColor: 'blue',
    color: 'white',
    padding: '10px 20px',
    borderRadius: '5px',
    border: 'none',
    cursor: 'pointer',
  },
  primary: {
    backgroundColor: '#0070f3',
  },
  disabled: {
    opacity: 0.5,
    cursor: 'not-allowed',
  },
});

// コンポーネントでの使用
function Button({ isPrimary, isDisabled }) {
  return (
    <button
      {...stylex.props(
        styles.button,
        isPrimary && styles.primary,
        isDisabled && styles.disabled
      )}
    >
      クリック
    </button>
  );
}
```

**コンパイル後のアトミック CSS（概念図）:**
```css
/* 各プロパティが独立したクラスに変換される */
.x1y0btm7 { background-color: blue; }
.xdl72j9  { color: white; }
.x1n2onr6 { padding: 10px 20px; }
.x10l6tqk { border-radius: 5px; }
.x1q0g3np { cursor: pointer; }
/* isPrimary=true のとき background-color は上書きされる */
.x1hz62hw { background-color: #0070f3; }
```

**メディアクエリの対応:**
```jsx
const styles = stylex.create({
  container: {
    padding: '16px',
    '@media (min-width: 768px)': {
      padding: '32px',
    },
  },
});
```

**コンポーネント間のスタイル合成（props を受け取る場合）:**
```jsx
// 親から渡されたスタイルと内部スタイルをマージ
function Card({ style }) {
  return (
    <div {...stylex.props(styles.card, style)}>
      内容
    </div>
  );
}
```

### ③ なぜ効果的か

| 比較項目 | styled-components / Emotion | StyleX |
|---|---|---|
| スタイル処理タイミング | **ランタイム**（JS 実行時） | **ビルド時**（コンパイル時） |
| React Server Components 対応 | 困難 | 完全対応 |
| バンドルサイズへの影響 | ランタイム追加あり | 追加なし（静的 CSS のみ） |
| CSS のスケーラビリティ | クラス名衝突リスクあり | アトミック CSS で重複排除 |
| AI 可読性 | 難（動的生成） | 高（静的クラス名） |

**アトミック CSS の強み:** 同一のプロパティ・値の組み合わせは 1 つのクラスに集約される。アプリが大きくなっても CSS のファイルサイズはほぼ増えない（Facebook/Meta では数百万行の React コードで使用中）。

**採用実績（2026年時点）:**
- Meta 社内全製品（Facebook、Instagram、WhatsApp、Messenger、Threads）
- Figma、Snowflake
- **Linear**: 2026年に styled-components から StyleX へ移行完了（1,000 件以上の PR）

## 2. Vitest 5.0 リリース

**参照:** [Vitest 5.0 is out!](https://vitest.dev/blog/vitest-5.html) / [Release v5.0.0](https://github.com/vitest-dev/vitest/releases/tag/v5.0.0)  
**リリース日:** 2026年9月3日

### ① 目的・問題意識

Vitest 5.0 はパフォーマンスと正確性を中心とした大型メジャーリリース。従来の「テストファイルを実行してテスト名を収集する」方式が抱えるオーバーヘッドや副作用の問題を解消し、ブラウザーモードの速度を大幅改善している。

### ② 具体的なコードと技術詳細

**主な変更点 1: `vitest list` の静的解析がデフォルトに**

```bash
# Vitest 5 以降: AST 静的解析でテスト名を収集（テストファイルを実行しない）
vitest list

# 旧動作（ファイルを実行して収集）に戻す場合
vitest list --no-static-parse
```

静的解析の制約として、テスト名は静的に解析可能でなければならない：

```ts
// ✅ 静的に解析可能（問題なし）
test('ユーザーを作成できる', () => { ... });
test.skip('スキップするテスト', () => { ... });

// ❌ 静的解析では名前が不明（--no-static-parse が必要）
const name = getTestName();
test(name, () => { ... });
```

**主な変更点 2: `clearCache` が正式 API へ昇格**

```ts
import { clearCache } from 'vitest/node';

// fsModuleCache を含むすべての Vitest キャッシュを削除
// Vitest 4.x では experimental.clearCache だったが 5.0 で正式化
await clearCache();
```

**主な変更点 3: ブラウザーモードの大幅高速化**

Vitest 5 のブラウザーモードで行われた最適化：

```
1. 自身のランタイムを事前バンドル（prebundle）
2. Vite サーバー起動中にブラウザーをプレウォーム（prewarm）
3. ブラウザーセッションをアダプティブにオープン
   （従来: maxWorkers 分のセッションを即座に全開）
4. ファイルごとのラウンドトリップを削減
```

**Breaking Changes の主要項目:**

```
- test discovery のデフォルト変更（静的解析）
- mocking のデフォルト挙動変更
- configuration のデフォルト値変更
- browser support の更新
- Node.js の最低バージョン要件変更
```

### ③ なぜ効果的か

- **静的解析によるテスト一覧取得**: テストファイルを実行せずに AST 解析するため、副作用なしに高速でテスト名を取得できる
- **ブラウザーモードの並列最適化**: セッションを必要な分だけ段階的に開くことで、ブラウザー起動のオーバーヘッドを最小化
- **`clearCache` 正式化**: テスト環境のキャッシュ問題を確実にリセットできる手段として安定的に使用可能になる

## 3. TanStack × Vercel パートナーシップ

**参照:** [TanStack + Vercel Partnership](https://tanstack.com/blog/vercel-partnership) / [Vercel partners with TanStack](https://daily.dev/posts/tanstack-vercel-partnership-d1fd8oedg)

### ① 目的・問題意識

Vercel と TanStack が公式にパートナーシップを締結し、Vercel が TanStack Start の**ファーストクラスホスティング先**となった。Next.js と同等の品質のサポートを TanStack ユーザーにも提供するのが目的。また、TanStack のオープンソース開発への資金支援も含む。

### ② 具体的な技術詳細

**TanStack Start の Vercel デプロイ:**
```bash
# TanStack Start プロジェクトを Vercel に Git ベースでデプロイ
# プレビュー URL によるレビューフローが利用可能
vercel deploy
```

デプロイ後、サーバー側処理は **Vercel Functions（Fluid compute）** 上で動作する。

**TanStack AI × Vercel AI Gateway の統合:**

```ts
import { createVercelGatewayClient } from '@tanstack/ai-vercel-gateway';

// Vercel AI Gateway を通じてモデルにアクセス
const client = createVercelGatewayClient({
  // 1 つの API キーで複数のモデルプロバイダーを利用可能
  apiKey: process.env.VERCEL_AI_GATEWAY_KEY,
});

// チャット、エンベディング、画像生成、要約を統一 API で呼び出し
const response = await client.chat({
  model: 'gpt-4o',
  messages: [{ role: 'user', content: 'Hello' }],
  // プロバイダーの優先順位やフォールバックモデルを設定可能
  providerPreferences: {
    fallback: ['claude-opus-5', 'gemini-1.5-pro'],
  },
});
```

**TanStack AI × Vercel Sandbox（コーディングエージェント）:**

```ts
import { createSandbox } from '@tanstack/ai-sandbox-vercel';

// Vercel の管理された microVM でコーディングエージェントを実行
const sandbox = await createSandbox({
  id: 'my-sandbox', // ID によるサンドボックス再開も可能
});

// Dev サーバーのプレビューポートを外部に公開
const previewUrl = await sandbox.exposePort(3000);
```

### ③ なぜ効果的か

- **ワンストップ DX**: TanStack Start のデプロイ、AI 機能、エージェント実行を Vercel のプラットフォームで完結できる
- **プロバイダー抽象化**: Vercel AI Gateway を通じて、単一の API キーで OpenAI・Anthropic・Google などの複数モデルを切り替え可能
- **フォールバック設定**: モデルダウン時の自動切り替えにより可用性が向上
- **Next.js と同等のサポート**: TanStack Start ユーザーもプレビュー URL や Git デプロイなどのワークフローを活用できる

## 4. How Turbopack chunks your JavaScript

**参照:** [How Turbopack chunks your JavaScript | Next.js](https://nextjs.org/blog/turbopack-chunking) / [Chunking by Tobias Koppers](https://gitnation.com/contents/turbopack-updates-3607)

### ① 目的・問題意識

バンドラーはモジュールを「チャンク」と呼ばれる出力ファイルにまとめる。このチャンク分割（chunking）は：

- **細かすぎる**: HTTP リクエスト数が増えてオーバーヘッドが増大
- **粗すぎる**: 初回ロードは速いが、ページ遷移時のキャッシュ活用が困難

Turbopack は Webpack とは全く異なるアプローチでこのトレードオフを解決する。

### ② 具体的なコードと技術詳細

**Turbopack のチャンクグループ概念:**

```
チャンクグループ = 1 つのルート or 動的インポートに対応するグループ

例:
  app/page.tsx         → チャンクグループ A
  app/dashboard/page.tsx → チャンクグループ B
  () => import('./HeavyComponent') → チャンクグループ C（動的）
```

**デフォルト制限:**

```
1 チャンクグループあたり最大 40 チャンク

↑ この数を下げる → より積極的なマージ → リクエスト数減少
↑ この数を上げる → より細かいチャンク → キャッシュヒット率向上
```

**`next.config.js` でのカスタマイズ:**

```js
// next.config.js
module.exports = {
  experimental: {
    turbopackChunking: {
      // デフォルト: 40
      // ↓ にするほどリクエスト数が減り初回ロードが速くなる
      // ↑ にするほどキャッシュ効率が上がりページ遷移が速くなる
      maxChunksPerGroup: 20,
    },
  },
};
```

**Turbopack の意思決定プロセス（概念）:**

```
各モジュールを チャンクグループ 内でグループ化

↓

マージするかどうか判断:
  - 単一ページセッションの推定キャッシュ効果
  - 複数ページセッションの推定キャッシュ効果
  
↓

両方のシナリオで最適なバランスになる点でマージ
```

**Webpack との比較:**

| 項目 | Webpack（SplitChunksPlugin） | Turbopack |
|---|---|---|
| キャッシング粒度 | プラグイン設定ベース | 関数レベルのキャッシュ |
| 再ビルド | 変更があったモジュールを再ビルド | 変更された部分のみ再計算 |
| メモリ効率 | JS 管理（メモリリークあり） | Rust 管理（効率的） |
| Tree Shaking | 標準的 | より積極的・正確 |

### ③ なぜ効果的か

- **HTTP/2 でもリクエスト数は有限のコスト**: HTTP/2 の多重化でもリクエストのオーバーヘッドは残るため、チャンク数の上限設定は依然として重要
- **セッションタイプ別最適化**: 「1 ページだけ見るユーザー」と「複数ページを見るユーザー」で最適なチャンク戦略が異なり、Turbopack はその両者のバランスを自動計算
- **設定で調整可能**: `maxChunksPerGroup` を下げると単純アプリ向けに最適化、上げると大規模 SPA 向けに最適化できる

## 5. Mantine v9.6.0 大型アップデート

**参照:** [Version v9.6.0 | Mantine](https://mantine.dev/changelog/9-6-0/) / [Lightbox | Mantine](https://mantine.dev/x/lightbox/)  
**リリース日:** 2026年9月

### ① 目的・問題意識

Mantine は 120 以上のコンポーネントを持つ React コンポーネントライブラリ。v9.6.0 では特に**メディア表示（ライトボックス）**の需要に応える新パッケージが追加された。合わせて Node.js 22 への移行も完了。

### ② 具体的なコードと技術詳細

**新パッケージ: `@mantine/lightbox`**

フルスクリーンメディアライトボックス。カルーセルナビゲーション・ズーム・サムネイル・ツールバーカスタマイズをサポート。

```bash
npm install @mantine/lightbox
```

```tsx
import '@mantine/lightbox/styles.css';
import { useState } from 'react';
import { Image, SimpleGrid } from '@mantine/core';
import { Lightbox, LightboxSlideData, useLightbox } from '@mantine/lightbox';

const images = [
  'https://example.com/photo1.png',
  'https://example.com/photo2.png',
  'https://example.com/photo3.png',
];

const slides: LightboxSlideData[] = images.map((src) => ({ src }));

// ストアベース API でライトボックスを操作
function PhotoGallery() {
  const lightbox = useLightbox();

  return (
    <>
      <SimpleGrid cols={3}>
        {images.map((src, index) => (
          <Image
            key={src}
            src={src}
            onClick={() => lightbox.open({ slides, index })}
            style={{ cursor: 'pointer' }}
          />
        ))}
      </SimpleGrid>

      {/* ズーム、サムネイル、フルスクリーン、ダウンロードを追加 */}
      <Lightbox
        withZoom
        withThumbnails
        withFullscreen
        withDownload
      />
    </>
  );
}
```

**動画スライドの対応:**
```tsx
const slides: LightboxSlideData[] = [
  { src: '/photo1.png' },                          // 画像
  { type: 'video', src: '/video.mp4' },            // 動画
  { type: 'custom', render: () => <MyWidget /> },  // カスタム
];
```

**v9.4.0 追加: `ResourcesDayView` コンポーネント（カレンダー拡張）**

会議室・人物・機器などのリソースをカレンダービューで管理するコンポーネント。

```tsx
import { ResourcesDayView } from '@mantine/dates';

const resources = [
  { id: 'room-a', label: '会議室 A' },
  { id: 'room-b', label: '会議室 B' },
];

const events = [
  {
    id: '1',
    resourceId: 'room-a',
    title: 'デザインレビュー',
    start: new Date('2026-09-13T10:00:00'),
    end: new Date('2026-09-13T11:00:00'),
  },
];

function CalendarDemo() {
  return (
    <ResourcesDayView
      resources={resources}
      events={events}
      date={new Date('2026-09-13')}
      // ドラッグ&ドロップ、業務時間ハイライト、スロット選択をサポート
      withDragDrop
      businessHours={{ start: 9, end: 18 }}
    />
  );
}
```

**v9.4.0 追加: `ComboboxPopover` コンポーネント**

`Select`/`MultiSelect` と異なり、**入力フィールドなしで**任意のボタンにドロップダウンを付与できるコンポーネント。

```tsx
import { ComboboxPopover } from '@mantine/core';

function FilterButton() {
  return (
    <ComboboxPopover
      data={['React', 'Vue', 'Angular', 'Svelte']}
      onOptionSubmit={(value) => console.log('選択:', value)}
    >
      {/* 任意の要素をターゲットに */}
      <ComboboxPopover.Target>
        <Button>フレームワークを選択</Button>
      </ComboboxPopover.Target>
    </ComboboxPopover>
  );
}
```

**Node.js 要件の更新:**
```
Mantine v9.6.0 以降: Node.js 22 以上が必要
（Node.js 20 は 2026年4月に EOL）
```

### ③ なぜ効果的か

- **`@mantine/lightbox`**: フルスクリーンギャラリーを一から実装する手間を省き、ズーム・動画・カスタムスライドなどの複雑な機能を宣言的に追加できる
- **`ResourcesDayView`**: 会議室予約・リソース管理などのビジネスアプリで頻出するカレンダービューを標準提供
- **`ComboboxPopover`**: `Select` コンポーネントが持つ「input 要素が必須」という制約を取り除き、デザインの自由度を大幅に向上
- **Node.js 22 移行**: EOL に達した Node.js 20 からの正式な移行を促進し、長期サポートバージョンに統一
