## 1. Google が「バックボタンハイジャック」をスパムポリシーに追加（6月15日施行）

**記事タイトル**: Introducing a new spam policy for "back button hijacking"
**URL**: [https://developers.google.com/search/blog/2026/04/back-button-hijacking](https://developers.google.com/search/blog/2026/04/back-button-hijacking)

### ① 目的・問題意識

「バックボタンハイジャック」とは、サイトが JavaScript を使ってブラウザの履歴スタックを操作し、ユーザーが「戻る」ボタンを押しても本来のページへ戻れなくしたり、意図しないページへ誘導したりする手法。具体的には以下が問題視されている:

- ページロード時に `history.pushState()` / `history.replaceState()` で偽のエントリを大量に積み込む（history stack stuffing）
- `popstate` イベントをインターセプトしてリダイレクトする
- 「離脱しようとしたらオーバーレイを表示する」exit-intent popup がバックボタンを奪う

Google はこれをユーザー体験を損なう「悪意ある慣行」と分類し、2026 年 6 月 15 日から手動スパムアクションまたはアルゴリズムによる降格を適用するスパムポリシーを施行することを発表した（2ヶ月前に事前予告）。

### ② 具体的な技術詳細

#### バックボタンハイジャックの典型的なコード例（悪例）

```javascript
// ❌ ページロード時に偽エントリを積んでバックボタンを奪う
window.addEventListener('load', () => {
  // 偽の履歴エントリを複数プッシュ
  history.pushState(null, '', window.location.href);
  history.pushState(null, '', window.location.href);
  history.pushState(null, '', window.location.href);
});

// ❌ popstate をインターセプトしてユーザーを閉じ込める
window.addEventListener('popstate', (event) => {
  // バックボタンを押されたら広告ページへリダイレクト
  window.location.replace('https://example.com/ad-page');
});
```

```javascript
// ❌ replaceState でバック先のURLを書き換える
window.addEventListener('load', () => {
  history.pushState(null, '', '/');
  history.replaceState(null, '', '/landing-page-you-never-visited');
});
```

#### 合法的な History API の使用例（SPA ルーティング）

```javascript
// ✅ SPA の正規ナビゲーション — ユーザーが選択したURLを変更する
function navigateTo(path) {
  history.pushState({ page: path }, '', path);
  renderPage(path);
}

// ✅ ブラウザバックに正しく応答する
window.addEventListener('popstate', (event) => {
  if (event.state) {
    renderPage(event.state.page); // 前のページを再描画
  }
});
```

#### 違反コードの検出方法

```javascript
// ページロード時に pushState が呼ばれていないかチェック
// Chrome DevTools → Application → Session Storage で
// 現在のエントリ数と、ページ遷移前後の差分を確認

// Google は以下のパターンを検出対象とする:
// 1. ページロードイベントで発生する pushState/replaceState
// 2. popstate ハンドラでのリダイレクト
// 3. exit-intent popup がバックボタンを阻害するケース
```

#### 修正チェックリスト

1. ページロード時に `history.pushState()` / `history.replaceState()` を呼んでいるコードを削除する
2. `popstate` ハンドラでリダイレクトしているコードを削除する
3. サードパーティスクリプト（広告ネットワーク・アフィリエイトスクリプト・exit-intent popup ツール）も監査する
4. Google Search Console でサイトへの手動アクションを確認する

> Google の Chris Nelson 氏: **「ユーザーがブラウザの履歴をナビゲートする能力を妨げるようなことは何もしないようにしてください」**

### ③ なぜ効果的か

| 観点 | 内容 |
|------|------|
| **ユーザー保護** | ユーザーが意図した戻り先に確実に戻れるようになる |
| **SEO リスク管理** | 6月15日以降、違反サイトはランキング降格・手動アクション対象となる |
| **サードパーティ責任** | 広告プラットフォーム由来のコードであっても、サイトオーナーが責任を負う |
| **検出メカニズム** | Chrome の集計ブラウジングデータ + クローラーの JS 解析 + 手動レビューの組み合わせで検出 |

## 2. なぜ AI はフロントエンドが苦手なのか — Adam Argyle

**記事タイトル**: Why AI Sucks At Front End
**URL**: [https://nerdy.dev/why-ai-sucks-at-front-end](https://nerdy.dev/why-ai-sucks-at-front-end)
**著者**: Adam Argyle (Google Chrome CSS エンジニア / nerdy.dev)
**公開日**: 2026年4月12日

### ① 目的・問題意識

2023年頃、「フロントエンドエンジニアは AI に最初に代替される職種」という予測が広まった。しかし 2026 年になっても AI はフロントエンドの本質的な問題をうまく解けていない。Adam Argyle はその根本的な理由を分析する。

### ② 具体的な論点・技術詳細

#### 問題1: AI は古いデータで学習している

AI は膨大なチュートリアルを読み込んだ「最新情報に疎いシニカルな開発希望者」のようなもので、学習データは：
- 古い解決策（IE 時代のハック、レガシーなレイアウト手法）
- オリジナリティのない UI パターン（Bootstrap 的なテンプレート）
- 品質の低いコード

```css
/* AI が提案しがちな古いアプローチ (2018年頃の書き方) */
.container {
  display: flex;
  -webkit-display: -webkit-flex;  /* 不要なベンダープレフィックス */
  -webkit-flex-wrap: wrap;         /* 今は flex-wrap: wrap で十分 */
  flex-wrap: wrap;
}

/* AI が知らない可能性がある 2026年のモダンCSS */
.container {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(min(200px, 100%), 1fr));
  container-type: inline-size;
}

.item {
  /* コンテナクエリを使用 */
  @container (min-width: 300px) {
    font-size: 1.2rem;
  }
}
```

#### 問題2: フロントエンドは「動く的」

ユーザーは以下の無数の組み合わせで操作する:
- ビューポートサイズ（デスクトップ / タブレット / モバイル / 折りたたみ端末）
- テーマ設定（`prefers-color-scheme: dark/light`）
- 入力デバイス（マウス / タッチ / キーボード / スクリーンリーダー）
- ブラウザ・バージョン
- アクセシビリティ設定（`prefers-reduced-motion`, `prefers-contrast`）

```css
/* AI はこうした複合的な状態に対応する CSS を書けない */
.button {
  /* ライトモード + ホバー */
  background: oklch(70% 0.2 250);

  /* ダークモード */
  @media (prefers-color-scheme: dark) {
    background: oklch(30% 0.2 250);
  }

  /* モーション無効化 */
  @media (prefers-reduced-motion: no-preference) {
    transition: transform 0.2s ease;
  }

  /* タッチデバイスではホバーなし */
  @media (hover: hover) {
    &:hover {
      transform: scale(1.05);
    }
  }
}
```

#### 問題3: AI はレンダリングエンジンではない

AI は「数学が苦手なテキスト予測機」であり、CSS のカスケード・インヘリタンス・レイアウト計算の視覚的結果を「見て」確認できない。

- スクリーンショットを渡しても空間的関係を正確に把握できない
- `calc()` や `clamp()` の計算結果を誤る
- ネストした `display: grid` / `flexbox` の相互作用を追えない

```css
/* AI が間違えやすい計算 */
.element {
  /* これが実際に何pxになるか AI は計算できないことがある */
  width: clamp(
    200px,
    calc(50vw - 2 * var(--gap) - var(--sidebar-width)),
    800px
  );
}
```

#### 問題4: CSS の因果連鎖が長い

CSS の「ある変更がどこかに影響する」という連鎖は非常に長い。

```
font-size を変更
  → em 単位で指定したすべての値が変化
    → padding / margin / border-radius が変化
      → レイアウトが変化
        → overflow が変化
          → スクロールバーの出現/非出現が変化
            → コンテナ幅が変化
              → grid の列数が変化
```

AI はこの連鎖全体を正確に追跡できない。

### ③ なぜ効果的か（記事の視点として）

- **AI の「得意なこと」の明確化**: AI は「ありきたりな UI の scaffolding」「定型的な退屈な作業」には有効
- **AI ツールの正しい使い方へ**: AI を「全部やらせる」のではなく「出発点を速くする」ために使う認識への転換
- **2026年でも人間のフロントエンド開発者の価値を示す**: 新しい CSS 機能・ユーザーの多様性・視覚的判断が必要な領域では人間が不可欠

## 3. 試せる View Transitions レシピ 7 選 — CSS-Tricks

**記事タイトル**: 7 View Transitions Recipes to Try
**URL**: [https://css-tricks.com/7-view-transitions-recipes-to-try/](https://css-tricks.com/7-view-transitions-recipes-to-try/)
**著者**: Sunkanmi Fafowora
**公開日**: 2026年4月13日

### ① 目的・問題意識

View Transitions API が全主要ブラウザで Baseline になり、クロスドキュメントビュートランジションも実用的になった。しかし「具体的にどんなアニメーションが作れるか」のレシピが少ない。本記事はコピー＆ペーストで使える 7 つのトランジションレシピを提供する。

### ② 具体的なコードと技術詳細

#### 基本セットアップ（全レシピ共通）

```css
/* ① アクセシビリティ対応のオプトイン */
@media (prefers-reduced-motion: no-preference) {
  @view-transition {
    navigation: auto;
    types: <transition-type-name>;
  }
}

/* ② ::view-transition-old() = 現在のページのスナップショット */
/* ③ ::view-transition-new() = 次のページのスナップショット */
/* ④ :active-view-transition-type() でトランジション種別を判別 */
```

---

#### レシピ 1: Pixelate Dissolve（ぼかし溶解）

**効果**: ページがブラーしながらフェードアウト/イン

```css
@media (prefers-reduced-motion: no-preference) {
  @view-transition {
    navigation: auto;
    types: pixelate-dissolve;
  }
}

html:active-view-transition-type(pixelate-dissolve)::view-transition-old(root) {
  animation: pixelate-out 1.4s ease forwards;
}

html:active-view-transition-type(pixelate-dissolve)::view-transition-new(root) {
  animation: pixelate-in 1.4s ease forwards;
}

@keyframes pixelate-out {
  0%   { filter: blur(0px);  opacity: 1; }
  100% { filter: blur(40px); opacity: 0; }
}

@keyframes pixelate-in {
  0%   { filter: blur(40px); opacity: 0; }
  100% { filter: blur(0px);  opacity: 1; }
}
```

---

#### レシピ 2: Wipe Up（上方向ワイプ）

**効果**: 現在ページが上に拭き取られ、新ページが下から現れる

```css
@media (prefers-reduced-motion: no-preference) {
  @view-transition {
    navigation: auto;
    types: wipe-up;
  }
}

html:active-view-transition-type(wipe-up)::view-transition-old(root) {
  animation: wipe-out 1.4s ease forwards;
}

html:active-view-transition-type(wipe-up)::view-transition-new(root) {
  animation: wipe-in 1.4s ease forwards;
}

@keyframes wipe-out {
  from { clip-path: inset(0 0 0 0); }
  to   { clip-path: inset(0 0 100% 0); }
}

@keyframes wipe-in {
  from { clip-path: inset(100% 0 0 0); }
  to   { clip-path: inset(0 0 0 0); }
}
```

---

#### レシピ 3: Rotate In-Out（ズーム回転）

**効果**: 旧ページが縮小しながら時計回りに回転、新ページが反時計回りで拡大

```css
@media (prefers-reduced-motion: no-preference) {

    navigation: auto;
    types: zoom-rotate;
  }
}

  transform-origin: center;
}

  animation: zoom-rotate-in 1.4s ease forwards;
  transform-origin: center;
}

@keyframes zoom-rotate-out {
  to { transform: scale(0) rotate(180deg); opacity: 0; }
}

@keyframes zoom-rotate-in {
  from { transform: scale(0) rotate(-180deg); opacity: 0; }
}
```

#### レシピ 7: 3D Flip（3Dフリップ）

**効果**: ページがカードのようにY軸を中心にフリップする

```css
@media (prefers-reduced-motion: no-preference) {
  @view-transition {
    navigation: auto;
    types: flip-3d;
  }
}

/* フリップにはパースペクティブが必要 */
html:active-view-transition-type(flip-3d)::view-transition-group(root) {
  perspective: 1000px;
}

html:active-view-transition-type(flip-3d)::view-transition-old(root) {
  animation: flip-out 0.7s ease-in forwards;
  backface-visibility: hidden;
}

  animation: flip-in 0.7s ease-out 0.7s backwards;
  backface-visibility: hidden;
}

@keyframes flip-out {
  to { transform: rotateY(90deg); opacity: 0; }
}

@keyframes flip-in {
  from { transform: rotateY(-90deg); opacity: 0; }
  to   { transform: rotateY(0deg); opacity: 1; }
}
```

### ③ なぜ効果的か

| 観点 | 内容 |
|------|------|
| **コピー＆ペースト可能** | `@view-transition` と `@keyframes` の 2 ブロックで完結 |
| **アクセシビリティ対応済み** | 全レシピが `prefers-reduced-motion` でラップされている |
| **Baseline 対応** | View Transitions API は全主要ブラウザで利用可能 |
| **JavaScript 不要** | 純粋な CSS のみでページ遷移アニメーションを実装できる |
| **拡張性** | `:active-view-transition-type()` で複数のアニメーションタイプを共存させられる |

## 4. Chrome 147 の新 CSS 機能: border-shape / contrast-color() / Element-Scoped View Transitions

**リリース日**: 2026年4月7〜8日
**URL**: [https://developer.chrome.com/blog/new-in-chrome-147](https://developer.chrome.com/blog/new-in-chrome-147)

### ① 目的・問題意識

Chrome 147 では、フロントエンド開発者の日常に直接影響する 3 つの CSS 機能が安定版に入った。

---

### 4a. CSS `border-shape` — 非矩形ボーダーの実現

#### 目的

`clip-path` は要素を切り抜くが、背景・ボーダー・フォーカスアウトライン・ボックスシャドウはすべて矩形のまま残る。`border-shape` は要素のジオメトリ自体を変えるため、これらすべてが指定した形に従う。

#### コード例

```css
/* ポリゴン（六角形）ボーダー */
.hexagon {
  border-shape: polygon(50% 0%, 100% 25%, 100% 75%, 50% 100%, 0% 75%, 0% 25%);
  background: oklch(70% 0.2 250);
  border: 3px solid oklch(40% 0.2 250);
  /* border、background、box-shadow がすべて六角形に従う */
  box-shadow: 0 4px 20px oklch(40% 0.2 250 / 0.4);
}

/* 円形ボーダー */
.circle-card {
  border-shape: circle(50%);
  background: linear-gradient(135deg, #667eea 0%, #764ba2 100%);
  width: 200px;
  height: 200px;
}

/* shape() 関数で複雑なパス */
.custom-shape {
  border-shape: shape(from 0% 0%, curve to 100% 0%, via 50% -20%, line to 100% 100%, line to 0% 100%);
}

/* clip-path との違い */
.using-clip-path {
  /* ❌ clip-path: ビジュアルは切り取られるが、
     レイアウトボックスは矩形のまま
     box-shadowがはみ出る */
  clip-path: polygon(50% 0%, 100% 25%, 100% 75%, 50% 100%, 0% 75%, 0% 25%);
}

.using-border-shape {
  /* ✅ border-shape: ジオメトリ自体が変わる
     border、background、box-shadow すべてが形に従う */
  border-shape: polygon(50% 0%, 100% 25%, 100% 75%, 50% 100%, 0% 75%, 0% 25%);
}
```

---

### 4b. CSS `contrast-color()` — アクセシブルなテキスト色の自動算出

#### 目的

背景色に対してコントラスト比（WCAG AA: 4.5:1）を満たすテキスト色を黒または白で自動的に選択する。ダークモード対応やユーザー定義カラーに対して手動でテキスト色を計算する必要がなくなる。

#### コード例

```css
/* 基本使用法 */
.card {
  background-color: var(--user-color);
  /* 背景色に対して最も高いコントラストを持つ黒または白を返す */
  color: contrast-color(var(--user-color));
}

/* ハードコードされた色でも動作 */
.badge-success {
  background: #34cdf2;
  color: contrast-color(#34cdf2); /* → black が選択される */
}

.badge-dark {
  background: #2d3748;
  color: contrast-color(#2d3748); /* → white が選択される */
}

/* CSS カスタムプロパティとの組み合わせ */
:root {
  --brand-primary: oklch(70% 0.2 250);
}

.button-primary {
  background: var(--brand-primary);
  color: contrast-color(var(--brand-primary));
  /* ブランドカラーが変わってもテキスト色が自動調整される */
}

/* 注意: 中間トーンの色ではコントラストが不十分になる場合がある */
/* oklch(50% 0.1 200) のような色には白も黒も4.5:1を満たさない */
.caution {
  background: oklch(50% 0.1 200);
  color: contrast-color(oklch(50% 0.1 200));
  /* ⚠️ 要確認: WCAG AA を満たさない可能性 */
}
```

### 4c. Element-Scoped View Transitions — 要素単位の同時トランジション

#### 目的

従来の `document.startViewTransition()` はページ全体をロックして同時に 1 つしかトランジションできなかった。`element.startViewTransition()` を使うと、DOM の一部だけをトランジションのスコープにでき、**複数のトランジションを同時並行で実行**できる。

#### コード例

```javascript
// 従来の document レベルのトランジション（ページ全体がロック）
document.startViewTransition(() => {
  updateDOM();
});

// ✅ Element-Scoped View Transitions（Chrome 147+）
const list = document.querySelector('ul');

// リスト内だけをトランジションのスコープにする
list.startViewTransition(() => {
  // ulの子要素だけがスナップショット対象になる
  shuffleListItems(list);
});

// ✅ 同時に複数のトランジションを実行
const listA = document.querySelector('#list-a');
const listB = document.querySelector('#list-b');

// 両方のリストを同時にシャッフル（それぞれ独立したトランジション）
listA.startViewTransition(() => shuffleListItems(listA));
listB.startViewTransition(() => shuffleListItems(listB));

// ✅ ネストしたトランジション
const outer = document.querySelector('.outer');
const inner = document.querySelector('.inner');

outer.startViewTransition(() => {
  // 外側のトランジション中に内側のトランジションも開始できる
  inner.startViewTransition(() => {
    updateInnerContent(inner);
  });
  updateOuterContent(outer);
});
```

```css
/* Element-Scoped View Transitions の CSS */
/* スコープ要素の直接の子に view-transition-name を付ける */
.list-item {
  view-transition-name: var(--item-id); /* 各アイテムに一意の名前 */
}

/* スコープ外の要素はインタラクティブなまま */
.controls button {
  /* スコープ（ul）の外なので、トランジション中もクリック可能 */
  pointer-events: auto;
}
```

### ③ なぜ効果的か

| 機能 | 効果 |
|------|------|
| **border-shape** | JavaScript なしで真の非矩形 UI を実現。ボーダー・背景・シャドウすべてが形に追従 |
| **contrast-color()** | アクセシビリティ対応の自動化。カラーパレット変更時の手動調整が不要 |
| **Element-Scoped View Transitions** | 複数要素の同時トランジション・ネスト・ページの部分的インタラクティビティが実現 |

## 5. CSS アンカーポジショニングだけで作るフローティングフォーカスインジケーター — Polypane

**記事タイトル**: CSS-only floating focus with anchor positioning
**URL**: [https://polypane.app/blog/css-only-floating-focus-with-anchor-positioning/](https://polypane.app/blog/css-only-floating-focus-with-anchor-positioning/)

### ① 目的・問題意識

アクセシビリティのためのフォーカスインジケーター（タブキーで操作する際に現在フォーカスされている要素を示す枠）は通常、各要素に `outline` スタイルを当てるだけだった。しかし「フォーカスが移動するたびに流れるように追いかける」フローティングインジケーターは JavaScript なしには作れなかった。CSS Anchor Positioning を使えば、JavaScript ゼロで実現できる。

### ② 具体的なコードと技術詳細

#### 基本概念: CSS Anchor Positioning

CSS Anchor Positioning は、ある要素（アンカー）に別の要素（ポジション要素）を tether（紐付け）する機能。

```css
/* アンカー側: anchor-name を設定 */
.anchor-element {
  anchor-name: --my-anchor;
}

/* ポジション要素側: position-anchor で紐付け */
.positioned-element {
  position: absolute;
  position-anchor: --my-anchor;
  /* anchor() 関数で位置を参照 */
  top: anchor(top);
  left: anchor(left);
}
```

#### フローティングフォーカスインジケーターの実装

```css
/* ① フォーカスされた要素にアンカー名を動的に設定 */
/* :focus-visible を使って、キーボードフォーカス時のみ適用 */
*:focus-visible {
  outline: none; /* デフォルトのアウトラインを非表示 */
  anchor-name: --focused-element; /* この要素をアンカーに設定 */
}

/* ② html::before を使ってフローティングインジケーターを作成 */
/* 余分な DOM 要素を追加せずに済む */
html::before {
  content: '';
  position: fixed; /* スクロールに追従しない */
  position-anchor: --focused-element; /* フォーカス要素にアンカー */

  /* アンカー要素の境界に合わせて配置 */
  /* inset: anchor(inside) は top/right/bottom/left すべてを
     アンカー要素の対応する辺に合わせる省略記法 */
  inset: anchor(inside);
  margin: -4px; /* フォーカス要素より少し大きく */

  /* フォーカスインジケーターのスタイル */
  border: 2px solid oklch(60% 0.25 250);
  border-radius: 4px;
  background: oklch(60% 0.25 250 / 0.1);
  pointer-events: none; /* クリックイベントを透過させる */
  z-index: 9999;

  /* フォーカスが移動する際のアニメーション */
  transition:
    top 0.15s ease,
    right 0.15s ease,
    bottom 0.15s ease,
    left 0.15s ease;
}

/* ③ フォーカスがないときはインジケーターを非表示 */
/* :focus-within を使ってフォーカスがあるかどうかを確認 */
html:not(:focus-within)::before {
  display: none;
}

/* ④ プログレッシブエンハンスメント */
/* @supports を使って、アンカーポジショニングをサポートしていない
   ブラウザには従来の outline を表示 */
@supports not (position-anchor: --test) {
  /* アンカーポジショニング非対応ブラウザ向けのフォールバック */
  *:focus-visible {
    outline: 2px solid oklch(60% 0.25 250);
    outline-offset: 2px;
  }

  html::before {
    display: none; /* フローティングインジケーターは非表示 */
  }
}
```

#### 応用: カスタムシェイプのフォーカスインジケーター

```css
/* 楕円形のフォーカスインジケーター */
html::before {
  content: '';
  position: fixed;
  position-anchor: --focused-element;
  inset: anchor(inside);
  margin: -6px;

  /* 楕円形 */
  border-radius: 50%;
  border: 3px solid oklch(70% 0.3 30); /* オレンジ系 */
  background: transparent;
  pointer-events: none;
  z-index: 9999;

  transition: inset 0.1s ease;
}

/* テキスト入力には角丸四角形 */
input:focus-visible,
textarea:focus-visible {
  anchor-name: --focused-element;
}

/* ボタンや通常要素には円形 */
button:focus-visible,
a:focus-visible,
[tabindex]:focus-visible {
  anchor-name: --focused-element;
}
```

### ③ なぜ効果的か

| 観点 | 内容 |
|------|------|
| **JavaScript ゼロ** | `getBoundingClientRect()` や `addEventListener('focus', ...)` が不要 |
| **DOM 汚染なし** | `html::before` 疑似要素で実装するため HTML に要素追加不要 |
| **アニメーション自動化** | CSS `transition` がフォーカス移動のアニメーションを担う |
| **プログレッシブエンハンスメント** | `@supports` でサポートしないブラウザには通常の outline が表示される |
| **アクセシビリティ向上** | フォーカスの位置が視覚的に追跡しやすくなりキーボードユーザーの体験が改善 |
