## 1. React、13歳の誕生日を迎える

**出典:** React Status #476 メイン記事 / [The React Foundation — react.dev](https://react.dev/blog/2026/02/24/the-react-foundation)

### ①目的・問題意識

React は 2013年5月29日に JSConf US でオープンソース化された。13年後の2026年現在、世界で約5,500万のウェブサイトを動かし、約2,000万人の開発者が利用する巨大なエコシステムに成長している。誕生日を機に、React の独立性・ガバナンス体制を振り返る記事。

### ②技術詳細

- 2025年10月、Meta は React・React Native・JSX を **React Foundation**（Linux Foundation 傘下）に移管すると発表
- **2026年2月24日**、React Foundation が正式に発足
- プラチナ創設メンバー：**Amazon、Callstack、Expo、Huawei、Meta、Microsoft、Software Mansion、Vercel**
- エグゼクティブディレクター：Seth Webster
- React は LF Projects, LLC の下でホストされる
- リポジトリ・ウェブサイト・インフラの移管作業も進行中

### ③なぜ効果的か

1社（Meta）に依存しない中立的なガバナンスにより、長期的な安定性と幅広いコントリビューターの参加が促進される。React Conf の将来計画や、エコシステム全体を支援するプログラムの策定が可能になる。

## 2. pip-it-up — Document Picture-in-Picture Toolkit for React

**出典:** [github.com/Shakya47/pip-it-up](https://github.com/Shakya47/pip-it-up) / [pip-it-up.vercel.app](https://pip-it-up.vercel.app/)

### ①目的・問題意識

ブラウザの **Document Picture-in-Picture API**（Chrome/Edge ≥ 116）を使うと、任意の HTML コンポーネントをフローティングウィンドウに表示できる。しかし生の API を扱うには、CSS 同期・DOM 状態保持・リサイズ対応など多くのボイラープレートが必要。`pip-it-up` はゼロコンフィグでこれらを解決するフレームワーク非依存ライブラリ（React バインディング付き）。

### ②具体的なコード

```bash
npm install @pip-it-up/react @pip-it-up/core
```

```jsx
import { PipWrapper, PipTrigger } from '@pip-it-up/react';

function App() {
  return (
    <PipWrapper>
      <div>
        <h1>My Floating Tool</h1>
        {/* 任意のコンテンツをフローティングウィンドウに表示 */}
        <PipTrigger>
          <button>Open Picture-in-Picture</button>
        </PipTrigger>
      </div>
    </PipWrapper>
  );
}
```

**PipWrapper** がコンテキストを提供し、**PipTrigger** でユーザーのジェスチャーに応じてウィンドウを開く。

#### 低レベルの react-document-picture-in-picture も選択肢

```bash
npm install react-document-picture-in-picture
```

```jsx
import ReactDocumentPictureInPicture from "react-document-picture-in-picture";

<ReactDocumentPictureInPicture
  buttonRenderer={({ open, close, toggle, isOpen }) => (
    <div>
      <b>Is {isOpen ? 'Open' : 'Closed'}</b>
      <button onClick={open}>Open</button>
      <button onClick={close}>Close</button>
      <button onClick={toggle}>Toggle</button>
    </div>
  )}
  onOpen={() => console.log('Opened')}
  onClose={() => console.log('Closed')}
  onResize={(w, h) => console.log(`Resized to ${w}x${h}`)}
>
  {/* フローティングウィンドウ内に表示されるコンテンツ */}
  Content displayed in the floating window
</ReactDocumentPictureInPicture>
```

### ③技術詳細・なぜ効果的か

| 機能 | 説明 |
|------|------|
| **自動サイズ検出** | ResizeObserver を使い手動設定不要 |
| **DOM 状態保持** | 物理的に DOM 要素を切り離し移動するため、イベントリスナー・カーソル位置を維持 |
| **CSS 同期** | Tailwind / CSS-in-JS のスタイルを MutationObserver でリアルタイム同期 |
| **プレースホルダー** | メインウィンドウのレイアウト崩れを防ぐ responsive placeholder を自動挿入 |
| **グレースフルデグレード** | 非サポートブラウザでポップアップ等へフォールバック |

**ブラウザ対応:** Chrome/Edge ≥ 116（Safari/Firefox は fallback あり）。HTTPS とユーザージェスチャー（クリック等）が必須。

従来の `<video>` 要素限定の PiP と異なり、**任意の React コンポーネントをフローティングウィンドウに表示できる**点が革新的。チャット UI・ダッシュボード・コントロールパネルなど幅広いユースケースに対応する。

## 3. Building Predictive Text Inputs in React

**出典:** [github.com/KhaledSakr/react-inline-predict](https://github.com/KhaledSakr/react-inline-predict)

### ①目的・問題意識

テキスト入力でユーザーが入力中に補完候補をインライン表示する「プレディクティブテキスト」機能は、UX 向上に効果的だが自前実装は複雑。`react-inline-predict` は辞書ベース・外部 API ベース両方に対応した軽量コンポーネント。

### ②具体的なコード

```bash
npm install --save react-inline-predict
```

#### 基本実装（辞書ベース）

```jsx
import InputPredict from 'react-inline-predict';

function ColorInput() {
  const [color, setColor] = React.useState('');

  function handleChange(value, isMatch) {
    if (isMatch) {
      // 辞書にマッチした場合の処理
      fetchColorData(value);
    }
    setColor(value);
  }

  return (
    <InputPredict
      type="text"
      name="color"
      placeholder="colorname"
      dictionary={["red", "green", "blue", "yellow", "purple"]}
      onValueChange={handleChange}
    />
  );
}
```

#### 外部 API からの補完候補

```jsx
// 外部から prediction を渡す方式（LLM API 等と組み合わせ可能）
<InputPredict
  suggestion={this.state.prediction}  // API から取得した補完テキスト
  onValueChange={this.handleChange}
/>
```

#### スタイルカスタマイズ

```jsx
<InputPredict
  inputStyle={{ fontSize: '16px', border: '1px solid #ccc' }}
  suggestionStyle={{ color: '#999', opacity: 0.7 }}
  dictionary={["apple", "banana", "cherry"]}
  onValueChange={handleChange}
/>
```

```css
/* CSS クラスでのカスタマイズ */
.input-predict-container { position: relative; }
.input-predict-input { background: transparent; z-index: 0; }
.input-predict-suggestion { position: absolute; z-index: -1; color: #aaa; }
```

#### キーボード操作

- `Tab` または `Enter`: 補完候補を確定
- `↑` / `↓`: 候補リストのナビゲーション

### ③技術詳細・なぜ効果的か

**onValueChange** は `(value: string, match: boolean)` の2引数を受け取り、辞書マッチ時のみ API コール等の副作用を実行できる。SSR 対応（Isomorphic）で Next.js 等のフレームワークでも動作する。

AI API（OpenAI / Anthropic 等）と組み合わせることで、動的な LLM ベースの補完にも対応可能。`react-admin` の `PredictiveTextInput` はこの発展形として `dataProvider.getCompletion()` 経由で任意の AI API を呼び出す実装を提供している。

## 4. TanStack Start の Deferred Hydration（遅延ハイドレーション）

**出典:** [youtube.com/watch?v=_PB9rHndhU8](https://www.youtube.com/watch?v=_PB9rHndhU8)（Jack Herrington）/ [tanstack.com/start/latest/docs/.../deferred-hydration](https://tanstack.com/start/latest/docs/framework/react/guide/deferred-hydration) / [github.com/jherr/ts-deferred-hydration](https://github.com/jherr/ts-deferred-hydration)

> ⚠️ 動画リンクのため内容確認はスキップ。ドキュメント・GitHub リポジトリから詳細を解説。

### ①目的・問題意識

ハイドレーションとは、SSR で生成された静的 HTML を React がインタラクティブな状態に変換するクライアントサイド処理（JS 読み込み・実行・イベント接続）。大規模ページではユーザーがすぐに操作しない部分（ページ下部のレビュー・コメント・関連コンテンツ等）もすべてハイドレートするため、**起動時間が無駄に長くなる**問題がある。

TanStack Start の **Deferred Hydration** は「必要になったタイミングで指定部分だけハイドレート」を宣言的に実現する機能（2026年5月20日リリース）。

### ②具体的なコード

```typescript
import { Hydrate } from '@tanstack/react-start'
import { interaction, visible } from '@tanstack/react-start/hydration'

// 例: ユーザーインタラクションが起きるまでカルーセルをハイドレートしない
export default function TanStackDeferredHydration({ guitars, onSelect }) {
  return (
    <Hydrate
      // ユーザーがフォーカス・ポインター・クリックしたときにハイドレート
      when={interaction({ events: ['focusin', 'pointerenter', 'click'] })}
      // ビューポートから 1200px 以内に入ったらチャンクをプリフェッチ
      prefetch={visible({ rootMargin: '1200px' })}
    >
      <RelatedGuitarsCarousel guitars={guitars} onSelect={onSelect} />
    </Hydrate>
  )
}
```

#### 4種類のハイドレーション戦略比較（Jack Herrington のデモより）

| ルート | 戦略 | JS バンドル | ハイドレーションタイミング |
|--------|------|-------------|---------------------------|
| `/regular` | Eager（デフォルト） | あり | ページ読み込みと同時 |
| `/react-selective` | React.lazy + Suspense | なし | 自動・低優先度（クリックで昇格） |
| `/react-conditional` | DIY インテントゲート | なし | ポインター・フォーカス・クリック後のみ |
| `/tanstack-deferred` | TanStack `<Hydrate>` | なし | ユーザーインタラクション後のみ |

#### React のみで同等のことをやる場合（DIY アプローチ）

```tsx
import { lazy, Suspense, useState, use } from 'react'

const LazyCarousel = lazy(() => import('./RelatedGuitarsCarousel'))

function ConditionalHydration({ guitars, onSelect }) {
  const [shouldHydrate, setShouldHydrate] = useState(false)

  return (
    <div
      onPointerEnter={() => setShouldHydrate(true)}
      onFocus={() => setShouldHydrate(true)}
    >
      {shouldHydrate ? (
        <Suspense fallback={<div>Loading...</div>}>
          <LazyCarousel guitars={guitars} onSelect={onSelect} />
        </Suspense>
      ) : (
        // SSR で生成された HTML をそのまま表示
        <div dangerouslySetInnerHTML={{ __html: serverRenderedHtml }} />
      )}
    </div>
  )
}
```

### ③なぜ効果的か

**TanStack `<Hydrate>` が優れている点：**

1. **CSS モジュールの自動 hoist** — React.lazy 分割時は CSS の `<link>` タグが SSR 時に document head へ挿入されず、チャンク到着まで一時的にスタイルなし描画が起きる。`<Hydrate>` はこれを自動解決する。
2. **イベントリプレイ** — ハイドレーション前に発生したユーザーイベントを再生する仕組みを内包。
3. **宣言的な制御** — `when` / `prefetch` を分離することで「見えたらプリフェッチ・操作したらハイドレート」という最適な戦略を数行で表現できる。
4. **ネスト対応** — 親バウンダリが先にハイドレートしてから子バウンダリがハイドレートする正しい順序を保証。

**重要な注意点:** バウンダリの外部で state / props / context 更新が起きた場合、React は正確性を保つためデファードバウンダリを早期ハイドレートすることがある。

## 5. Storybook 10.4 — AI 自動セットアップ・TanStack React 対応

**出典:** [storybook.js.org/blog/storybook-10-4/](https://storybook.js.org/blog/storybook-10-4/)

### ①目的・問題意識

Storybook は UI コンポーネントの開発・テストワークショップ。v10.4 ではセットアップの自動化・チームレビューの効率化・フレームワーク対応の拡充が行われた。

### ②技術詳細

#### AI 自動セットアップ

AI エージェントが複雑なアプリでも Storybook を自動セットアップ：

1. プロジェクト構造を解析
2. `storybook.config` を生成
3. モック（MSW 等）を生成
4. 最大10コンポーネントの Story とインタラクションテストを生成
5. スタイル付きレンダリングを自動検証・反復改善

#### TanStack React フレームワーク対応

TanStack コアチームとの共同開発による `@storybook/tanstack-react` を導入：

```bash
npx storybook@latest init --type tanstack-react
```

- **タイプセーフルーティング** のゼロコンフィグ対応
- **サーバーファンクション** のサポート
- **React Query** 等オプション機能のドキュメント統合

#### 変更検出サイドバーフィルター

新しく追加されたサイドバーフィルター：

| フィルター | 内容 |
|-----------|------|
| **New** | 新規追加された Story |
| **Modified** | コード変更の影響を受けた Story |
| **Related** | 変更に関連する可能性がある Story |

#### クイックシェアリング

ボタン1クリックで Storybook を **Chromatic** に公開。PR や CI 不要でチームメンバーがすぐにフィードバックできる。

#### その他

- **React Native 対応改善**: スタンドアロンエントリーポイントによるクリーンなセットアップ
- **実験的 React Component Meta**: Volar と TypeScript Language Server を利用した高品質な MCP メタデータ生成

### ③なぜ効果的か

AI セットアップにより Storybook の初期導入コストが大幅に低下。TanStack React への対応により、TanStack Start/Router ベースのプロジェクトでもファーストクラスの UI 開発環境が整う。変更検出フィルターはコードレビュー時の確認範囲を絞り込み、チームの効率を向上させる。
