## 1. Very Early Playing with random() in CSS

**出典:** https://frontendmasters.com/blog/very-early-playing-with-random-in-css/

### ① 目的・問題意識

CSS でランダムな値を扱う場合、従来は JavaScript に頼らざるを得なかった。たとえばカードを不規則に配置したり、アニメーションに揺らぎを持たせたりするには、JS で `Math.random()` を計算しインラインスタイルや CSS カスタムプロパティに書き込む必要があった。  
CSS `random()` 関数はこれをブラウザ・CSS エンジン側で直接解決する。値は CSS の解決フェーズで生成されるため、JS 不要でランダム性を表現できる。

### ② 具体的な構文・技術詳細

**基本構文:**

```
random( <random-key>? , <min> , <max> [, by <step>]? )
```

| パラメータ | 説明 |
|---|---|
| `<random-key>` | 省略可。キャッシュ戦略を指定（後述） |
| `<min>` | 最小値（単位付き） |
| `<max>` | 最大値（同単位） |
| `by <step>` | 省略可。刻み幅 |

**基本使用例（デフォルト：全要素で同値を共有）:**

```css
.card {
  top: random(5rem, 20rem);
  rotate: random(0deg, 360deg);
  animation-delay: random(0s, 3s);
}
```

**刻み幅を指定する例:**

```css
.grid-item {
  font-size: random(1rem, 20rem, by 5rem);
  /* 1rem, 6rem, 11rem, 16rem のいずれかになる */
  padding: random(2rem, 10rem, by 1.1rem);
}
```

**`<random-key>` によるキャッシュ制御:**

| キー | 挙動 |
|---|---|
| なし（デフォルト） | 同一スタイルルール内の全要素で同じ値を共有 |
| `per-element` | 要素ごとに異なる値を生成 |
| `--my-key`（dashed-ident） | 同じキー名を持つプロパティ間で値を共有 |
| `fixed <number>` | 明示的な固定値（0〜1 の実数） |

```css
/* 要素ごとに異なるランダム値 */
.item {
  top: random(per-element, 4rem, 10rem);
}

/* 幅と高さを同じランダム値で揃える（正方形になる） */
.box {
  width: random(--sync-size, 50px, 200px);
  height: random(--sync-size, 50px, 200px);
}
```

**プロダクション用フォールバックパターン:**

```css
.element {
  top: 10rem; /* フォールバック */
}

@supports (top: random(1rem, 5rem)) {
  .element {
    top: random(5rem, 20rem);
  }
}
```

### ③ なぜ効果的か

- **JS 依存を排除:** インラインスタイルへの書き込みが不要になり、コードが簡潔になる
- **CSS の宣言的な性質を維持:** ランダム性をスタイルシート側で完結できる
- **`per-element` でリスト・グリッドのバリエーション表現が容易:** JS のループ処理なしに、多数の子要素に自然なばらつきを付与できる
- **`--sync-key` でプロパティ間の同期が可能:** 幅と高さを揃えたい場合など、関連プロパティを同じ乱数に束ねられる

**ブラウザサポート（2026年時点）:** Safari 26.2 がリリース済み。Chrome・Firefox は未サポートのため `@supports` でのフォールバックが必要。

## 2. 9 Times the Web Platform Was Influenced by Libraries

**出典:** https://jadjoubran.io/blog/web-platform-influenced-by-libraries

### ① 目的・問題意識

ライブラリが「足りない機能を補う」存在として普及した後、ブラウザ標準がそのパターンを取り込んだ歴史を整理する記事。「昔は jQuery が必要だった」といった言い方をよく聞くが、それがなぜ・どのように標準化されたかを理解することで、今後の標準化動向を読む力が養われる。

### ② 9つの事例

**1. DOM セレクタ — `querySelector` / `querySelectorAll`**

```javascript
// 昔: jQuery が Sizzle エンジンで提供
$('.card.active')

// 現在: ブラウザネイティブ
document.querySelector('.card.active')
document.querySelectorAll('.card.active')
```

jQuery の `$()` が「CSS セレクタで要素を取得する」パターンを普及させ、ブラウザがそのまま標準化した。

---

**2. 要素の祖先探索 — `Element.closest()`**

```javascript
// 昔: jQuery の .closest()
$(element).closest('.modal')

// 現在: ブラウザネイティブ
element.closest('.modal')
```

DOM ツリーを上に遡って最初に一致する祖先を返すメソッド。手動の `while` ループが不要になった。

---

**3. クラス操作 — `classList`**

```javascript
// 昔: jQuery
$(el).addClass('active')
$(el).removeClass('active')
$(el).toggleClass('active')

// 現在: classList API
el.classList.add('active')
el.classList.remove('active')
el.classList.toggle('active')
```

---

**4. 非同期処理 — Promises / async/await**

```javascript
// 昔: Dojo Deferred, jQuery.Deferred, Q, Bluebird
$.ajax('/api/data').done(data => ...)

// 現在: ネイティブ Promises + Fetch
const data = await fetch('/api/data').then(r => r.json())
```

Promises/A+ 仕様が複数ライブラリの競合から生まれ、ECMAScript に標準化された。

---

**5. Ajax → Fetch API**

```javascript
// 昔: jQuery.ajax
$.ajax({ url: '/data', success: callback })

// 現在: Fetch API
const res = await fetch('/data')
const json = await res.json()
```

---

**6. ES Modules**

```javascript
// 昔: RequireJS (AMD), Browserify (CommonJS)
define(['dependency'], function(dep) { ... })
require(['app'], function() { ... })

// 現在: ES Modules
import { helper } from './helper.js'
export function myFunc() { ... }
```

---

**7. `Array.flat` — SmooshGate**

```javascript
// 昔: Lodash / Underscore
_.flatten([1, [2, [3]]])

// 現在: ネイティブ
[1, [2, [3]]].flat()
[1, [2, [3]]].flat(Infinity)
```

当初の提案名は `Array.prototype.flatten` だったが、MooTools が同名メソッドを別の挙動で `Array.prototype` にモンキーパッチしており、広く利用されているサイトが壊れることが判明。TC39 は 2018 年のミーティング（通称 **#SmooshGate**）で名称を `flat` に変更して解決した。

---

**8. CSS カスタムプロパティ（CSS 変数）**

```css
/* 昔: Sass 変数 */
$primary-color: #3498db;
.button { background: $primary-color; }

/* 現在: CSS カスタムプロパティ */
:root {
  --primary-color: #3498db;
}
.button {
  background: var(--primary-color);
}
```

Sass が変数の有用性を実証し、CSS 仕様に取り込まれた。Sass 変数と異なり、カスタムプロパティは実行時に変更可能でカスケードも機能する。

---

**9. CSS ネスティング**

```css
/* 昔: Sass */
.parent {
  color: red;
  .child {
    color: blue;
  }
}

/* 現在: CSS ネイティブネスティング */
.parent {
  color: red;
  .child {
    color: blue;
  }
  &:hover {
    opacity: 0.8;
  }
}
```

---

**Temporal API（番外）**

Moment.js が Date API の問題点を長年にわたって整理し、Moment.js メンテナの Maggie Johnson-Pint が Bloomberg・Igalia と共に TC39 の Temporal 提案をリード。将来の標準化が進行中。

### ③ なぜ効果的か

- ライブラリが「生きたプロトタイプ」として機能し、標準化委員会に実際のユースケースを提示した
- 「後から壊せない」web の性質上、後方互換性の問題（SmooshGate など）が生じることもあるが、それも含めて web の歴史として残る
- 現在普及中のライブラリのパターンが今後も標準化される可能性を示唆している

## 3. New in Chrome 148

**出典:** https://developer.chrome.com/blog/new-in-chrome-148  
**リリース日:** 2026年5月5〜6日

### ① 目的・問題意識

Chrome 148 では CSS・HTML の利便性を向上させる 2 つの主要機能と、オンデバイス AI API が追加された。

---

### ② 機能詳細

#### 3-1. 名前のみによるコンテナクエリ（Name-Only Container Queries）

**問題:** これまで `@container` を使うには `container-type` の指定が必須だった。`container-type` を設定するとレイアウト・スタイル・サイズのコンテインメントが発生し、意図せずレイアウトに影響を与えることがあった。

**解決策:** `container-name` のみでコンテナクエリが書けるようになった。

```css
/* 旧来の記法（container-type が必須） */
#container {
  container-name: --my-container;
  container-type: inline-size; /* 必須だった */
}

/* Chrome 148 以降（container-name のみで OK） */
#container {
  container-name: --foo;
  /* container-type 不要 */
}

@container --foo {
  input {
    background-color: green;
  }
}
```

```html
<div id="container">
  <div><input></div>
</div>
```

**効果:** コンテインメントの副作用を避けつつ、コンテナ名で条件分岐できる。スタイルのみをトリガーにしたい場面で有用。

---

#### 3-2. `<video>` / `<audio>` の `loading="lazy"`

**問題:** `<img>` と `<iframe>` には `loading="lazy"` 属性があり、ビューポート外のリソース読み込みを遅延できたが、`<video>` と `<audio>` には同等の仕組みがなかった。メディアリッチなページでは初期ロード時に大量の動画・音声リソースが読み込まれ、パフォーマンスが悪化していた。

**解決策:** `<video>` と `<audio>` にも `loading` 属性を追加。

```html
<!-- ビューポート付近になるまで読み込みを遅延 -->
<video loading="lazy" src="large-video.mp4" controls></video>
<audio loading="lazy" src="podcast.mp3" controls></audio>

<!-- デフォルト（即時読み込み） -->
<video loading="eager" src="hero-video.mp4" autoplay></video>
```

**効果:**
- ページの初期ロード時間を短縮
- データ使用量を削減（特にモバイル環境）
- `<img loading="lazy">` と同じ挙動で一貫性が生まれる

---

#### 3-3. Prompt API（オンデバイス AI）

Chrome 148 には Gemini Nano を使ったオンデバイス AI API（Prompt API）が搭載された。テキスト・画像・音声の入力に対応し、ブラウザ上で推論できる。また、Response Constraints として正規表現・JSON スキーマに準拠した出力を強制する機能も追加。

```javascript
const session = await ai.languageModel.create()
const result = await session.prompt('フランスの首都は？')
console.log(result) // "パリ"
```

---

### ③ なぜ効果的か

- **コンテナクエリの制約緩和:** `container-type` の副作用（コンテインメント）を気にせず名前ベースのクエリが書ける
- **メディア遅延読み込みの統一:** `img`・`iframe`・`video`・`audio` が同一の `loading` 属性で扱えるようになり、パフォーマンス最適化のパターンが統一される
- **Web AI のアクセシビリティ向上:** サーバー側 API なしでブラウザ内でテキスト生成・推論が行える

## 4. CSS メディアクエリ レンジ構文（Media Query Range Syntax）

**出典:** https://ishadeed.com/article/range-syntax/ / https://css-tricks.com/the-new-css-media-query-range-syntax/

### ① 目的・問題意識

従来の `min-width` / `max-width` によるメディアクエリは読みにくく、境界値（`min-width: 768px` と `max-width: 767px` など1px差）でのクラッシュが起きやすかった。新しいレンジ構文は数学的比較演算子を使うことでこれらの問題を解消する。

### ② 具体的なコードと比較

**最小幅の指定:**

```css
/* 旧来 */
@media (min-width: 400px) { }

/* 新構文 */
@media (width >= 400px) { }
```

**最大幅の指定:**

```css
/* 旧来 */
@media (max-width: 30em) { }

/* 新構文 */
@media (width <= 30em) { }
```

**範囲の指定（旧来は and が必要）:**

```css
/* 旧来 */
@media (min-width: 400px) and (max-width: 600px) { }

/* 新構文（単一式で表現） */
@media (400px <= width <= 600px) { }
```

**その他の比較演算子:**

```css
/* 幅が 768px より大きい（等号なし） */
@media (width > 768px) { }

/* 幅が 1024px 未満 */
@media (width < 1024px) { }
```

**コンテナクエリにも同様に適用可能:**

```css
@container (inline-size >= 600px) {
  .card {
    display: grid;
    grid-template-columns: 1fr 2fr;
  }
}
```

**PostCSS で旧ブラウザ向けに変換する場合:**

```bash
# postcss-media-query-parser プラグインが新構文を旧構文に変換
npm install postcss-preset-env
```

### ③ なぜ効果的か

- **可読性の向上:** 数学的な意味が直感的で、`min-width` / `max-width` の意味を暗記する必要がなくなる
- **境界値バグの排除:** `(min-width: 768px)` と `(max-width: 767px)` という1px差のハックが不要。`(width > 768px)` と `(width <= 768px)` で明確に分離できる
- **コードの短縮:** 範囲指定が `and` を使わず単一式で書ける

**ブラウザサポート（2026年時点）:** Chrome 104+、Firefox 63+、Safari 16.4+、Edge 104+ で対応済み。プロダクション環境で問題なく使用可能。

## 5. CSS Recently In All Browsers

**出典:** https://nerdy.dev/CSS-recently-in-all-browsers  
**記事日付:** 2026年4月26日（著者: Adam Argyle）

### ① 目的・問題意識

2025年10月〜2026年4月の間に全主要ブラウザ（Chrome・Firefox・Safari）でサポートされた CSS 機能をまとめた記事。「Interop 2026」プロジェクトの成果として多数の機能が Baseline に到達した。

### ② 各機能の詳細

#### 5-1. CSS アンカーポジショニング（Anchor Positioning）

**問題:** ツールチップ・ポップオーバーなどを特定要素に「紐付けて」配置するには JavaScript（位置計算 + `getBoundingClientRect`）が必要だった。

**解決策:**

```css
/* アンカー要素に名前を付ける */
.trigger {
  anchor-name: --my-anchor;
}

/* ターゲット要素をアンカーに紐付ける */
.tooltip {
  position: absolute;
  position-anchor: --my-anchor;
  position-area: top;           /* アンカーの上に配置 */
  position-try-fallbacks: flip-block; /* スペースがなければ下に反転 */
}
```

`position-area` は仮想的な 3×3 グリッドでアンカー周辺の配置位置を指定する：

```
top-left    | top center | top-right
left center | center     | right center
bottom-left | bottom     | bottom-right
```

**可視的な説明:** ツールチップがビューポート端に近づくと、`position-try-fallbacks: flip-block` により自動的に下側に反転する。JS なしでこれを実現できる。

---

#### 5-2. CSS `@scope`（セレクタのスコープ制限）

**問題:** グローバル CSS でのクラス名衝突、過度に詳細なセレクタ（`.header .nav .item.active`）、コンポーネント間のスタイルの意図しない干渉。

**解決策:**

```css
/* .feature コンポーネント内のスタイルのみに適用 */
@scope (.feature) {
  :scope {
    background: rebeccapurple;
    color: antiquewhite;
  }
  figure {
    background-color: white;
    border: 2px solid black;
    padding: 10px;
  }
}
```

**「ドーナツスコープ」（上限・下限を設定）:**

```css
/* .feature 内、ただし figure の子孫は除外 */
@scope (.feature) to (figure) {
  img {
    border: 5px solid black;
    background-color: goldenrod;
  }
}
```

`.feature` 内の `img` には適用されるが、`figure` 内の `img` には適用されない（ドーナツの穴にあたる部分）。

**重要な注意:** `@scope` はセレクタの到達範囲を制限するが、CSS の継承（`color` などの親から子への伝播）は止まらない。

---

#### 5-3. `shape()` 関数と `xywh()` / `rect()`

**問題:** `clip-path: polygon()` は SVG の絶対ピクセル座標に縛られ、レスポンシブデザインで使いにくかった。

**`shape()` — パスコマンドを CSS 単位で記述:**

```css
.hero {
  clip-path: shape(
    from 0% 0%,
    line to 100% 0%,
    line to 100% 80%,
    curve to 50% 100% via 75% 90%,  /* ベジェ曲線 */
    line to 0% 80%,
    close
  );
}
```

**`xywh()` — X/Y 座標と幅/高さで矩形クリップ:**

```css
.card {
  clip-path: xywh(0 5px 100% 75% round 15% 0);
  /* x=0, y=5px, width=100%, height=75%, 角丸=15% */
}
```

**`rect()` — 四辺からの距離で矩形クリップ:**

```css
.image {
  clip-path: rect(5px 5px 160px 145px round 20%);
  /* top=5px, right=5px, bottom=160px, left=145px, 角丸=20% */
}
```

---

#### 5-4. `view-transition-class` と JS View Transition Types

**`view-transition-class`（複数要素への一括アニメーション適用）:**

```css
/* 各カードに一意の view-transition-name が必要 */
#card1 { view-transition-name: card-1; }
#card2 { view-transition-name: card-2; }
#card3 { view-transition-name: card-3; }

/* クラスを共有して一つのルールで全カードに適用 */
.card { view-transition-class: card; }

::view-transition-group(.card) {
  animation-duration: 0.5s;
  animation-timing-function: ease-in-out;
}
```

**JS View Transition Types（SPA での前後ナビゲーション方向制御）:**

```css
/* CSS: ナビゲーション方向ごとに異なるアニメーション */
html:active-view-transition-type(forwards) {
  &::view-transition-old(root) { animation-name: slide-out-to-left; }
  &::view-transition-new(root) { animation-name: slide-in-from-right; }
}

html:active-view-transition-type(backwards) {
  &::view-transition-old(root) { animation-name: slide-out-to-right; }
  &::view-transition-new(root) { animation-name: slide-in-from-left; }
}
```

```javascript
// JS: トランジション開始時にタイプを指定
const direction = isGoingForward ? 'forwards' : 'backwards';
document.startViewTransition({
  update: updateTheDOMSomehow,
  types: [direction],
});
```

**クロスドキュメント（MPA）でのビュートランジション:**

```css
/* 両ページに記述 */
@view-transition {
  navigation: auto;
}
```

#### 5-5. 相対的なタイポグラフィ単位（rcap / rch / rex / ric）

新しい相対単位がルートフォントに基づく絶対的なサイズ指定を可能にする：

| 単位 | 意味 |
|---|---|
| `rcap` | ルートフォントの大文字高さ（cap-height） |
| `rch` | ルートフォントの `ch`（`0` の文字幅） |
| `rex` | ルートフォントの `ex`（小文字高さ） |
| `ric` | ルートフォントの `ic`（CJK 文字幅） |

```css
/* フォントサイズが変わっても一貫したタイポグラフィ比率を維持 */
.icon {
  width: 1rcap;
  height: 1rcap;
  /* 常にルートフォントの大文字と同じ高さになる */
}
```

### ③ なぜ効果的か

Interop 2026 の成果として、これらの機能が「すべてのブラウザで使える」状態になったことが重要。ポリフィルや `@supports` フォールバックなしに本番コードで利用できるため、CSS だけで解決できる問題が大幅に増えた。特にアンカーポジショニングと `@scope` は、これまで JS やクラス命名規則（BEM など）で対処していたユースケースをネイティブ CSS で置き換えられる。
