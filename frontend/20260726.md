## 1. CSS Mixins & Functions — Edge も実装に着手

**関連記事**: CSS Custom Functions and Mixins Module Level 1 / MDN "CSS custom functions and mixins" ほか
**URL**: [https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Custom_functions_and_mixins](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Custom_functions_and_mixins) / [https://drafts.csswg.org/css-mixins/](https://drafts.csswg.org/css-mixins/)

### ① 目的・問題意識

これまで「値の計算を再利用したい」「スタイルのまとまりをテンプレート化したい」といったニーズは、Sass/Less などの CSS プリプロセッサの `@mixin` / `@function` に頼るしかなかった。ビルドステップを挟まずにネイティブ CSS だけで同様のことを実現したいという要求から、CSS Working Group は **CSS Custom Functions and Mixins Module Level 1** を策定した。

- `@function` は「単一の値を返す」関数（Sass の `@function` 相当）
- `@mixin` + `@apply` は「複数のプロパティ宣言をまとめて適用する」仕組み（Sass の `@mixin` + `@include` 相当）

Chrome では `@function` が Chrome 139 で先行実装され、`@mixin` も Chrome Canary で実験的に着手済み。Issue #749 では **Microsoft Edge（Chromium ベース）もこの実装に追随し始めた**ことが取り上げられている。Firefox / Safari は未対応（2026年7月時点）で、progressive enhancement や `@supports` と組み合わせた利用が推奨される。

### ② 具体的なコード・技術詳細

#### `@function` — 単一の値を返すカスタム関数

```css
/* px を rem に変換するカスタム関数 */
@function --px-to-rem(--px type(length)) {
  result: calc(var(--px) / 16 * 1rem);
}

h1 {
  font-size: --px-to-rem(32px);
}
```

- `@function` ブロック内で引数の型（`type(length)` など）を指定できる
- `result:` で返す値を宣言する
- 呼び出し側は `<dashed-function>` 構文（`--px-to-rem(32px)` のようにカスタムプロパティ名の末尾に `()` を付けた形）を使う
- 内部で `calc()`、`if()`、`@media` などの条件分岐を組み合わせられるため、単なる値の別名以上の「ロジックを持った関数」を書ける

#### `@mixin` + `@apply` — 複数プロパティをまとめて適用

```css
/* ボタンの共通スタイルをまとめた mixin */
@mixin --button (--face, --text, --radius) {
  background-color: var(--face);
  color: var(--text);
  border-radius: var(--radius);
}

.btn {
  @apply --button(rebeccapurple, white, 1rem);
}
```

```css
/* スクリーンリーダー専用テキストの定番パターンを mixin 化 */
@mixin --sr-text {
  position: absolute;
  left: -10000px;
  top: auto;
  width: 1px;
  height: 1px;
  overflow: hidden;
}

header a:first-child {
  @apply --sr-text;
}
```

- `@mixin <名前> (<引数リスト>)` で定義し、`@apply <名前>(<引数>)` を任意のルールセット内にネストして呼び出す
- `@function` が「1つの値」しか返せないのに対し、`@mixin` は「複数のプロパティ宣言全体」を差し込める点が異なる
- 2026年7月時点でネイティブ実装は Chromium 系ブラウザでの実験段階（Chrome Canary で先行着手、Edge も追随開始）。Firefox / Safari は未対応

### ③ なぜそれが効果的か

- **ビルドレス化**: Sass/Less のようなプリプロセッサ・ビルドステップなしで、値計算やスタイルテンプレートの再利用が可能になる
- **保守性**: 「ボタンの角丸・配色パターン」のような繰り返し記述をコンポーネント単位で一元管理でき、変更箇所が1か所で済む
- **ロジックの表現力向上**: `@function` 内で `if()` や `calc()` と組み合わせることで、単なる変数以上の「計算されたデザイントークン」を表現できる
- **段階的導入が可能**: `@supports` でラップすれば、未対応ブラウザ向けのフォールバックと共存させながら先行導入できる

## 2. Safari MCP Server — AI エージェントがブラウザを直接デバッグできる仕組み

**記事タイトル**: Introducing the Safari MCP server for web developers
**URL**: [https://webkit.org/blog/18136/introducing-the-safari-mcp-server-for-web-developers/](https://webkit.org/blog/18136/introducing-the-safari-mcp-server-for-web-developers/)

### ① 目的・問題意識

これまで AI コーディングエージェント（Claude Code など）は、書いたコードが実際のブラウザでどう描画されるか、コンソールにエラーが出ていないか、ネットワークリクエストがどう飛んでいるかを**自分では確認できず**、開発者が手動でブラウザを確認して結果をエージェントに伝え返す必要があった。

WebKit チームはこの「エージェントとブラウザの間のフィードバックループの欠如」を解決するため、**Model Context Protocol (MCP) サーバーとして Safari を直接操作・観測できる仕組み**を導入した。Safari 27 beta / Safari Technology Preview 247 で提供される。

### ② 具体的な技術詳細

#### 前提条件・セットアップ手順

1. Safari 27 beta（または Safari Technology Preview 247）をインストール
2. `Safari > 設定 > Advanced` で **"Show features for web developers"** を有効化
3. `Safari > 設定 > Developer` で **"Allow remote automation and external agents"** を有効化

#### Claude Code への接続

```bash
claude mcp add safari-mcp -- "/usr/bin/safaridriver" --mcp
```

- `safaridriver` バイナリを MCP サーバーとして起動し、Claude Code から `safari-mcp` という名前で参照できるようにする一行コマンド
- 他の MCP 対応クライアントからも同様に接続可能な設計

#### 提供される機能（ツール群）

- 16〜17個のツールが公開されており、以下のようなブラウザ内部情報にエージェントがアクセスできる
  - DOM の内容
  - ネットワークリクエストの詳細
  - スクリーンショットの取得
  - コンソール出力（エラー・ログ）
- これによりエージェントは「ユーザーが実際に見ている画面」を自分の目で確認しながらデバッグできる

#### アーキテクチャ上の特徴

- Safari MCP Server は**開発者のローカルマシン上で完結**して動作し、それ自体は外部へのネットワーク通信を一切行わない（プライバシー・セキュリティ面での安心材料として明記されている）

### ③ なぜそれが効果的か

- **フィードバックループの自動化**: 「コードを書く → 人間がブラウザで確認 → 結果をエージェントに伝える」という手動の往復が不要になり、エージェントが自律的に「動くまで直す」というループを回せる
- **実ブラウザでの検証**: シミュレーションではなく実際の Safari エンジンでの描画結果・コンソール・ネットワークを見られるため、Safari 固有の不具合（レンダリング差異など）にもエージェントが自力で気づける
- **ローカル完結によるセキュリティ**: 外部通信を行わない設計のため、機密性の高い開発環境でも導入しやすい
- **MCP の標準化を活用**: 特定のエージェント専用機能ではなく MCP という共通プロトコルに乗せているため、Claude Code に限らず任意の MCP 対応クライアントから利用できる汎用性がある

## 3. CSS Anchor Positioning 入門

**記事タイトル**: Getting Started with Anchor Positioning
**URL**: [https://www.joshwcomeau.com/css/anchor-positioning/](https://www.joshwcomeau.com/css/anchor-positioning/)

### ① 目的・問題意識

ツールチップ、ドロップダウンメニュー、ポップオーバーなど「ある要素を別の要素（アンカー）にくっつけて表示し、画面端に近づいたら自動で反転（フリップ）させたい」という UI パターンは、従来 Floating UI や Popper.js のような JavaScript ライブラリに頼らなければ実装が困難だった。

**CSS Anchor Positioning** はこれを **JavaScript 不要・宣言的な CSS だけ**で実現するための新しいレイアウト機構。2026年7月時点で Chrome 125+、Edge 125+、Safari 26+、Firefox 147+ の主要ブラウザ全てで対応済み（ただし caniuse 上のサポート率はまだ約81%）。

### ② 具体的なコード・技術詳細

#### 基本：アンカーと対象要素の紐付け

```css
.anchor {
  anchor-name: --my-anchor;
}

.target {
  position: absolute;
  position-anchor: --my-anchor;
}
```

- `anchor-name` はアンカー側要素に付与する識別子。値は「ダッシュ付き識別子（dashed-ident）」で、`--` から始まる開発者定義の名前
- `position-anchor` を対象要素に指定することで、その要素の位置決めの基準点をアンカー要素にできる

#### アンカー関数によるエッジ指定

```css
#tooltip {
  position: absolute;
  position-anchor: --my-anchor;
  top: anchor(--my-anchor bottom);
  left: anchor(--my-anchor left);
}
```

- `anchor()` 関数で `top: anchor(bottom)` のように「アンカーのどの辺」を基準にするかを指定できる
- これにより JavaScript の `getBoundingClientRect()` を使った再計算なしで、要素同士の相対位置を CSS だけで表現できる

#### 画面端でのフリップ（position-try-fallbacks）

```css
#my-tooltip {
  position-anchor: --question-mark;
  position-area: top;
  position-try-fallbacks: flip-block;
}
```

- `position-area: top` でまず「アンカーの上」に配置を試みる
- `position-try-fallbacks: flip-block` を指定しておくと、ビューポート上端に収まらない場合にブラウザが自動的に配置を反転（下側に表示）してくれる
- `flip-block` / `flip-inline` という組み込みキーワードにより、これまで JS で個別に計算していた「衝突検出＋反転」ロジックが1行の CSS 宣言に置き換わる

#### フォールバック適用状態の検出（anchored container queries）

```css
@container anchored(fallback: flip-block) {
  .arrow {
    /* フリップが発生した場合だけ矢印の向きを反転 */
    transform: rotate(180deg);
  }
}
```

- `@container anchored(...)` を使うと、「どのフォールバックが実際に適用されたか」をコンテナクエリとして検知できる
- 例えば矢印付きツールチップで、上下どちらに表示されたかによって矢印の向きを CSS だけで切り替えられる

#### 想定される用途（デモ内で言及されている例）

- ビューポート端で自動的に反転するツールチップ
- トリガーボタンの直下に表示されるドロップダウンメニュー
- スクロール中もアンカーに追従し続けるポップオーバー
- クリック座標に表示されるコンテキストメニュー
- フォーム入力に追従するフローティングラベル

### ③ なぜそれが効果的か

- **JavaScript ライブラリからの脱却**: Floating UI / Popper.js が担っていた「位置計算・衝突検出・反転」のロジックがブラウザネイティブの CSS だけで完結し、バンドルサイズと実行時コストを削減できる
- **宣言的な保守性**: 「上に出す、はみ出したら下に出す」という意図を `position-area` + `position-try-fallbacks` という宣言的な記述で表現できるため、命令的な JS の再計算ロジックより読みやすく壊れにくい
- **レイアウトスラッシングの回避**: JS でのリサイズ・スクロール監視による再計算が不要になるため、レイアウトスラッシング（強制リフロー）によるパフォーマンス劣化を避けられる
- **ブラウザの標準機能としての一貫性**: 主要4ブラウザで実装が揃ったことで、ポリフィルや複数実装の差異を気にせず本番投入しやすい段階に到達している
