## 1. Next.js から TanStack Start への400ルート移行

### 目的・問題意識

Next.js App Router のビルド時間・デプロイ複雑性・ベンダー依存（Vercel最適化）に課題を感じた開発チームが、TanStack Start（v1.0、2026年3月 GA）への移行を実施した実例。Railway はこの移行を2つの PR で完了し、**ビルド時間を10分超から2分未満**へ削減した。

### 具体的な技術詳細

#### ルート変換

Next.js の `[bracket]` 記法を TanStack の `$prefix` 記法に変換。

```
# Next.js
pages/blog/[slug].tsx  →  src/routes/blog/$slug.tsx
app/users/[id]/page.tsx →  src/routes/users/$id.tsx
```

TanStack Start のルートは `createFileRoute()` で定義する：

```tsx
// Next.js (App Router)
// app/blog/[slug]/page.tsx
export default async function BlogPost({ params }: { params: { slug: string } }) {
  const post = await getPost(params.slug);
  return <article>{post.content}</article>;
}

// TanStack Start
// src/routes/blog/$slug.tsx
import { createFileRoute } from '@tanstack/react-router';

export const Route = createFileRoute('/blog/$slug')({
  loader: ({ params }) => getPost(params.slug),
  component: BlogPost,
});

function BlogPost() {
  const post = Route.useLoaderData();
  return <article>{post.content}</article>;
}
```

#### API ルート → Server Functions

Next.js の API ルートや Server Actions は `createServerFn()` に移行する：

```tsx
// Next.js API Route
// pages/api/hello.ts
export default function handler(req, res) {
  res.json({ message: 'Hello' });
}

// TanStack Start Server Function
import { createServerFn } from '@tanstack/react-start';

export const hello = createServerFn().handler(async () => {
  return { message: 'Hello' };
});
```

HTTP ハンドラを直接定義する場合：

```tsx
export const Route = createFileRoute('/api/hello')({
  server: {
    handlers: {
      GET: async () => {
        return Response.json({ message: 'Hello from TanStack Start' });
      },
    },
  },
});
```

#### ルートレイアウト

Next.js の `layout.tsx` は TanStack Start の `__root.tsx` に対応する：

```tsx
// Next.js: app/layout.tsx
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html>
      <body>{children}</body>
    </html>
  );
}

// TanStack Start: src/app/__root.tsx
import { createRootRoute, Outlet } from '@tanstack/react-router';

export const Route = createRootRoute({
  component: () => (
    <html>
      <body>
        <Outlet />
      </body>
    </html>
  ),
});
```

#### 段階的移行戦略（Railway の手法）

1. **PR 1**: Next.js 固有の import を除去・抽象化（フレームワーク非依存化）
2. **PR 2**: フレームワーク本体を TanStack Start に差し替え

この2ステップにより各 PR が独立してデプロイ可能な状態を維持する。

### なぜ効果的か

- **Vite ベース**のビルドにより HMR が高速で開発体験が向上
- **型安全なルーティング**: `Route.useLoaderData()` がローダーの返り値に完全に型付けされる
- **マルチターゲット**: Cloudflare、Netlify、AWS、Fly、Railway など任意のサーバーに同等にデプロイ可能
- **ベンダー非依存**: Vercel 最適化に依存しないため、インフラ選択の自由度が高い

## 2. React Canary: browser() API と parallel transitions

### 目的・問題意識

React Canary（v19.3.0-canary）で追加された `browser()` API は、**サーバーサイドレンダリング（SSR）時にブラウザ専用コンポーネントを除外**するための仕組み。これまで `typeof window !== 'undefined'` チェックやダイナミックインポートで対処していた SSR 非対応コンポーネントを、React のサスペンスと統合した形で宣言的に扱える。

### 具体的なコードと技術詳細

#### browser() API

```tsx
import { use } from 'react';
import { browser } from 'react-dom/browser';

// このコンポーネントはSSR中はSuspenseフォールバックに差し替えられる
function MapWidget() {
  use(browser()); // SSR中はここで止まる。ブラウザでは undefined を返す

  // ブラウザ専用ライブラリ（window, canvas, WebGL など）を安全に使用できる
  return <LeafletMap />;
}

// 使用側
function App() {
  return (
    <Suspense fallback={<div>Loading map...</div>}>
      <MapWidget />
    </Suspense>
  );
}
```

- SSR 中: `use(browser())` でレンダリングが中断 → 最も近い `<Suspense>` の fallback が使われる
- ブラウザ: `use(browser())` が `undefined` を返し、通常どおりレンダリング

#### parallel transitions（addTransitionType）

複数の非同期遷移が重なる場合に遷移タイプを識別し、アニメーションを適切に選択する仕組み：

```tsx
import { startTransition, addTransitionType } from 'react';

function NavigationButton({ direction, to }) {
  function handleClick() {
    startTransition(() => {
      addTransitionType(direction === 'forward' ? 'slide-left' : 'slide-right');
      navigate(to);
    });
  }

  return <button onClick={handleClick}>Go</button>;
}
```

```css
/* スライド方向に応じたView Transition アニメーション */
::view-transition-old(page):active-types(slide-left) {
  animation: slide-out-left 300ms ease-in;
}
::view-transition-new(page):active-types(slide-left) {
  animation: slide-in-right 300ms ease-out;
}
```

`addTransitionType` は複数のトランジションが同時発生した場合、すべてのタイプを収集・適用する（論理和）。

#### ViewTransition コンポーネント

```tsx
import { ViewTransition } from 'react';

function ProductCard({ product }) {
  return (
    <ViewTransition name={`product-${product.id}`}>
      <img src={product.image} alt={product.name} />
      <h2>{product.name}</h2>
    </ViewTransition>
  );
}
```

同じ `name` を持つ要素間で自動的にアニメーションが発生する。

### なぜ効果的か

- `browser()` は `typeof window` チェックより**意図が明確**で、React のデータフロー（Suspense）と統合されている
- `addTransitionType` により遷移方向・意味に応じたアニメーションを**宣言的に**実現でき、条件分岐コードが不要になる

## 3. Next.js の2件のRCE脆弱性（August 2026 Security Release）

### 目的・問題意識

2026年8月、Next.js チームは2件のクリティカルな RCE（Remote Code Execution）脆弱性を含むセキュリティリリースを公開した。いずれも認証なしに悪用可能な深刻な問題。

### 脆弱性の詳細

#### CVE-2026-75604: パストラバーサルによる RCE（CVSS 9.0）

- **概要**: Windows ファイルシステムでホストされている場合、パストラバーサルを通じて RCE が可能
- **対象**: Windows 環境でセルフホストされた Next.js アプリ
- **備考**: Vercel のマネージドランタイムは Linux を使用するため影響なし

#### AVIF 画像最適化 RCE（CVSS 9.5）

- **概要**: AVIF 画像処理の上流依存ライブラリに存在するクリティカルな脆弱性。画像最適化機能が有効な場合に悪用可能
- **発見経緯**: スケジュール外のリリースを前倒しするほど緊急性が高かった

### パッチバージョン

```
Next.js 15.5.24 以上
Next.js 16.3.3 以上
```

```bash
# アップグレード手順
npm install next@latest
# または
pnpm add next@latest
```

### なぜ重要か

- AVIF 最適化は `next.config.js` でデフォルト有効なため、**多くのアプリケーションが影響を受ける**
- 認証不要の RCE は攻撃難易度が低く、即時パッチ適用が推奨される

## 4. Ionic Framework 9 リリース

### 目的・問題意識

React アプリからモバイルアプリを構築するための UI フレームワーク Ionic が v9 をリリース。最大の要望だった **React Router 6 対応**と、ナビゲーション管理の内部刷新が主な目的。

### 具体的な技術詳細

#### React Router 6 サポート

v9 では Ionic がビュー保持・クリーンアップを自身で管理するよう設計を変更し、React Router の内部実装への依存を排除した：

```tsx
// Ionic 9 + React Router 6
import { IonApp, IonRouterOutlet } from '@ionic/react';
import { IonReactRouter } from '@ionic/react-router';
import { Route } from 'react-router-dom';

function App() {
  return (
    <IonApp>
      <IonReactRouter>
        <IonRouterOutlet>
          <Route exact path="/home" component={HomePage} />
          <Route path="/profile/:id" component={ProfilePage} />
        </IonRouterOutlet>
      </IonReactRouter>
    </IonApp>
  );
}
```

パラメータ付きルートでの「戻るスワイプ」バグが修正された。

#### リッチな Select オプション

```tsx
import { IonSelect, IonSelectOption } from '@ionic/react';

function AvatarSelect() {
  return (
    <IonSelect>
      <IonSelectOption value="alice">
        <img src="/avatars/alice.png" alt="Alice" slot="start" />
        Alice Smith
        <small slot="end">Admin</small>
      </IonSelectOption>
      <IonSelectOption value="bob">
        <img src="/avatars/bob.png" alt="Bob" slot="start" />
        Bob Jones
        <small slot="end">Member</small>
      </IonSelectOption>
    </IonSelect>
  );
}
```

#### マイグレーション CLI

```bash
npx @ionic/migrate
```

v8 → v9 の破壊的変更（Angular の import パス更新、React Router コンポーネント→エレメント書き換えなど）を自動化する。

#### 要件変更

- React 18+ が必須（React 17 以下は非サポート）

### なぜ効果的か

- React Router 6 への依存が公式化され、長期的なメンテナンス安定性が向上
- マイグレーション CLI によりアップグレードコストが大幅に削減

## 5. TanStack Query 注目アップデート

### 目的・問題意識

TanStack Query v5 は React のデータフェッチ・キャッシュ管理ライブラリの最新メジャー版。2026年中のアップデートで特に注目された機能強化を取り上げる。

### 具体的な技術詳細

#### Suspense 対応フック（useSuspenseQuery）

```tsx
import { useSuspenseQuery } from '@tanstack/react-query';

function UserProfile({ userId }: { userId: string }) {
  // Suspenseと統合 — loading/error状態チェック不要
  const { data: user } = useSuspenseQuery({
    queryKey: ['user', userId],
    queryFn: () => fetchUser(userId),
  });

  return <div>{user.name}</div>;
}

// 使用側
function App() {
  return (
    <Suspense fallback={<Spinner />}>
      <ErrorBoundary fallback={<Error />}>
        <UserProfile userId="123" />
      </ErrorBoundary>
    </Suspense>
  );
}
```

#### 楽観的更新の簡略化（useMutation + variables）

```tsx
import { useMutation, useQueryClient } from '@tanstack/react-query';

function TodoItem({ todo }) {
  const queryClient = useQueryClient();

  const { mutate, isPending, variables } = useMutation({
    mutationFn: (newText: string) => updateTodo(todo.id, newText),
    onSettled: () => queryClient.invalidateQueries({ queryKey: ['todos'] }),
  });

  // isPending中は variables（楽観的な値）を表示
  const displayText = isPending ? variables : todo.text;

  return (
    <li style={{ opacity: isPending ? 0.5 : 1 }}>
      {displayText}
    </li>
  );
}
```

#### useMutationState で複数ミューテーションの状態監視

```tsx
import { useMutationState } from '@tanstack/react-query';

function UploadProgressBar() {
  const mutations = useMutationState({
    filters: { mutationKey: ['upload'], status: 'pending' },
    select: (mutation) => mutation.state.variables,
  });

  return (
    <div>
      {mutations.length > 0 && (
        <p>{mutations.length} 件アップロード中...</p>
      )}
    </div>
  );
}
```

#### 実験的 Persister（永続化）

```tsx
import { experimental_createPersister } from '@tanstack/query-persist-client-core';
import { createSyncStoragePersister } from '@tanstack/query-sync-storage-persister';

const persister = experimental_createPersister({
  storage: createSyncStoragePersister({ storage: localStorage }),
  maxAge: 1000 * 60 * 60 * 24, // 24時間
});

const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      persister,
    },
  },
});
```

### なぜ効果的か

- `useSuspenseQuery` により `isLoading`/`isError` の条件分岐コードが不要になり、コードが簡潔になる
- `variables` を利用した楽観的更新は手動キャッシュ操作を排除し、実装ミスを減らす
- `useMutationState` によりコンポーネント横断でのミューテーション状態管理が容易になる
