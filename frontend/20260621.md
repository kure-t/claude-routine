## 1. PolyCSS — CSS 3D Engine for the DOM

**リンク**: https://polycss.com / https://github.com/LayoutitStudio/polycss

### ① 目的・問題意識

WebGL や `<canvas>` を使わずに、CSS の `matrix3d()` トランスフォームだけで 3D ポリゴンメッシュを DOM 上にレンダリングするライブラリ。ポリゴンの1枚ずつが本物の HTML 要素として生成されるため、クリックイベント・CSS クラス・CSS トランジションなどを普通の DOM 操作と同じ感覚で扱える点が従来の WebGL との大きな違い。

### ② 具体的な技術詳細

#### サポートフォーマット

| フォーマット | 説明 |
|---|---|
| OBJ + MTL | `map_Kd` テクスチャ、UV 座標対応 |
| STL | バイナリ Magics フェイスカラー含む |
| glTF / GLB | 埋め込み画像・`TEXCOORD_0` 対応 |
| MagicaVoxel `.vox` | ボクセル形式 |
| プリミティブ生成 | box, plane, ring, sphere, torus, cylinder, cone, プラトン立体 |

#### CSS レンダリング戦略

PolyCSS は1ポリゴンに対して最も安価な CSS プリミティブを自動選択する:

| タグ | 用途 |
|---|---|
| `<b>` | 矩形面（`background: currentColor` で塗りつぶし）|
| `<u>` | 三角形（`corner-shape` または `border-width` フォールバック）|
| `<i>` | 一般ポリゴン（`border-shape: polygon(...)` ）|
| `<s>` | テクスチャ付き面（アトラスにパック）|

各ポリゴンは `transform: matrix3d(...)` で3D空間に配置される:

```css
/* 三角ポリゴンの例 */
.poly-face {
  transform: matrix3d(
    m00, m01, m02, m03,
    m10, m11, m12, m13,
    m20, m21, m22, m23,
    m30, m31, m32, m33
  );
}
```

UV テクスチャ付きポリゴンはアトラススプライトに集約され、`background-position` で切り出す。

#### React コンポーネント API

```jsx
import { PolyCamera, PolyScene, PolyOrbitControls, PolyMesh } from '@layoutit/polycss-react';

function App() {
  return (
    <PolyCamera rotX={65} rotY={45}>
      <PolyScene textureLighting="dynamic">
        <PolyOrbitControls drag wheel />
        <PolyMesh src="/model.obj" mtl="/model.mtl" />
      </PolyScene>
    </PolyCamera>
  );
}
```

#### バニラ JS (カスタム要素) API

```html
<poly-camera rot-x="65" rot-y="45">
  <poly-scene texture-lighting="dynamic">
    <poly-orbit-controls drag wheel></poly-orbit-controls>
    <poly-mesh src="/model.glb"></poly-mesh>
  </poly-scene>
</poly-camera>
```

#### カメラ種別

- `PolyCamera` — 正投影（デフォルト）
- `PolyPerspectiveCamera` — 透視投影

#### コントロール種別

- `PolyOrbitControls` — ドラッグ回転・Shift+ドラッグでパン・ホイールズーム
- `PolyMapControls` — マップスタイルのパン操作
- `PolyFirstPersonControls` — キーボード＋ポインタルック
- `PolyTransformControls` — 平行移動・回転ギズモ

#### ポリゴンデータモデル

```javascript

}
```

#### スナップショットエクスポート

```javascript

```

### ③ なぜ効果的か

- ブラウザのコンポジターが `matrix3d` 計算を担当するため、JavaScript でのレンダリングループが不要
- 各ポリゴンが普通の DOM 要素のため、CSS アニメーション・トランジション・イベントハンドラーをそのまま使える
- WebGL コンテキストのオーバーヘッドがない（シンプルなシーンでは軽量）
- パフォーマンスはマウントされるポリゴン数とテクスチャアトラス面積で決まり、シンプルな面は安価なプリミティブで処理される

## 2. CSS is DOOMed — Rendering DOOM in 3D with CSS

**リンク**: https://nielsleenheer.com/articles/2026/css-is-doomed-rendering-doom-in-3d-with-css/
**GitHub**: https://github.com/NielsLeenheer/cssDOOM

### ① 目的・問題意識

DOOM（1993年の FPS ゲーム）を Canvas や WebGL を一切使わず、CSS の 3D トランスフォームだけでブラウザ上で動作させた実験的プロジェクト。「モダン CSS がどこまで強力か」を限界まで探ることが動機。すべての壁・床・スプライト・エフェクトが `<div>` 要素として3D空間に配置される。

### ② 具体的な技術詳細

#### ジオメトリパイプライン

DOOM の WAD ファイルから linedefs・sidedefs・sectors を抽出し、各壁に CSS カスタムプロパティとして頂点座標を渡す:

```css
/* 壁要素のカスタムプロパティ */
.wall {
  --start-x: 2560;
  --start-y: -2112;
  --end-x: 2560;
  --end-y: -2496;
  --floor-z: 32;
  --ceiling-z: 88;

  /* CSS で幅と角度を計算 */
  width: calc(hypot(var(--delta-x), var(--delta-y)) * 1px);
  height: calc((var(--ceiling-z) - var(--floor-z)) * 1px);
  transform: translate3d(
      calc(var(--start-x) * 1px),
      calc(var(--floor-z) * -1px),
      calc(var(--start-y) * 1px)
    )
    rotateY(atan2(var(--delta-y), var(--delta-x)));
}
```

#### 座標系変換

DOOM の座標系（2D 俯瞰・Y 軸が北方向）を CSS 3D 座標系（Y軸が垂直・Z軸が視点方向）に変換:

```css
/* DOOM (x, y, z) → CSS translate3d(x, -z, -y) */
transform: translate3d(
  calc(var(--x) * 1px),
  calc(var(--z) * -1px),
  calc(var(--y) * 1px)
);
```

#### カメラ実装

カメラを動かすのではなく、シーン全体をプレイヤーの逆方向に移動させる:

```css
#scene {
  transform-style: preserve-3d;
  transform:
    rotateY(calc(var(--player-angle) * -1rad))
    translate3d(
      calc(var(--player-x) * -1px),
      calc(var(--player-z) *  1px),
      calc(var(--player-y) *  1px)
    );
}
```

JavaScript はフレームごとに4つのカスタムプロパティだけを更新する:

```javascript
scene.style.setProperty('--player-x', player.x);
scene.style.setProperty('--player-y', player.y);
scene.style.setProperty('--player-z', player.z);
scene.style.setProperty('--player-angle', player.angle);
```

#### 使用 CSS 機能一覧

| CSS 機能 | 用途 |
|---|---|
| `transform-style: preserve-3d` | DOM 階層全体で 3D 関係を維持 |
| `@property` + `@keyframes` | カスタムプロパティのアニメーション（照明のちらつきなど）|
| `clip-path: polygon()` / `shape()` | 不規則な床・天井形状の作成 |
| `steps()` タイミング関数 | スプライトフレームアニメーション |
| `filter: brightness()` | セクターごとの照明継承 |
| `rotateY()` 継承角度 | スプライトが常にカメラに向く（ビルボード）|
| CSS `transition` | ドア・リフトのアニメーション（ゲームループ不要）|
| SVG フィルター (`feColorMatrix`, `feTurbulence`) | スペクター（透明モンスター）の不可視エフェクト |
| CSS アンカーポジショニング | 武器 HUD を画面端に固定 |
| `hypot()`, `atan2()`, `sin()`, `cos()` | 壁の幅・角度の計算 |

#### 照明のアニメーション例（@property）

```css
@property --light-level {
  syntax: '<number>';
  inherits: true;
  initial-value: 1;
}

@keyframes flicker {
  0%   { --light-level: 0.8; }
  50%  { --light-level: 1.0; }
  100% { --light-level: 0.9; }
}

.sector {
  animation: flicker 0.3s steps(1) infinite;
  filter: brightness(var(--light-level));
}
```

#### 入力システム

```javascript
// Pointer Lock API でマウスの生デルタ値を取得
document.addEventListener('pointerlockchange', () => {
  if (document.pointerLockElement === canvas) {
    document.addEventListener('mousemove', (e) => {
      player.turnDelta += e.movementX; // レート制限をバイパス
    });
  }
});
```

マウス・キーボード・タッチ・ゲームパッドを単一ストリームに統一して処理。

#### フラスタムカリング（視錐台カリング）

```javascript
// JavaScript ベースのカリング
function isInViewFrustum(wall) {
  const angle = Math.atan2(wall.midY - player.y, wall.midX - player.x);
  const diff = normalizeAngle(angle - player.angle);
  return Math.abs(diff) < HALF_FOV + MARGIN;
}

walls.forEach(wall => {
  wall.element.style.visibility = isInViewFrustum(wall) ? 'visible' : 'hidden';
});
```

CSS `if()` のサポート後は純粋な CSS カリングに移行予定。

### ③ なぜ効果的か

- ゲームロジック・物理演算・衝突判定を JavaScript が担当し、**視覚的レンダリングをすべて CSS が担当**するという明確な関心の分離
- JavaScript はごく少数の CSS カスタムプロパティを更新するだけで、ブラウザのコンポジターが変換計算とレンダリングを担当するため効率的
- `@property` により数値型のカスタムプロパティがアニメーション可能になり、照明などの演出を CSS アニメーションとして実装できる
- CSS の進化（`hypot()`、`atan2()`、`clip-path: shape()`、アンカーポジショニングなど）が揃ったことで、このような複雑なレンダリングが初めて実現可能になった

#### 既知のブラウザ制限

| ブラウザ | 問題 |
|---|---|
| Safari | View Transitions が `preserve-3d` を2Dに平坦化する |
| Chromium | コンポジターの負荷が高いときにテクスチャが消える |
| 全般 | `background-image` をカスタムプロパティで参照すると再ラスタライズが多発（インラインスタイル必須）|
| Safari | `@starting-style` が 3D 要素で繰り返しトリガーされる |
