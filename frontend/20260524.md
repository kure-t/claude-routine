## 1. Google I/O 2026: Chrome と「エージェント時代のウェブ」

**記事URL:** https://developer.chrome.com/blog/chrome-at-io26

### ① 目的・問題意識

AI エージェントが急速に普及する中、従来の Web はエージェントが構造を認識しにくい。AI がフォームを操作したり、サイトの機能をプログラム的に呼び出したりするには、開発者が明示的に「エージェント向けインターフェース」を提供する必要がある。また、3D Canvas の世界とアクセシビリティ・検索性は両立が難しかった。Google I/O 2026 では、これらを解決する複数の新機能が発表された。

---

### A. WebMCP（Web Model Context Protocol）

**② 具体的な技術詳細**

WebMCP は、Web サイトの機能（JavaScript 関数や HTML フォーム）を AI エージェントが呼び出せるツールとして公開するためのオープン標準（W3C ドラフト）。ブラウザに `navigator.modelContext` という API が追加される。

**Declarative API（HTML フォームに属性を付与するだけ）**

```html
<!-- 既存フォームに toolname / tooldescription を追加するだけ -->
<form
  toolname="search_products"
  tooldescription="商品を検索します"
  action="/search"
>
  <input type="text" name="query" placeholder="キーワード">
  <button type="submit">検索</button>
</form>
```

`toolautosubmit` 属性を追加すると、エージェントがフィールドを埋めた後に自動でフォームを送信できる。

```html
<!-- より詳細な例（サポートリクエストフォーム） -->
<form
  toolname="supportRequestTool"
  tooldescription="サポートリクエストを送信します"
  action="/submit"
>
  <input type="text" name="firstName">
  <input type="text" name="lastName">

  <!-- toolparamtitle / toolparamdescription で各フィールドの意味を説明 -->
  <select
    name="supportType"
    toolparamtitle="サポート種別"
    tooldescription="リクエストのルーティング先チームを決定します"
  >
    <option value="returns">購入品を返品したい</option>
    <option value="shipping">荷物の配送状況を確認したい</option>
    <option value="website">サイトの使い方を教えてほしい</option>
  </select>

  <button type="submit">送信</button>
</form>
```

**Imperative API（JavaScript による動的登録）**

```javascript
if ('modelContext' in navigator) {
  navigator.modelContext.registerTool({
    name: 'search_inventory',
    description: '商品在庫をフィルタ付きで検索します',
    inputSchema: {
      type: 'object',
      properties: {
        query: {
          type: 'string',
          description: '検索キーワード'
        },
        category: {
          type: 'string',
          description: '商品カテゴリ'
        },
        maxPrice: {
          type: 'number',
          description: '上限価格（USD）'
        },
        inStock: {
          type: 'boolean',
          description: '在庫ありのみ表示'
        }
      },
      required: ['query']
    },
    annotations: { readOnlyHint: true },
    async execute(input) {
      const res = await fetch(`/api/search?q=${encodeURIComponent(input.query)}`);
      return await res.json();
    }
  });
}
```

- **Origin Trial**: Chrome 149 で公開オリジントライアル開始
- Gemini in Chrome が WebMCP APIs をサポート予定

**③ なぜ効果的か**

- 既存の HTML フォームに属性を 2 つ追加するだけでエージェント対応が完了（Declarative API）
- エージェントが正確に機能を理解して呼び出せるため、スクレイピング頼りの不安定な自動化が不要になる
- ブラウザが JSON Schema を自動生成するため、バックエンドの変更が不要

### B. HTML-in-Canvas API

**② 具体的な技術詳細**

DOM 要素を WebGL / WebGPU テクスチャとして直接 Canvas に描画する API。3D シーン内に本物の HTML が埋め込まれる。Origin Trial（Chrome 146+）で試験提供中。

**3 つのコアプリミティブ:**

1. `layoutsubtree` 属性: `<canvas>` 内の子要素を「レイアウト対象」としてマーク
2. `texElementImage2D()` メソッド: 要素の描画をテクスチャとしてアップロード
3. `paint` イベント: 子要素が変化したときに発火

```html
<!-- layoutsubtree 属性で canvas 子要素をレイアウト対象にする -->
<canvas id="scene" layoutsubtree>
  <div id="ui-card" class="product-card">
    <h2>商品名</h2>
    <p>価格: ¥1,980</p>
    <button>カートに追加</button>
  </div>
</canvas>
```

```javascript
const canvas = document.getElementById('scene');
const gl = canvas.getContext('webgl2');
const uiCard = document.getElementById('ui-card');
const texture = gl.createTexture();

// DOM 要素が変化するたびにテクスチャを更新
canvas.onpaint = () => {
  gl.bindTexture(gl.TEXTURE_2D, texture);
  // DOM 要素をそのままテクスチャとして渡す
  gl.texElementImage2D(
    gl.TEXTURE_2D,
    0,               // mipmap level
    gl.RGBA,
    gl.RGBA,
    gl.UNSIGNED_BYTE,
    uiCard           // HTML 要素を直接指定
  );
  // ここで通常の WebGL 描画ループを実行
  render();
};
```

**③ なぜ効果的か**

- スクリーンショットではなくブラウザ本来のレンダリングパイプラインを使うため、CSS アニメーション・フォーム要素・フォント・SVG がそのまま動作
- アクセシビリティツリーが自動的に正しく構築される
- ページ内検索（Ctrl+F）、テキスト選択、ブラウザ翻訳がそのまま機能
- 従来の Canvas 描画で必要だった「アクセシビリティ用の並列 DOM 構造」が不要

### C. Chrome DevTools for Agents

AI エージェントが Chrome DevTools の機能（コンソールログ、ネットワーク通信、アクセシビリティツリー）に直接アクセスできるようになる。エージェントによるコード検証・バグ修正・品質監査の自動化を支援。

### D. Modern Web Guidance

Baseline に連動した「エキスパート監修スキル集」。コーディングエージェントに対して 100 以上のユースケースをカバーするベストプラクティスをリアルタイムで提供。開発者は「何を作るか」に集中でき、適切な機能とフォールバックはエージェントが自動的に判断する。

## 2. Tailwind からの脱却と CSS 設計の学び直し

**記事URL:** https://jvns.ca/blog/2026/05/15/moving-away-from-tailwind--and-learning-to-structure-my-css-/
**著者:** Julia Evans

### ① 目的・問題意識

Tailwind は CSS の制約とシステムを提供することで生産性を高めるが、「変わったことをやりたいとき」の限界がある。また、CSS の専門性を低く見る文化への懸念もある。Julia Evans は複数のサイトを Tailwind からバニラ CSS に移行し、Tailwind が提供していた「システム」をどう自前で再現するかを整理した。

背景として、2026年1月に Tailwind Labs が技術スタッフの75%を解雇（売上が80%減少）という事件も影響。

### ② 具体的な技術詳細

**CSS リセット（Preflight の再現）**

Tailwind の preflight（ブラウザデフォルトを正規化するリセットCSS）をそのままコピーして利用。

```css
/* reset.css の例 */
*,
::before,
::after {
  box-sizing: border-box; /* Tailwind が全要素に適用 */
}

html {
  line-height: 1.5; /* Tailwind の preflight から */
  -webkit-text-size-adjust: 100%;
  tab-size: 4;
}

body {
  margin: 0;
  font-family: inherit;
  line-height: inherit;
}
```

**CSS @import でファイルを分割管理**

```css
/* main.css */
@import "reset.css";
@import "typography.css";
@import "colors.css";
@import "layout.css";
@import "components.css";
```

CSS の `@import` がネイティブで使えるため、ビルドツール不要で関心事ごとにファイルを分割できる。

**カラーパレットを CSS カスタムプロパティで管理**

Tailwind のカラーパレットが恋しくなったため、CSS 変数で同等のシステムを構築:

```css
/* colors.css */
:root {
  /* プライマリカラー */
  --color-blue-50: #eff6ff;
  --color-blue-100: #dbeafe;
  --color-blue-500: #3b82f6;
  --color-blue-700: #1d4ed8;
  --color-blue-900: #1e3a8a;

  /* グレースケール */
  --color-gray-100: #f3f4f6;
  --color-gray-500: #6b7280;
  --color-gray-900: #111827;

  /* セマンティックカラー */
  --color-text-primary: var(--color-gray-900);
  --color-text-secondary: var(--color-gray-500);
  --color-bg-primary: white;
  --color-bg-secondary: var(--color-gray-100);
  --color-accent: var(--color-blue-500);
}
```

**レイアウト管理**

外側のコンテナコンポーネントがスペーシングを管理する責任を持つアプローチを採用。Tailwind では難しかった柔軟な CSS Grid レイアウトをブレークポイント少なめで実現:

```css
/* layout.css */
.container {
  max-width: 1200px;
  margin: 0 auto;
  padding: 0 1rem;
}

/* CSS Grid を使ったレスポンシブレイアウト（ブレークポイント不要） */
.auto-grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(300px, 100%), 1fr));
  gap: 1.5rem;
}
```

**③ なぜ効果的か**

- CSS ネイティブの `@import` や `@layer` を使うことで、Tailwind 依存なしに同等の設計システムを構築できる
- CSS カスタムプロパティによるカラーシステムは、ダークモード対応も容易
- レイアウトの責任を明確に分離することで、コンポーネントのスペーシングが予測可能になる
- Tailwind のよい部分（制約・システム）だけを取り出し、悪い部分（HTML の肥大化・カスタマイズの壁）を回避できる

## 3. クロスドキュメント View Transitions の落とし穴

**記事URL:** https://css-tricks.com/cross-document-view-transitions-part-1/

### ① 目的・問題意識

CSS だけでマルチページアプリ（MPA）にページ遷移アニメーションを付けられる「クロスドキュメント View Transitions」は強力だが、ドキュメントが少なく、静かに失敗するケースが多い。古いチュートリアルの情報や、ブラウザ実装の細かな挙動を知らないと、なぜ動かないか分からない。

### ② 具体的な技術詳細

**基本的な有効化（現行の正しい書き方）**

```css
/* 両ページの CSS に記述する必要がある */
@view-transition {
  navigation: auto;
}
```

**落とし穴 1: 廃止されたメタタグ（最も多い「動かない」原因）**

古いチュートリアルにある以下の記述は Chrome 126 以降では無効。エラーも警告も出ない。

```html
<!-- ❌ 廃止済み（Chrome 126+ では何も起きない） -->
<meta name="view-transition" content="same-origin">
```

```css
/* ✅ 正しい書き方 */
@view-transition {
  navigation: auto;
}
```

**落とし穴 2: 4秒タイムアウト**

ナビゲーション開始から 4 秒以内に新ページが描画されないとトランジションがキャンセルされる（`TimeoutError` の DOMException）。サーバー応答 2 秒 + ページ描画 2.5 秒 = 合計 4.5 秒でアウト。

```javascript
// デバッグ用: トランジションがキャンセルされた理由を確認
window.addEventListener("pagereveal", (event) => {
  if (!event.viewTransition) {
    console.log("トランジションなし: ページが opt-in していないか、ブラウザがスキップ");
    return;
  }
  event.viewTransition.finished
    .then(() => console.log("トランジション完了 ✅"))
    .catch((err) => {
      console.error("トランジションキャンセル:", err.name, err.message);
      // TimeoutError が表示される
    });
});
```

**落とし穴 3: 画像の歪み**

ブラウザは要素を直接アニメーションするのではなく、新旧2つのスクリーンショットを取ってモーフィングする。アスペクト比が変わる場合（サムネイル 150×150 → ヒーロー画像 600×300）に引き伸ばし歪みが発生。

```css
/* ❌ 何もしない場合: 歪む */
.product-image {
  view-transition-name: product-hero;
}

/* ✅ 疑似要素に object-fit: cover を指定して歪みを防ぐ */
::view-transition-old(product-hero),
::view-transition-new(product-hero) {
  object-fit: cover;
  /* 旧ページと新ページで crop 位置を別々に制御 */
}

::view-transition-old(product-hero) {
  object-position: center;     /* サムネイルは中央クロップ */
}

::view-transition-new(product-hero) {
  object-position: top center; /* ヒーロー画像は上部アンカー */
}
```

**落とし穴 4: 両ページのオプトインが必要**

遷移元と遷移先の両方のページで `@view-transition { navigation: auto; }` が必要。片方だけでは動作しない。

**落とし穴 5: `navigation: auto` が反応しないケース**

ユーザーのクリックや「戻る」ボタン以外では発火しない:

```javascript
// ❌ これではトランジションが発動しない
window.location.href = "/somewhere"; // プログラムからの遷移
// ❌ 同様に NG
form.submit(); // POST フォームの送信
```

**アクセシビリティ対応**

```css
@media (prefers-reduced-motion: reduce) {
  ::view-transition-group(*),
  ::view-transition-old(*),
  ::view-transition-new(*) {
    animation: none !important;
  }
}
```

**完全な基本実装例**

```css
/* 両ページ共通 */
@view-transition {
  navigation: auto;
}

/* 共有要素（ヒーロー画像）の命名 */
.hero-image {
  view-transition-name: hero;
}

/* カスタムアニメーション */
@keyframes fade-in {
  from { opacity: 0; }
}

@keyframes slide-up {
  from { transform: translateY(20px); opacity: 0; }
}

::view-transition-new(root) {
  animation: 300ms ease fade-in;
}

.content-area {
  view-transition-name: content;
}

::view-transition-new(content) {
  animation: 300ms ease slide-up;
}

/* reduced-motion 対応 */
@media (prefers-reduced-motion: reduce) {
  ::view-transition-group(*),
  ::view-transition-old(*),
  ::view-transition-new(*) {
    animation: none !important;
  }
}
```

### ③ なぜ効果的か

- JavaScript なし、CSS だけで MPA に SPA のような遷移アニメーションを追加できる
- `view-transition-name` を一致させるだけで要素が「飛んで移動」するモーフアニメーションになる
- ブラウザ対応: Chromium 系 + Safari 18.2+（2026年時点）。Firefox は対応作業中

## 4. Firefox 151 の開発者向け新機能

**記事URL:** https://developer.mozilla.org/en-US/docs/Mozilla/Firefox/Releases/151
**リリース日:** 2026年5月19日

### ① 目的・問題意識

Firefox 151 は開発者向けに複数の重要な機能追加を行った。特に Web Serial API の追加により、ブラウザから直接マイコンを制御できる時代が来た。CSS コンテナスタイルクエリの範囲記法サポートにより、条件分岐の表現力も向上した。

### ② 具体的な技術詳細

**A. Web Serial API（デスクトップ版）**

マイコンやシリアルポートを持つハードウェアをブラウザから直接制御できる。

対応デバイス例: ESP32 / Raspberry Pi Pico / 3D プリンタ / CNC マシン / LEGO デバイス

```javascript
// 1. ポートを選択（ユーザーに選択ダイアログを表示）
const port = await navigator.serial.requestPort();

// 2. ポートをオープン
await port.open({ baudRate: 9600 });

// 3. データ送信
const writer = port.writable.getWriter();
const encoder = new TextEncoder();
await writer.write(encoder.encode("Hello, ESP32!\n"));
writer.releaseLock();

// 4. データ受信
const reader = port.readable.getReader();
const decoder = new TextDecoder();

try {
  while (true) {
    const { value, done } = await reader.read();
    if (done) break;
    console.log("受信:", decoder.decode(value));
  }
} finally {
  reader.releaseLock();
}

// 5. ポートをクローズ
await port.close();
```

特定の USB ベンダーIDでフィルタリング:

```javascript
// Adafruit のデバイスのみ表示
const port = await navigator.serial.requestPort({
  filters: [{ usbVendorId: 0x239A }]
});
```

注意: Firefox での利用には、ウェブサイトが合成された「サイト権限アドオン」をインストールする必要がある（WebMIDI と同様のアプローチ）。

**B. CSS コンテナスタイルクエリ 範囲記法**

カスタムプロパティの値を比較演算子（`>`、`<`、`>=`、`<=`）で比較できる。

```css
/* コンテナを定義 */
.card {
  container-type: inline-size;
  container-name: card;
  --lightness: 30%;
}

/* 範囲記法で条件分岐 */
@container style(--lightness < 50%) {
  .card-text {
    color: white; /* 暗い背景には白文字 */
  }
}

@container style(--lightness >= 50%) {
  .card-text {
    color: black; /* 明るい背景には黒文字 */
  }
}
```

CSS `if()` 関数との組み合わせ:

```css
.progress-bar {
  --progress: 80%;
  /* --progress が 75% を超えたら緑、そうでなければ青 */
  background: if(style(--progress > 75%): green; else: blue);
}
```

従来の書き方と比較:

```css
/* ❌ 従来: 値ごとに複数のブロックが必要 */
@container style(--progress: 25%) { .bar { background: red; } }
@container style(--progress: 50%) { .bar { background: orange; } }
@container style(--progress: 75%) { .bar { background: yellow; } }
@container style(--progress: 100%) { .bar { background: green; } }

/* ✅ 範囲記法: 1ブロックで済む */
@container style(--progress > 75%) {
  .bar { background: green; }
}
```

**C. プライバシー・ユーザー向け改善（開発者に影響するもの）**

- **フィンガープリント保護強化**: Standard ETP でデバイス情報の漏洩をより制限。開発者はフィンガープリントに頼った実装を見直す必要がある
- **ローカルネットワークアクセス制限**: Web サイトがローカルネットワークデバイスに接続するにはユーザー許可が必要に（全ユーザーへロールアウト）
- **Firefox Home の新デザイン**: 新タブページの UI が刷新

### ③ なぜ効果的か

- **Web Serial API**: ネイティブアプリ不要でハードウェアプロトタイピングが可能。Adafruit はこれを使ってブラウザから CircuitPython を書き込める体験を提供済み
- **CSS 範囲記法**: カスタムプロパティを使ったデザイントークンと組み合わせることで、数値ベースの条件分岐が CSS だけで書けるようになる。プログレスバー、テーマ切り替え、動的スタイルシステムに活用できる
