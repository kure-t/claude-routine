## 1. 12 個の CSS 機能が依存ライブラリを不要にする（メイン特集記事）

**記事タイトル**: 12 CSS features you can use today with no build step
**著者**: Flavio Copes
**URL**: [https://flaviocopes.com/modern-css-features/](https://flaviocopes.com/modern-css-features/)
**内容確認日（記事内記載）**: 2026年9月21日

### ① 目的・問題意識

長年、CSS だけでは実現できない機能（ネスティング、色の演算、親要素セレクタ、コンポーネント単位のスタイル分離など）を補うために、Sass・PostCSS・JavaScript ハックといったビルドステップや実行時のライブラリが必須だった。本記事は、ブラウザがネイティブでサポートするようになった CSS 機能を 12 個取り上げ、それぞれが「どのワークアラウンド（回避策・依存ライブラリ）を退役させられるか」という観点で整理し、素の `.css` ファイルに貼り付けられるスニペットとブラウザサポート状況を示している。

以下、記事から確認できた 11〜12 個のテクニックを個別に詳述する。

---

### 1.1 ネイティブ CSS ネスティング

**① 目的・問題意識**
Sass が導入される最大の理由がネスティングだった。子セレクタを親の中に書き、ビルドツールがフラットなセレクタに展開する、という工程をブラウザ自身が行えるようになった。

**② コード**

Before（フラットな CSS / Sass 相当）:
```css
.card { padding: 1rem; border: 1px solid #ddd; }
.card h2 { margin: 0; font-size: 1.25rem; }
.card a { color: royalblue; }
```

After（ネイティブネスティング）:
```css
.card {
  padding: 1rem;
  border: 1px solid #ddd;

  h2 {
    margin: 0;
    font-size: 1.25rem;
  }

  a {
    color: royalblue;
  }

  &:hover {
    border-color: #000;
  }

  @media (min-width: 40rem) {
    padding: 2rem;
  }
}
```
結果として生成されるセレクタは `.card h2`、`.card a` と（Sass でコンパイルした場合と）同一になる。`&` は親セレクタを表し、`@media` や `@container` などの at-rule もスタイルと並べてネストできる（`@media` ブロックが `.sidebar` に対して適用され、セレクタを繰り返す必要がない）。

**③ 効果・注意点**
- ビルドツール（Sass コンパイラ）を挟まずに済み、ブラウザが直接展開を行う。
- 親セレクタがセレクタリスト（例: `.card, #featured { .title {} }`）の場合、`:is(.card, #featured) .title` と同じ扱いになるため、`.card` だけがマッチしたケースでもネストされたルールは ID セレクタ相当の詳細度を持つ、という**詳細度の落とし穴**がある点に注意が必要。
- ブラウザサポート: Baseline "Widely available"（2026年6月時点）。

---

### 1.2 `:has()` セレクタ

**① 目的・問題意識**
CSS は長らく「子要素」や「隣接する兄弟要素」に向けてしかスタイルを適用できず、「中に何が入っているか」に応じて親要素をスタイリングすることができなかった。そのため JavaScript でクラスを親に付け外しするハックが必要だった。

**② コード**
```css
.field:has(input:user-invalid) {
  border-color: red;
}
```
入力欄のバリデーションが失敗した（`:user-invalid`）とき、それを内包するラッパー `.field` を赤枠にする例。

**③ 効果**
- これまで JavaScript でトグルしていた親要素のクラス付与を CSS だけで代替できる。ただし「見た目を変える」以上のこと（何らかの処理を実行する）が必要な場合は依然として JavaScript が必要。
- ブラウザサポート: 2023年12月以降、主要ブラウザ全てで利用可能。プロダクションで安全に使える。

---

### 1.3 コンテナクエリ（`container-type` / `@container` / `cqi`）

**① 目的・問題意識**
メディアクエリはビューポート全体の幅を問い合わせるが、同じコンポーネント（例: カード）が「狭いサイドバー」と「広いメインカラム」の両方に置かれる場合、置かれた場所ごとに異なるレイアウトを与えたい。コンテナクエリは、ビューポートではなく「コンポーネントを包むラッパー要素」の幅を問い合わせる。

**② コード**
```css
.sidebar, .main {
  container-type: inline-size;
}

.card {
  display: grid;
  gap: 1rem;
}

@container (min-width: 32rem) {
  .card {
    grid-template-columns: 1fr 2fr;
  }
}

/* コンテナ幅に応じて可変するタイポグラフィ */
.card h2 {
  font-size: clamp(1rem, 5cqi, 1.75rem);
}
```
ラッパーに `container-type: inline-size` を指定することで、ブラウザに「この要素の幅を追跡してほしい」と伝える。`cqi` はコンテナのインライン方向サイズの 1% を表す単位。

**③ 効果**
- 同一コンポーネントを異なる幅のコンテナに配置しても、コンテナ自身の実測幅に応じてレイアウト・文字サイズを切り替えられる。
- 注意点: `container-type: inline-size` は既に親を埋める要素には問題ないが、幅がコンテンツ由来の要素（インラインブロックのボタンなど）に指定するのは適さない。

### 1.4 サブグリッド（`subgrid`）

**① 目的・問題意識**
カード型 UI で「画像・タイトル・本文」の高さを複数カード間で揃えたい場合、従来は各カード内部で `grid` を再定義してもカード同士の行の高さを揃えることは難しかった。`subgrid` は、子要素が自身のマークアップ構造を保ったまま、親グリッドの行トラックをそのまま借用できる。

**② コード**
```css
.cards {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 1.5rem;
}

.card {
  display: grid;
  grid-row: span 3;
  grid-template-rows: subgrid;
}
```
`.card` は親 `.cards` の行トラック定義をそのまま継承し、複数カードの各パーツ（画像行・タイトル行・本文行）の高さが自動的に揃う。

**③ 効果**
- カードごとに個別に高さを JS で測定・同期する処理が不要になる。
- ブラウザネイティブの Grid 機構だけで、複雑な整列レイアウトを実現できる。

### 1.5 `aspect-ratio`

**① 目的・問題意識**
レスポンシブな動画埋め込み（YouTube の iframe など）で、あらゆる画面幅でも 16:9 などの比率を保った箱を作りたいという要求は昔からあった。`aspect-ratio` 登場以前は、`height: 0; padding-top: 56.25%;` としたラッパー要素の中に絶対配置した子要素を置く、いわゆる「パディングハック」（padding-top のパーセンテージがラッパーの**幅**を基準に解決されるという CSS の仕様の副作用を利用したテクニック）でしか実現できなかった。

**② コード**

Before（パディングハック）:
```css
.video-wrapper {
  position: relative;
  height: 0;
  padding-top: 56.25%; /* 16:9 */
}
.video-wrapper iframe {
  position: absolute;
  top: 0;
  left: 0;
  width: 100%;
  height: 100%;
}
```

After（`aspect-ratio`）:
```css
iframe {
  aspect-ratio: 16 / 9;
  width: 100%;
}
```

**③ 効果**
- ラッパー要素や絶対配置が不要になり、ブラウザが自動的に高さを計算する。あらゆる画面幅で崩れない。
- ブラウザサポート: Baseline "Widely available"（2024年3月、Chrome 88 / Firefox 89 / Safari 15 以降）。

### 1.6 `text-wrap: balance`

**① 目的・問題意識**
見出し（`h1`/`h2` など）が複数行に折り返されるとき、最後の行だけ極端に短い単語が残る（不格好な改行）という問題が長年あった。これを解消するために JavaScript で行の折り返し位置を計算するライブラリが使われることもあった。

**② コード**
```css
h1, h2, h3 {
  text-wrap: balance;
}
```

**③ 効果**
- 見出し内の各行の文字量ができるだけ均等になるようブラウザが自動的に折り返し位置を調整する。見出しには「1行足すだけ」で効果があるとされる。
- 類似機能の `text-wrap: pretty`（最終行の孤立語を避ける）は記事執筆時点で Firefox 未対応と注記されている。

### 1.7 動的ビューポート単位（`svh` / `lvh` / `dvh`）

**① 目的・問題意識**
モバイルブラウザでは、アドレスバーの表示・非表示によってビューポートの実際の高さが変化するため、従来の `vh` 単位では `100vh` の要素がアドレスバー表示時に画面からはみ出す問題があった。

**② コード**
```css
/* レイアウトの既定値としてはこちらを推奨 */
.page {
  min-height: 100svh; /* Small viewport height: UI表示時の高さ */
}

/* 常に画面いっぱいに追従させたい要素にのみ dvh を使う */
.bottom-sheet {
  height: 100dvh; /* Dynamic viewport height: 現在の状態に追従 */
}
```
`svh` は「ブラウザ UI が表示されている状態」の小さいビューポート、`lvh` は「UI が畳まれた状態」の大きいビューポート、`dvh` は現在の状態に追従する動的な値。

**③ 効果**
- `dvh` はスクロール中にツールバーがアニメーションしながら消えるのに合わせて値が変化し続けるため、ボトムシートのような「追従してほしい」要素には向くが、ヒーローセクションのような要素では数ピクセル単位でガタつく副作用がある。そのため記事では「レイアウトの既定は `svh`、動きが意図された要素にのみ `dvh`」という使い分けを推奨している。
- ブラウザサポート: Baseline "Widely available"（2025年6月時点、Safari 15.4 / Firefox 101 / Chrome 108 以降）。

### 1.8 `@starting-style` + `transition-behavior: allow-discrete`

**① 目的・問題意識**
`display: none` から出現する要素をアニメーションさせたい場合、通常の `transition` では要素に「遷移前のスタイル」が存在しないため機能しなかった。そのため `requestAnimationFrame` で 1 tick 遅れてクラスを付与したり、専用ライブラリに頼る必要があった。

**② コード**
```css
[popover] {
  opacity: 1;
  transition: opacity 0.3s, display 0.3s allow-discrete;

  @starting-style {
    opacity: 0;
  }
}

[popover]:not(:popover-open) {
  opacity: 0;
}
```
`@starting-style` はブラウザに要素の「開始前」状態を教える。`transition-behavior: allow-discrete`（`display 0.3s allow-discrete` の記法）を指定すると、`display` のような離散的（discrete）なプロパティも遷移が終わるまで表示を保持できるため、フェードアウトも可能になる。

**③ 効果**
- `requestAnimationFrame` を使った tick 遅延ハックやアニメーションライブラリなしに、出現・消滅アニメーションを CSS だけで実装できる。
- ブラウザサポート: Baseline "Newly available"（2024年8月、Chrome 117 / Safari 17.5 / Firefox 129）、"Widely available" 到達は2027年2月ごろの見込み。Firefox は `transition-behavior: allow-discrete` 自体はサポートするが `display` の遷移には未対応のため、Firefox ではフェードインは効くがフェードアウトは瞬時に消える（非対称な挙動になる）。

### 1.9 `oklch()` と `color-mix()`

**① 目的・問題意識**
Sass が使われる主な理由の一つが `darken()` や `mix()` といった色の演算関数で、ビルド時に色計算を行っていた。CSS ネイティブにはこうした色演算の手段がなかった。

**② コード**
```css
:root {
  --brand: oklch(55% 0.2 250);
  --brand-light: oklch(75% 0.2 250);
  --brand-dark: oklch(40% 0.2 250);
}

.button {
  background: var(--brand);
}

.button:hover {
  background: color-mix(in oklch, var(--brand) 85%, white);
}
```
`oklch()` は明度・彩度（chroma）・色相（hue）で色を表現する色空間関数で、色相を固定したまま明度の数値だけ変えることで明るいバリエーションを簡単に作れる。`color-mix()` は実行時に 2 色を指定比率で混合する関数で、テーマやユーザー設定によって変化するカスタムプロパティ（`--brand` など）とも組み合わせられる。

**③ 効果**
- Sass のビルドステップなしに、ホバー時の色変化やカラーパレットのバリエーション生成をブラウザ実行時に行える。
- カスタムプロパティ経由なのでテーマ切り替え（ダークモード等）にも動的に追従する。

### 1.10 `@scope`

**① 目的・問題意識**
コンポーネント単位でスタイルを閉じ込めたい（他のコンポーネントのクラス名と衝突させたくない）というニーズに対し、これまでは命名規則（BEM 等）、CSS Modules、CSS-in-JS、ユーティリティクラスなど、ビルドツールやランタイムに依存する手法が使われてきた。`@scope` はセレクタの適用範囲をネイティブに限定する at-rule。

**② コード・詳細**
記事内の完全なコードスニペットはネットワーク制約により本セッションでは確認できませんでした（`.css` に貼り付け可能な形の具体例が検索結果から復元できず）。一般的な `@scope` の構文は以下の通り：
```css
@scope (.card) to (.card__nested-scope-limit) {
  h2 { color: royalblue; }
}
```
`@scope (開始セレクタ) to (終了セレクタ)` の形で、指定した要素の内側だけにスタイルの適用範囲を限定できる。

**③ 効果・サポート状況**
- コンポーネントライブラリ間のスタイル衝突を、ビルドツールなしにネイティブ CSS だけで防げる（とされる）。
- ブラウザサポート: Baseline "Newly available"（2026年3月24日時点）。

### 1.11 `field-sizing: content`

**① 目的・問題意識**
`<textarea>` などのフォーム要素を入力内容に応じて自動的にリサイズさせたい場合、従来は JavaScript で `scrollHeight` を監視して高さを再計算するハックが必要だった。

**② コード・詳細**
記事内の完全なコードスニペットはネットワーク制約により本セッションでは確認できませんでした。一般的な構文は以下の通り：
```css
textarea {
  field-sizing: content;
}
```
`field-sizing: content` を指定すると、フォームコントロールが内容量に応じて自動的にサイズを変える。

**③ 効果・サポート状況**
- `scrollHeight` を監視して高さを再計算する JavaScript が不要になる。
- ブラウザサポート: 2026年6月16日時点で利用可能（web-features / webstatus.dev 情報に基づく）。
