## 1. selected オプションの幅に合わせて select をサイズする（field-sizing: content）

**記事タイトル**: Setting the width of `<select>` to the width of the selected option
**URL**: [https://www.matuzo.at/blog/2026/select-fieldsize](https://www.matuzo.at/blog/2026/select-fieldsize)（Manuel Matuzovic 氏のブログ。Issue #748 のメイン特集記事と推定 — 根拠は本ファイル末尾の調査メモを参照）

### ① 目的・問題意識

HTML の `<select>` 要素は、デフォルトでは**現在選択されているオプションの文字数に関わらず、選択肢の中で最も長いオプションの幅**に合わせてボックスサイズが決まる。

例えば選択肢に "Amsterdam" "Rotterdam" "Scheveningen" "Utrecht" がある場合、"Utrecht"（7文字）を選択していても、select ボックスは最も長い "Scheveningen"（12文字）に合わせた幅のまま表示され続ける。これにより、フォーム内で select 要素だけ不自然に横長になり、隣接するテキスト入力欄などとの見た目の整合性が崩れるという問題が長年放置されてきた。

この記事は、CSS の `field-sizing` プロパティ（`content` 値）を使うことで、**select を「選択中のオプションの幅」に応じて動的にサイズさせる**方法を解説している。

### ② 具体的な技術詳細とコード例

HTML（記事で使われている都市名の選択肢の例）:

```html
<label for="city">Choose a city</label>
<select id="city" name="city">
  <option value="ams">Amsterdam</option>
  <option value="rot">Rotterdam</option>
  <option value="sch">Scheveningen</option>
  <option value="utr" selected>Utrecht</option>
</select>
```

基本の CSS:

```css
select {
  field-sizing: content;
}
```

これだけだと、非常に短いオプションで select が極端に小さくなりすぎる、あるいは長いオプションで際限なく広がるという問題があるため、`min-inline-size` / `max-inline-size` で下限・上限を設けるのが実用的とされる:

```css
select {
  field-sizing: content;
  min-inline-size: 8ch;   /* 短い選択肢でボックスが潰れすぎないようにする最小幅 */
  max-inline-size: 30ch;  /* 極端に長い選択肢でも際限なく広がらないようにする最大幅 */
}
```

未対応ブラウザではこのプロパティが単に無視され、従来通りの固定サイズ（最長オプション基準）にフォールバックするため、`@supports` を使わずそのまま書いても安全な漸進的強化（progressive enhancement）として使える。より丁寧に書く場合:

```css
@supports (field-sizing: content) {
  select {
    field-sizing: content;
    min-inline-size: 8ch;
    max-inline-size: 30ch;
  }
}
```

選択肢が変わるたびに幅が唐突に変わるのではなく滑らかにアニメーションさせたい場合、`interpolate-size: allow-keywords` と `transition` を組み合わせる手法も同時期の関連記事群で言及されている:

```css
select {
  field-sizing: content;
  interpolate-size: allow-keywords;
  transition: inline-size 0.2s ease;
}
```

### ③ なぜそれが効果的か

- JavaScript で選択中の `<option>` のテキスト幅を測定して `style.width` を都度書き換える、といった従来の力技（ResizeObserver やダミー要素での幅計測など）が一切不要になり、宣言的な CSS 1行で解決できる。
- ブラウザ組み込みのテキスト計測ロジックをそのまま使うため、フォントの変更やユーザーのズーム設定、国際化（多言語で文字幅が変わる場合）にも自動的に追従する。
- `min-inline-size` / `max-inline-size` と組み合わせることで、実用上必要な「小さすぎず・大きすぎず」の挙動を CSS のみで制御でき、レイアウトの予測可能性を保てる。
- 非対応ブラウザではプロパティが単に無視されるだけで壊れないため、安全に本番投入できる progressive enhancement である点も採用ハードルを下げている。
- タイミングとしても効果的な話題選定である。`field-sizing` は Chrome/Safari では既に対応済みだったが、**Firefox 152（2026年6月16日リリース）でついに実装され、3大ブラウザエンジンで揃って Baseline（Newly available）となった**。これにより「明日から実務でも使える」タイミングでの紹介記事として意味を持つ。

### デモ・視覚的説明

記事内には Amsterdam / Rotterdam / Scheveningen / Utrecht という都市名を選択肢に持つインタラクティブな `<select>` のライブデモが埋め込まれており、選択肢を切り替えるたびに select ボックスの横幅が選択中の都市名の文字数に応じてリアルタイムに伸縮する様子を実際に操作して確認できる構成と推察される。
