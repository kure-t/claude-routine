## 1. The History of React Through Code（コードで振り返るReactの歴史）

**出典**: [playfulprogramming.com/posts/react-history-through-code/](https://playfulprogramming.com/posts/react-history-through-code/)  
**著者**: Corbin Crutchley

### ① 目的・問題意識

React が2013年5月29日に公開されてから13年。その進化をコードサンプルと実装詳細を通じて振り返ることで、React のAPIデザインに一貫した設計哲学があることを示す。「なぜ今のReactがこうなのか」を歴史から理解することが目的。

### ② 具体的な技術詳細

React の歴史的な変遷をコードで追うと、以下のような進化が見えてくる。

**初期（2013年）— createClass**

```jsx
var HelloWorld = React.createClass({
  render: function() {
    return <div>Hello, {this.props.name}!</div>;
  }
});
```

**ES6クラス（React 0.13〜）**

```jsx
class HelloWorld extends React.Component {
  render() {
    return <div>Hello, {this.props.name}!</div>;
  }
}
```

**Hooks（React 16.8〜、2019年）**

```jsx
function HelloWorld({ name }) {
  const [count, setCount] = useState(0);
  return (
    <div>
      <p>Hello, {name}! Clicked {count} times.</p>
      <button onClick={() => setCount(count + 1)}>Click</button>
    </div>
  );
}
```

**React Server Components（React 18〜）**

```jsx
// server component（サーバーで実行、JSをクライアントに送らない）
async function ProductList() {
  const products = await db.query('SELECT * FROM products');
  return (
    <ul>
      {products.map(p => <li key={p.id}>{p.name}</li>)}
    </ul>
  );
}
```

**React Compiler（現在）**

React Compiler は、React の Rules of Hooks とStrictModeに準拠したコードを自動的にメモ化し最適化する。開発者が `useMemo`・`useCallback` を手動で書く必要がなくなる。

**Next.js の Partial Pre-rendering（PPR）**

```jsx
import { Suspense } from 'react';

export default function Page() {
  return (
    <>
      {/* 静的コンテンツ: ビルド時にキャッシュ */}
      <StaticHeader />
      {/* 動的コンテンツ: リクエスト時に並列計算 */}
      <Suspense fallback={<Spinner />}>
        <DynamicFeed />
      </Suspense>
    </>
  );
}
```

### ③ なぜ効果的か

React の API はバージョンをまたいで一貫した設計哲学（コンポーネントの合成・単方向データフロー・宣言的UI）を保っており、古いコードパターンを学ぶことが最新のReactの理解に直結する。13年の変遷を辿ることで、単なる機能リストではなく「設計の意図」が見えてくる。

## 2. Picture-in-Picture for Any React Component（あらゆるReactコンポーネントをPiP表示）

**出典**: [npmjs.com/package/react-document-pip](https://www.npmjs.com/package/react-document-pip) / [HN: Show HN #45576961](https://news.ycombinator.com/item?id=45576961)  
**GitHub (関連)**: [martinshaw/react-document-picture-in-picture](https://github.com/martinshaw/react-document-picture-in-picture)

### ① 目的・問題意識

従来のPicture-in-Picture APIは動画要素（`<video>`）専用だった。Chrome 116で導入された **Document Picture-in-Picture API** を使えば、任意のHTMLコンテンツを常に最前面に浮かぶフローティングウィンドウとして表示できる。Reactコンポーネントをそのまま浮かせたい、というユースケースを簡単に実現するのが `react-document-pip` パッケージ。

### ② 具体的なコードと技術詳細

**インストール**

```bash
npm install react-document-pip
```

**基本的な使い方**

```tsx
import { DocumentPIP } from 'react-document-pip';

function App() {
  const [isPipOpen, setIsPipOpen] = useState(false);

  return (
    <div>
      <button onClick={() => setIsPipOpen(true)}>Open PiP</button>

      <DocumentPIP
        isPipOpen={isPipOpen}
        size={{ width: 400, height: 300 }}
        mode="transfer"
        copyAllStyles={true}
        onEnter={() => console.log('PiP opened')}
        onClose={() => setIsPipOpen(false)}
      >
        {/* 任意のReactコンポーネントを渡せる */}
        <VideoPlayer />
      </DocumentPIP>
    </div>
  );
}
```

**主要Props**

| Prop | 型 | 説明 |
|------|-----|------|
| `isPipOpen` | `boolean` | PiPウィンドウの開閉制御 |
| `size` | `{ width: number; height: number }` | ウィンドウサイズ |
| `mode` | `"clone" \| "transfer" \| "transfer-only"` | コンテンツの表示方法 |
| `copyAllStyles` | `boolean` | CSSスタイルをPiPウィンドウにコピー |
| `disallowReturnToOpener` | `boolean` | ユーザーによる元ウィンドウへの戻りを無効化 |
| `preferInitialWindowPlacement` | `boolean` | 初期位置指定を優先 |
| `onEnter` | `() => void` | PiP開いたときのコールバック |
| `onClose` | `() => void` | PiP閉じたときのコールバック |

**モードの違い**
- `clone`: 元コンテンツはそのままに複製をPiP表示
- `transfer`: コンテンツを元の場所からPiPウィンドウに移動
- `transfer-only`: 完全にPiPウィンドウにのみ表示

**ローレベル実装（Vanilla JS + React ポータル）**

```tsx
async function openPiP() {
  const pipWindow = await window.documentPictureInPicture.requestWindow({
    width: 400,
    height: 300,
  });

  // PiPウィンドウのdocumentにReactをレンダリング
  const container = pipWindow.document.createElement('div');
  pipWindow.document.body.appendChild(container);

  ReactDOM.createPortal(<MyComponent />, container);
}
```

**制限事項**
- Chrome 116以上が必要（他ブラウザは未対応）
- HTTPS（セキュアコンテキスト）またはlocalhostでのみ動作

### ③ なぜ効果的か

動画に限定されていた従来のPiPと異なり、任意のコンポーネント（チャット、メモ、ToDoリスト、編集UI）を浮かせて別アプリを操作しながら使い続けられる。`react-document-pip` はこの複雑なブラウザAPIをReactの宣言的なパターンで隠蔽し、`isPipOpen` というシンプルなboolean制御に落とし込んでいる。

## 3. Building a Predictive Text Input（予測テキスト入力の実装）

**出典**: [buttondown.com/vadima - How to Build an AI-Powered Autocomplete for Any Text Input](https://buttondown.com/vadima/archive/how-to-build-an-ai-powered-autocomplete-for-any/) (2026年3月)  
**関連ライブラリ**: [react-ghost-text](https://github.com/agdhruv/react-ghost-text) / [react-inline-predict](https://github.com/KhaledSakr/react-inline-predict)

### ① 目的・問題意識

VS CodeのIntelliSenseやGmailのSmart Composeのように、ユーザーが入力中に「薄いグレーのゴーストテキスト」として補完候補を表示し、Tabキーで確定できる体験をReactアプリに実装する。特にAI APIと組み合わせることで、任意のテキストエリアにインライン予測補完を追加する方法を解説する。

### ② 具体的なコードと技術詳細

#### パターンA: `react-ghost-text` ライブラリ（AIベースのゴーストテキスト）

```bash
npm install react-ghost-text
```

```tsx
import { AutocompleteTextbox } from 'react-ghost-text';

export default function Editor() {
  const [content, setContent] = useState('');

  // AIサービス（OpenAI/Claudeなど）を呼び出す非同期関数
  const getSuggestion = async (precedingText: string): Promise<string> => {
    const response = await fetch('/api/autocomplete', {
      method: 'POST',
      body: JSON.stringify({ text: precedingText }),
    });
    const data = await response.json();
    return data.suggestion;
  };

  return (
    <AutocompleteTextbox
      getSuggestion={getSuggestion}
      onContentChange={(text) => setContent(text)}
      debounceTime={500}          // 入力停止後500msで提案リクエスト
      suggestionStyle={{ color: 'rgba(0,0,0,0.35)' }}  // ゴーストテキストのスタイル
    />
  );
}
```

**主要Props**

| Prop | デフォルト | 説明 |
|------|-----------|------|
| `getSuggestion` | 必須 | 補完候補を返す非同期関数 |
| `debounceTime` | `1000` | 入力停止後の待機時間（ms） |
| `disableAutocomplete` | `false` | 補完機能の無効化 |
| `suggestionClassName` | `"suggestion"` | ゴーストテキストのCSSクラス |
| `onSuggestionShown` | - | 候補表示時コールバック |
| `onSuggestionAccepted` | - | Tab押下・確定時コールバック |
| `onSuggestionRejected` | - | Escape押下・却下時コールバック |

**動作フロー**
1. ユーザーが入力を止める（debounceTime後）
2. `getSuggestion(現在のテキスト)` が呼ばれる
3. AIサービスが補完テキストを返す
4. 入力欄の末尾にゴーストテキストとして表示
5. `Tab` → 補完確定、`Escape` → 却下

```tsx

  };
```

#### パターンC: スクラッチ実装（ストリーミング対応・詳解版）

```tsx
import { useState, useRef, useCallback } from 'react';

function PredictiveTextarea() {
  const [value, setValue] = useState('');
  const [suggestion, setSuggestion] = useState('');
  const abortRef = useRef<AbortController | null>(null);
  const debounceRef = useRef<NodeJS.Timeout>();

  const fetchSuggestion = useCallback(async (text: string) => {
    // 前のリクエストをキャンセル
    abortRef.current?.abort();
    abortRef.current = new AbortController();

    const res = await fetch('/api/complete', {
      method: 'POST',
      signal: abortRef.current.signal,
      body: JSON.stringify({ prompt: text }),
    });

    let result = '';
    const reader = res.body!.getReader();
    const decoder = new TextDecoder();

    // ストリーミングで受信しながらゴーストテキストを更新
    while (true) {
      const { done, value } = await reader.read();
      if (done) break;
      result += decoder.decode(value);
      setSuggestion(result);
    }
  }, []);

  const handleChange = (e: React.ChangeEvent<HTMLTextAreaElement>) => {
    const newValue = e.target.value;
    setValue(newValue);
    setSuggestion('');

    // デバウンス
    clearTimeout(debounceRef.current);
    debounceRef.current = setTimeout(() => {
      if (newValue.trim()) fetchSuggestion(newValue);
    }, 400);
  };

  const handleKeyDown = (e: React.KeyboardEvent) => {
    if (e.key === 'Tab' && suggestion) {
      e.preventDefault();
      setValue(value + suggestion);
      setSuggestion('');
    } else if (e.key === 'Escape') {
      setSuggestion('');
    }
  };

  return (
    <div style={{ position: 'relative' }}>
      <textarea
        value={value}
        onChange={handleChange}
        onKeyDown={handleKeyDown}
        style={{ width: '100%', minHeight: '100px' }}
      />
      {suggestion && (
        <span style={{
          position: 'absolute',
          color: 'rgba(0,0,0,0.35)',
          pointerEvents: 'none',
          // テキストエリアと同じフォント設定が必要
        }}>
          {suggestion}
        </span>
      )}
    </div>
  );
}
```

### ③ なぜ効果的か

- **デバウンス + キャンセル**: 入力のたびにAPIを叩くとコスト・遅延が増大する。デバウンスで間引き、AbortControllerで古いリクエストをキャンセルすることで、高速なタイピングに追従しつつムダなAPIコールを防ぐ。
- **ストリーミング**: 補完テキストを一括受信するよりストリーミングで受け取ることで、ゴーストテキストが「書かれていく」ような自然なUXを実現する。
- **キーボードUX**: Tab確定・Escape却下という直感的な操作は、VS CodeやGmailでユーザーが慣れ親しんだパターンと一致する。
- **スマートキャッシング**: `react-ghost-text` は過去の提案をキャッシュし、同じ入力プレフィックスに対して再度APIを呼び出さない設計になっている。

## 4. Is TanStack Start's Deferred Hydration a Big Deal?（TanStack Startの遅延Hydrationは革命的か？）

**出典**: [YouTube: Is TanStack Starts Deferred Hydration Revolutionary?](https://www.youtube.com/watch?v=_PB9rHndhU8)  
**公式ドキュメント**: [TanStack Start - Deferred Hydration](https://tanstack.com/start/latest/docs/framework/react/guide/deferred-hydration)  
**リリース**: TanStack Router - 2026年5月20日（PR #7362 by @schiller-manuel）

> ※この記事はYouTube動画へのリンクのため、動画内容の詳細確認はスキップし、公式ドキュメントの情報をもとに解説します。

### ① 目的・問題意識

SSR（サーバーサイドレンダリング）を使うアプリでは、ページがHTMLとして表示された後に **Hydration**（JavaScriptを読み込み・実行してReactコンポーネントをインタラクティブにする処理）が行われる。大きなページでは、ユーザーがすぐに必要としないビューポート外のコンポーネントまで全てhydrateするため、初期ロード時間が長くなる問題があった。

**Deferred Hydration** は、ページのビューポート外にあるコンテンツのhydrationを後回しにし、必要になったときだけ処理するためのパフォーマンス最適化手法。

### ② 具体的なコードと技術詳細

**基本的な設定**

```tsx
// app/routes/product.$id.tsx
import { createLazyComponent } from '@tanstack/react-start';

// 遅延hydrationの境界を定義
const DeferredReviews = createLazyComponent(
  () => import('../components/Reviews'),
  {
    // ビューポートの400px手前で先読み開始
    hydrationStrategy: 'viewport',
    rootMargin: '400px',
  }
);

export default function ProductPage() {
  return (
    <div>
      {/* すぐにインタラクティブにする必要があるコンテンツ */}
      <ProductInfo />
      <AddToCart />

      {/* ビューポートに近づくまでhydrationを遅延 */}
      <Suspense fallback={<ReviewsSkeleton />}>
        <DeferredReviews productId={productId} />
      </Suspense>
    </div>
  );
}
```

**仕組み**

1. **初回SSR**: サーバーはReviewsコンポーネントも含めてHTMLを生成（SEO・速度ともに問題なし）
2. **初回クライアントhydration**: `DeferredReviews` のHTMLは保持されるが、Reactツリーとしてのhydrationはスキップ
3. **ビューポート接近（400px以内）**: IntersectionObserverが境界を検知し、TanStack Startが遅延バンドルをロードしてhydration開始
4. **クライアントサイドナビゲーション**: SSR HTMLがない場合は通常通りクライアントレンダリング

**`rootMargin` による先読みチューニング**

```tsx
const DeferredReviews = createLazyComponent(
  () => import('../components/Reviews'),
  {
    hydrationStrategy: 'viewport',
    // ビューポートから400px手前でバンドルを先読み開始
    // → ユーザーがスクロールしてきたときにはすでにロード済み
    rootMargin: '400px',
  }
);
```

**遅延hydrationに適したコンテンツ**

- ビューポート外のレビュー・コメント
- 商品詳細・関連商品
- 長いマーケティングセクション
- フッターコンテンツ
- 「おすすめ」「類似商品」セクション

**注意点**

```tsx
// ❌ 避けるべき: ラッパーコンポーネントで境界を隠す
function Wrapper({ children }) {
  return <DeferredBoundary>{children}</DeferredBoundary>;
}

// 子コンポーネントのコード分割は、コンパイラが
// 任意のコンポーネントの間接参照をたどれないため機能しない
```

### ③ なぜ効果的か

- **初期TTI（Time to Interactive）の削減**: 重要でないコンポーネントのJSをビューポート外では評価しないため、JavaScriptの実行コストが下がる。
- **SEOを維持**: サーバーレンダリングは行われるため、クローラーにはHTMLが届く。
- **ユーザーが感じる速度**: ページ上部のインタラクティビティが早く確保されるため、体感速度が向上する。
- **自動コード分割**: `createLazyComponent` が自動的に境界でバンドルを分割するため、手動でのダイナミックインポート管理が不要。
- **従来のReact.lazy との違い**: `React.lazy` はクライアントサイドのコード分割のみ。Deferred Hydrationはそれに加えて、SSRで生成済みのHTMLを保持したままhydrationを遅延させる点が異なる。

| テーマ | 核心技術 | 効果 |
