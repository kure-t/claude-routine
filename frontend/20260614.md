## 記事1: PolyCSS — A CSS 3D Engine for the DOM

**リンク**: https://polycss.com / https://github.com/LayoutitStudio/polycss

### ① 目的・問題意識

WebGL や Canvas は高性能な 3D レンダリングを可能にするが、レンダリング結果は「ピクセル」に過ぎず、DOM の恩恵（アクセシビリティ、イベントリスナー、CSS スタイリング、DevTools での検査、テキスト選択、ホバー状態）を失う。

**PolyCSS** はこの問題を解消するために生まれた CSS 3D エンジンで、**ポリゴンメッシュを実際の DOM 要素（HTML 要素）としてレンダリング**する。各ポリゴンが本物の `<div>` 要素として存在するため、CSS クラス、クリックハンドラー、ホバー効果、CSS トランジション、フレームワークコンポーネントをそのまま適用できる。

### ② 具体的な技術詳細

**仕組みの核心: `matrix3d()` による配置**

各可視ポリゴンはひとつのリーフ要素として DOM に出力される。レンダラーはポリゴンを表現するのに最もコストの低い CSS プリミティブ（`div`）を選択し、`matrix3d(...)` を使って 3D 空間に配置する。

```
transform: matrix3d(
  a1, a2, a3, a4,
  b1, b2, b3, b4,
  c1, c2, c3, c4,
  d1, d2, d3, d4
)
```

UV テクスチャ付き三角形は生成されたアトラススプライトにパックされ、`background-position` で位置調整される。ブラウザのコンポジターが 3D レイヤリングを処理する。

**対応ファイル形式**

- OBJ + MTL
- glTF / GLB
- STL
- MagicaVoxel VOX（ボクセル）

**カスタム要素（Custom Elements）の使い方**

CDN から読み込むだけで HTML タグとして利用できる。

```html
<script type="module" src="https://esm.sh/@layoutit/polycss/elements"></script>

<poly-camera rot-x="65" rot-y="45">
  <poly-scene>
    <poly-orbit-controls drag wheel></poly-orbit-controls>
    <poly-box size="100" color="#ffd166"></poly-box>
  </poly-scene>
</poly-camera>
```

- `<poly-camera>`: 外側のノード。投影と軌道状態を管理する
- `<poly-scene>`: カメラ内部に置く。ライティングとアトラスオプションを保持
- `<poly-mesh>`: OBJ/STL/glTF/GLB/VOX を読み込んでレンダリングする
- `<poly-orbit-controls>`: マウスドラッグ・ホイールによるカメラ操作

**npm インストールと JS API**

```bash
# Vanilla JS
npm install @layoutit/polycss

# React
npm install @layoutit/polycss-react

# Vue
npm install @layoutit/polycss-vue
```

**Headless API（命令型）の完全なコード例**

```javascript
import { createPolyCamera, createPolyScene, loadMesh } from "@layoutit/polycss";

// カメラを作成（回転角度を指定）
const host = document.getElementById("polycss");
const camera = createPolyCamera({ rotX: 65, rotY: 45 });

// シーンを作成してカメラをバインド
const scene = createPolyScene(host, { camera });

// OBJ ファイルと MTL マテリアルを読み込む
const mesh = await loadMesh("https://polycss.com/gallery/obj/cottage.obj", {
  mtlUrl: "https://polycss.com/gallery/obj/cottage.mtl",
});

// シーンにメッシュを追加
scene.add(mesh);
```

**メッシュ最適化**

`loadMesh()` はデフォルトで `meshResolution: "lossy"` モードで動作し、以下の最適化パイプラインを実行する：
1. ソリッドテクスチャのスウォッチベイク
2. 近似する色の統合クリーンアップ
3. 静的三角形の簡略化
4. DOM コスト最適化

### ③ なぜ効果的か

| 比較 | WebGL / Canvas | PolyCSS |
|------|---------------|---------|
| アクセシビリティ | ✗（ピクセル） | ✓（DOM 要素） |
| CSS スタイリング | ✗ | ✓（hover, class, animation） |
| イベント処理 | 手動計算が必要 | ✓（addEventListener） |
| DevTools 検査 | 困難 | ✓（Elements パネルで確認可） |
| パフォーマンス | 高（GPU シェーダー） | 中（ブラウザコンポジター） |
| セマンティクス | ✗ | ✓ |

CSS 3D transforms はブラウザのコンポジターによってハードウェアアクセラレートされており、`transform: matrix3d()` は GPU の行列演算を活用する。WebGL ほど高速ではないが、数百ポリゴン規模のモデルを実用的な速度でレンダリングでき、**3D オブジェクトが「クリック可能・選択可能・スタイル可能な DOM ノード」** であり続けるという強力な優位性がある。

## 記事2: CSS is DOOMed — Rendering DOOM in 3D with CSS

**リンク**: https://nielsleenheer.com/articles/2026/css-is-doomed-rendering-doom-in-3d-with-css/  
**GitHub**: https://github.com/NielsLeenheer/cssDOOM  
**プレイ**: https://cssdoom.wtf/

### ① 目的・問題意識

「モダン CSS はどこまでできるのか？」という限界探求プロジェクト。Canvas も WebGL も使わずに、**DOOM（1993年のクラシック3Dシューター）をブラウザで完全にプレイ可能な形で CSS だけでレンダリングする**という試みである。

すべての壁、床、天井、バレル、敵（Imp）は `<div>` 要素として存在し、3D 空間への配置は CSS transforms で行われる。ゲームロジック（AI、衝突判定、入力処理）は JavaScript が担当するが、**描画処理は 100% CSS** である。

### ② 具体的な技術詳細

**アーキテクチャの分離**

JavaScript から CSS へは最小限の情報だけを渡す設計になっている：

```javascript
// JavaScript 側: プレイヤーの座標と角度のみを CSS カスタムプロパティとして設定
document.documentElement.style.setProperty('--player-x', playerX);
document.documentElement.style.setProperty('--player-y', playerY);
document.documentElement.style.setProperty('--player-z', playerZ);
document.documentElement.style.setProperty('--player-angle', playerAngle);
```

CSS がこれらの値を基に全ての三角関数計算を行う。

**壁のレンダリング（核心部分）**

各壁は DOOM の WAD ファイルから読み取った生座標をカスタムプロパティとして持ち、CSS が `hypot()` と `atan2()` を使って幅・回転を計算する：

```css
.wall {
  /* JavaScript が設定するプロパティ: DOOM 座標の生データ */
  /* --start-x, --start-y, --end-x, --end-y, --floor-z, --ceiling-z */

  /* CSS が三角関数で計算 */
  --delta-x: calc(var(--end-x) - var(--start-x));
  --delta-y: calc(var(--end-y) - var(--start-y));

  /* 壁の幅: 始点と終点の距離を Pythagoras（斜辺）で計算 */
  width: calc(hypot(var(--delta-x), var(--delta-y)) * 1px);

  /* 壁の高さ: 天井と床の差 */
  height: calc((var(--ceiling-z) - var(--floor-z)) * 1px);

  /* 3D 空間への配置: 始点に translate し、atan2 で回転角を計算 */
  transform:
    translate3d(
      calc(var(--start-x) * 1px),
      calc(var(--ceiling-z) * -1px),
      calc(var(--start-y) * -1px)
    )
    rotateY(atan2(var(--delta-y), var(--delta-x)));
}
```

**カメラ実装（逆変換トリック）**

プレイヤーを動かすのではなく、世界全体をプレイヤーの逆方向に動かすことで「カメラ移動」を実現している：

```css
.scene {
  /* プレイヤー座標の逆変換でシーン全体を移動させ、カメラ効果を作る */
  transform:
    rotateX(90deg)
    rotateZ(calc(var(--player-angle) * -1deg))
    translate3d(
      calc(var(--player-x) * -1px),
      calc(var(--player-y) * -1px),
      calc(var(--player-z) * -1px)
    );
}
```

**`@property` によるライティングアニメーション**

CSS カスタムプロパティは通常アニメーション不可だが、`@property` で型定義することで補間アニメーションが可能になる。セクター（部屋）単位でライトレベルを継承させ、ちらつき光源を実現：

```css
@property --light {
  syntax: "<number>";
  inherits: true;
  initial-value: 1;
}

/* ちらつくライトのアニメーション */
@keyframes flicker {
  0%   { --light: 1.0; }
  25%  { --light: 0.6; }
  50%  { --light: 1.0; }
  75%  { --light: 0.4; }
  100% { --light: 1.0; }
}

.sector.flickering {
  animation: flicker 0.3s infinite;
}

/* 子要素はすべて --light を継承し、輝度に反映 */
.wall, .floor, .ceiling {
  filter: brightness(var(--light));
}
```

**`clip-path` による非矩形ジオメトリ**

非矩形セクターの壁は `polygon()` で正確な形状にクリッピング：

```css
.non-rectangular-wall {
  clip-path: polygon(
    var(--x1) var(--y1),
    var(--x2) var(--y2),
    var(--x3) var(--y3),
    var(--x4) var(--y4)
  );
}
```

**SVG フィルターによるスペクターの透明効果**

Spectre（半透明の敵）の見えないエフェクトは CSS 経由の SVG フィルターで実装：

```css
.spectre {
  filter: url(#spectre-effect);
}
```

```svg
<filter id="spectre-effect">
  <!-- 黒シルエットを生成 -->
  <feColorMatrix type="saturate" values="0"/>
  <!-- 手続き的ノイズを生成 -->
  <feTurbulence type="fractalNoise" baseFrequency="0.05" numOctaves="2" result="noise"/>
  <!-- ノイズでピクセルを歪ませる -->
  <feDisplacementMap in="SourceGraphic" in2="noise" scale="20" xChannelSelector="R" yChannelSelector="G"/>
</filter>
```

**アンカーポジショニングによる武器スプライト**

武器スプライトはステータスバーの上端に CSS アンカーポジショニングで固定し、ステータスバーの高さに関わらず正しい位置に表示：

```css
#status-bar {
  anchor-name: --status-bar;
}

#weapon {
  position: absolute;
  bottom: anchor(--status-bar top);
}
```

**使用した CSS 機能一覧**

| 機能 | 用途 |
|------|------|
| `transform-style: preserve-3d` | 3D 空間の共有 |
| `perspective` | 遠近法 |
| `translate3d()` / `rotateY()` | 壁・床・天井の配置 |
| `hypot()` | 壁の幅（ピタゴラスの定理） |
| `atan2()` | 壁の回転角 |
| `sin()` / `cos()` | カメラ移動計算 |
| `@property` | カスタムプロパティのアニメーション化 |
| `clip-path: polygon()` | 非矩形壁のクリッピング |
| CSS アンカーポジショニング | 武器スプライトの固定 |
| SVG フィルター（CSS 経由） | Spectre の透明エフェクト |

### ③ なぜそれが効果的か

**「CSS でここまでできる」という証明**

現代の CSS は単なるスタイリング言語を超え、三角関数（`sin`, `cos`, `atan2`, `hypot`）や型付きカスタムプロパティ（`@property`）を含む**実用的な計算エンジン**として機能する。

ポイントは **JavaScript ↔ CSS の責務分離**の明快さ：
- JavaScript はゲームロジックと最小限の座標変数のみ管理
- CSS はそれ以降の全描画計算を担当
- これにより CSS が「表示ロジック」の真の担当者となる

DOOM のようなコリドーベースの空間は凸空間の連結で構成されるため、背面から前面への描画順序が比較的簡単に管理でき、CSS の z-index ソートで扱える。また DOOM の壁は必ず鉛直（垂直）のため、`rotateX()` が不要で CSS 3D transforms の限界に当たりにくい。

**DOM ベースレンダリングの学術的価値**

Canvas/WebGL が適切な本番用途でも、CSS 3D のアイデア（DOM として残る、イベントが使える、アクセシブル）を小規模 UI に応用できる。たとえばインゲーム UI、3D 製品ビューアー、インタラクティブなカード等のユースケースでは CSS 3D が実用的選択肢となる。

## 関連情報: HTML-in-Canvas API（Google I/O 2026）

**リンク**: https://developer.chrome.com/blog/html-in-canvas-origin-trial

（Issue 742「Google I/O and the 'era of the agentic web'」で取り上げられた注目機能）

### 概要

Chrome 148〜150 のオリジントライアルで利用可能な新 API。DOM 要素を **2D Canvas または WebGL/WebGPU テクスチャに直接描画**できる。アクセシビリティ、find-in-page、翻訳、ダークモード、オートフィル、ブラウザ拡張機能、DevTools 検査がすべて維持される。

### これが解決する 20 年来の問題

```
従来の選択肢:
  DOM  → アクセシブル・インタラクティブ、しかし 3D 不可
  Canvas/WebGL → 高速 3D 可能、しかしアクセシビリティ消失

HTML-in-Canvas:
  DOM 要素を WebGL テクスチャとして使用 → 両立
```

### 主な API メソッド

```javascript
// 2D Canvas への描画
const source = document.getElementById("my-dom-element");
ctx.drawElementImage(source, 0, 0);

// WebGL テクスチャへのバインド
gl.texElementImage2D(gl.TEXTURE_2D, 0, gl.RGBA, gl.RGBA, gl.UNSIGNED_BYTE, source);

// 要素のトランスフォーム取得
const transform = ctx.getElementTransform(source);
```
