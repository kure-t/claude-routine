## 1. Meta が Astryx — AI エージェント対応の React デザインシステムをオープンソース化

**リンク**: https://github.com/facebook/astryx / https://astryx.atmeta.com/

### ① 目的・問題意識

Meta が社内で 8 年かけて構築し、Facebook・Instagram・Threads を含む 13,000 以上のアプリを支えてきた React デザインシステムを MIT ライセンスで公開した。従来のデザインシステムは「人間が読む」前提で設計されていたが、Astryx は **AI コーディングエージェントが読み書きできる**設計を中核に置いている。MCP サーバーと CLI を通じて、Cursor・Claude Code・GitHub Copilot などのエージェントが Astryx を直接クエリできる。

### ② 具体的な技術詳細

**インストール**

```bash
npm install @astryxdesign/core @astryxdesign/theme-neutral
npm install -D @astryxdesign/cli
```

**基本セットアップ (Next.js)**

```tsx
// app/layout.tsx
import '@astryxdesign/theme-neutral/index.css';
import { ThemeProvider } from '@astryxdesign/core';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        <ThemeProvider theme="neutral">
          {children}
        </ThemeProvider>
      </body>
    </html>
  );
}
```

**コンポーネント利用例**

```tsx
import { Button, Dialog, Selector } from '@astryxdesign/core';

function App() {
  return (
    <Button variant="primary" size="medium">
      Send
    </Button>
  );
}
```

**パッケージ構成**

| パッケージ | 役割 |
|---|---|
| `@astryxdesign/core` | コンポーネント・テーマシステム・ユーティリティ |
| `@astryxdesign/cli` | コンポーネントドキュメント・テンプレート・スキャフォールド |
| `@astryxdesign/build` | StyleX ビルドプラグイン |
| `@astryxdesign/theme-*` | 7 つのカスタマイズ可能なテーマ (neutral, butter, chocolate, matcha, stone, gothic, y2k) |

**CLI コマンド例**

```bash
# コンポーネントの詳細ドキュメントを表示
npx astryx component Button

# ダッシュボードのページテンプレートを出力
npx astryx template dashboard

# AI が使う機械可読の JSON マニフェストを取得
npx astryx manifest --json

# AI エージェント向けのコンテキスト一式を初期化
npx astryx init --features agents
```

**MCP サーバー設定 (Claude Desktop)**

```json
{
  "mcpServers": {
    "xds": {
      "type": "url",
      "url": "https://astryx.atmeta.com/mcp"
    }
  }
}
```

**Cursor 向け設定**

```bash
mkdir -p ~/.cursor/rules
npx astryx agent-docs --agent-docs-path ~/.cursor/rules/xds.mdc
```

`package.json` スクリプトへの登録:

```json
{
  "scripts": {
    "astryx": "node node_modules/@astryxdesign/cli/bin/astryx.mjs"
  }
}
```

### ③ なぜ効果的か

- **150 以上の型付き React コンポーネント**が JSDoc アノテーション付きで提供されており、AI がコンポーネントを正確に呼び出せる
- **StyleX** (Meta のコンパイル時 CSS エンジン) によりアトミックな静的 CSS をビルド時に生成。ランタイムでのスタイル注入がなく、エンタープライズ規模での予測可能性とパフォーマンスに優れる
- MCP サーバーにより AI エージェントが `search(query)` / `get(name)` を通じてコンポーネントのドキュメント・プロップス・コード例をオンデマンドで取得できる
- テーマは CSS カスタムプロパティのカスケードで実現しており、コンポーネントラッパー不要でテーマ変更が可能

## 2. shadcn/ui がチャット UI 向けコンポーネントを追加

**リンク**: https://ui.shadcn.com/docs/changelog/2026-06-chat-components

### ① 目的・問題意識

AI チャットインターフェースを構築する際、スクロール制御・ストリーミング対応・メッセージバブル・添付ファイル表示といった共通 UI を毎回ゼロから実装する手間を解消する。shadcn/ui に会話 UI の基盤コンポーネントレイヤーを追加した。

### ② 具体的な技術詳細

**新規コンポーネント一覧**

| コンポーネント | 役割 |
|---|---|
| `MessageScroller` | 会話スクロールコンテナ。自動スクロール・ターンアンカー・履歴プリペンド対応 |
| `Message` | アバター・整列・ヘッダー・フッターを含む会話行レイアウト |
| `Bubble` | メッセージサーフェス。バリアント・リアクション・リンク・折り畳みコンテンツ対応 |
| `Attachment` | ファイル・画像の表示。アップロード状態・アクションボタン付き |
| `Marker` | タイムスタンプ・日付区切りなどのインジケーター |

**MessageScroller の基本実装**

```tsx
import { Message } from "@/components/ui/message"
import {
  MessageScroller,
  MessageScrollerButton,
  MessageScrollerContent,
  MessageScrollerItem,
  MessageScrollerProvider,
  MessageScrollerViewport,
} from "@/components/ui/message-scroller"

function Chat({ messages }: { messages: Message[] }) {
  return (
    <div className="flex flex-col h-screen">
      <MessageScrollerProvider autoScroll scrollPreviousItemPeek="64px">
        <MessageScroller>
          <MessageScrollerViewport>
            <MessageScrollerContent>
              {messages.map((message) => (
                <MessageScrollerItem
                  key={message.id}
                  messageId={message.id}
                  scrollAnchor={message.role === "user"}
                >
                  <Message />
                </MessageScrollerItem>
              ))}
            </MessageScrollerContent>
          </MessageScrollerViewport>
          <MessageScrollerButton />
        </MessageScroller>
      </MessageScrollerProvider>
    </div>
  )
}
```

**useMessageScroller フック**

```tsx
import { useMessageScroller } from "@/components/ui/message-scroller"

function ChatControls() {
  const { scrollToMessage, scrollToEnd, scrollToStart } = useMessageScroller()

  return (
    <button onClick={() => scrollToEnd()}>最新へ</button>
  )
}
```

**useMessageScrollerVisibility フック**

```tsx
const { currentAnchorId, visibleMessageIds } = useMessageScrollerVisibility()
// ナビゲーショントレイルやジャンプ機能に活用
```

**新 CSS ユーティリティ**

```css
/* scroll-fade: スクロールコンテナの端にフェードを追加 */
.my-list {
  @apply scroll-fade;
}

/* shimmer: ストリーミング中の"Thinking..."等に使用 */
.thinking-text {
  @apply shimmer;
}
```

**新パッケージ `@shadcn/react`**

```bash
npm install @shadcn/react
```

```tsx
// スタイルなしのヘッドレス MessageScroller
import { MessageScroller } from "@shadcn/react/message-scroller"
```

### ③ なぜ効果的か

- `autoScroll` は「ユーザーがすでに一番下にいる間だけ」自動スクロールし、上にスクロールして過去のメッセージを読んでいる間は追従を止める — UX として自然な挙動
- `MessageScrollerProvider` が全スクロール状態を所有するため、`useMessageScroller` フックで任意の子コンポーネントからスクロール制御が可能
- ヘッドレス版 `@shadcn/react` により、既存の AI Elements ライブラリとの並行利用や独自スタイリングが容易

## 3. React Router v8 リリース

**リンク**: https://remix.run/blog/react-router-v8

### ① 目的・問題意識

年次メジャーリリーススケジュールを採用し、破壊的変更を最小限かつ予測可能にする。Node 20 の EOL タイムラインに合わせて最小要件を更新し、ESM 専用パブリッシングへ移行することで現代的なツールチェーンとの整合を図る。

### ② 具体的な技術詳細

**最小要件 (v7 からの変更)**

| 依存関係 | v7 | v8 |
|---|---|---|
| Node.js | 18+ | **22.22.0+** |
| React | 18+ | **19.2.7+** |
| Vite | 5+ | **7+** |

**インポートパスの変更 (破壊的変更)**

```tsx
// v7 (旧)
import { Link } from "react-router-dom"

// v8 (新) — react-router-dom パッケージは廃止
import { Link } from "react-router"
import { Link } from "react-router/dom" // ブラウザ固有ユーティリティ
```

**meta 関数の変更**

```tsx
// v7 (deprecated, v8 では削除)
export function meta({ data }: { data: LoaderData }) { ... }

// v8 (正しい書き方)
export function meta({ loaderData }: { loaderData: LoaderData }) { ... }
```

**ミドルウェア (v8 でデフォルト有効)**

```tsx
// routes/dashboard.tsx
import { createContext } from "react-router"

const userContext = createContext<User>()

export async function middleware({ context, request, next }: MiddlewareArgs) {
  const user = await getUser(request)
  context.set(userContext, user) // 型安全
  return next()
}

export async function loader({ context }: LoaderArgs) {
  const user = context.get(userContext) // User 型として取得
  return { user }
}
```

**Split Route Modules (v8 でデフォルト有効)**

```tsx
// route.tsx — サーバー側コードのみ
export async function loader() { ... }
export async function action() { ... }

// route.client.tsx — クライアント側コードを別チャンクに分割
export async function clientLoader() { ... }
export function HydrateFallback() { ... }
```

**v7 からのアップグレード方法**

1. `future.v8_*` フラグをすべて有効化する (v7)
2. 最小要件を満たすよう依存関係を更新
3. `react-router-dom` インポートを `react-router` / `react-router/dom` に変更
4. `meta` 関数で `data` → `loaderData` に変更

### ③ なぜ効果的か

- **年次リリーススケジュール** により破壊的変更のタイミングが予測可能になり、プロダクションへの追従が容易
- **ESM 専用** + ES2022 ターゲットにより、バンドルサイズの削減と Tree Shaking の改善が期待できる
- **型安全なコンテキスト API** (`createContext` + `context.set/get`) によりミドルウェアからルートへのデータ受け渡しに型が付き、実行時エラーを防ぐ
- v7 の `future` フラグをすべてオンにした状態と v8 は機能的に等価であるため、段階的な移行が実質的に完了した状態からのアップグレードになる

## 4. mapcn — shadcn スタイルのコピー&ペースト型 React マップコンポーネント

**リンク**: https://github.com/AnmolSaini16/mapcn / https://www.mapcn.dev/docs

### ① 目的・問題意識

React でインタラクティブマップを実装する際、MapLibre GL の設定は煩雑でボイラープレートが多い。mapcn は shadcn/ui のアプローチ (コンポーネントをプロジェクトにコピーして所有する、ゼロ依存ロック) をマップコンポーネントに適用し、API キー不要・ゼロコンフィグで動作するマップ UI を実現する。

### ② 具体的な技術詳細

**インストール (shadcn/ui CLI 経由)**

```bash
npx shadcn@latest add https://mapcn.vercel.app/maps/map.json
```

これにより `maplibre-gl` が依存関係として追加され、マップコンポーネントが `components/ui/` ディレクトリにコピーされる。

**基本マップ**

```tsx
import { Map, MapControls } from "@/components/ui/map"
import { Card } from "@/components/ui/card"

export function BasicMap() {
  return (
    <Card className="h-[400px] p-0 overflow-hidden">
      <Map center={[-74.006, 40.7128]} zoom={12}>
        <MapControls />
      </Map>
    </Card>
  )
}
```

**マーカーとポップアップ**

```tsx
import { Map, MapMarker, MapPopup, MapControls } from "@/components/ui/map"

export function MapWithMarkers() {
  const [activeId, setActiveId] = useState<string | null>(null)

  return (
    <Map center={[-74.006, 40.7128]} zoom={12}>
      <MapMarker
        coordinates={[-74.006, 40.7128]}
        label="New York"
        onClick={() => setActiveId("nyc")}
      >
        {activeId === "nyc" && (
          <MapPopup onClose={() => setActiveId(null)}>
            <p>ニューヨーク市</p>
          </MapPopup>
        )}
      </MapMarker>
      <MapControls
        showZoom
        showCompass
        showLocate
        showFullscreen
        position="top-right"
      />
    </Map>
  )
}
```

**ルート描画**

```tsx
import { Map, MapRoute } from "@/components/ui/map"

export function MapWithRoute() {
  const routeCoordinates = [
    [-74.006, 40.7128],
    [-73.935242, 40.730610],
    [-73.985, 40.758],
  ]

  return (
    <Map center={[-74.006, 40.7128]} zoom={11}>
      <MapRoute
        coordinates={routeCoordinates}
        color="#3b82f6"
        width={4}
      />
    </Map>
  )
}
```

**コンポーネント一覧**

| コンポーネント | 役割 |
|---|---|
| `Map` | MapLibre GL コンテキストプロバイダー。テーマ・ライト/ダーク自動切換え |
| `MapMarker` | カスタムマーカー。ラベル・クリックイベント・ドラッグ対応 |
| `MapPopup` | マーカーに紐付くポップアップ |
| `MapRoute` | 座標列を結ぶルートパス描画 |
| `MapControls` | ズーム・コンパス・現在地・フルスクリーンコントロール |

**注意点**: デフォルトタイルは CARTO Basemaps (OpenStreetMap データ) を使用。商用利用には CARTO Enterprise ライセンスが必要。無料代替として OpenStreetMap タイルや MapTiler が利用可能。

### ③ なぜ効果的か

- **API キー不要** で即座に動作確認できる (CARTO の無料タイル使用)
- **ライト/ダークモード自動切換え** — `prefers-color-scheme` に従いマップスタイルが自動変更
- **shadcn/ui パターン準拠** — コンポーネントをプロジェクト内にコピーして所有するため、ロックインなし。Tailwind CSS でスタイルカスタマイズが可能
- **コンポーザブルアーキテクチャ** — `Map` コンテキスト内に `MapMarker` / `MapPopup` / `MapRoute` を自由に組み合わせ、複雑なインターフェースを宣言的に構築できる
- GitHub 10.8k スター (2026年7月時点) と活発なコミュニティ
